Этот файл фиксирует кодовые блоки и фактические локальные проверки. Он не является разрешением на сетевой импорт, OAuth-тест или анализ реальных партий.

## Блок 1 — база и библиотека (PR #9, ветка `codex/m3-db-library`)

- `games` сохранена; SQLite `user_version=1`, миграция добавляет поля источника, линии и ошибки импорта.
- Перед миграцией существующей БД создаётся непрезаписываемая копия через SQLite backup API.
- Добавлены ревизии линий, нормализованные SAN/UCI ходы и позиции, включая позицию `ply=0`, а также текстовые заметки.
- Ветка линии после takeback получает новую ревизию; старые ходы/позиции/заметки сохраняются.
- Библиотека поддерживает поиск, постраничную выборку, просмотр, экспорт PGN и заметку к начальной позиции.
- Проверки локально: `python -m pytest -o addopts= -q` — 114 passed; `python -m compileall -q src tests` — PASS; `git diff --check` — PASS.
- Это Python 3.11.5 в доступной Windows-среде. CI Python 3.12 для этого нового блока ещё не запускался.
- Не проверялись реальный архив Lichess, реальный Stockfish и ручной интерактивный просмотр окна.

## Блок 2 — архив Lichess (PR #10, ветка `codex/m3-archive-sync`)

- Схема поднята до `user_version=2`: checkpoint backfill/incremental хранится отдельно для аккаунта.
- Добавлен потоковый NDJSON export завершённых партий, импорт PGN одной записью за раз, привязка game ID к аккаунту, checksum/raw PGN и доступные accuracy/lastMoveAt.
- Первая полная синхронизация возобновляется по timestamp checkpoint; инкрементальная начинается с курсора с перекрытием 24 часа для поздних обновлений; все upsert идемпотентны.
- В Home добавлено явное действие с подтверждением, фоновым прогрессом и отменой. Автоматической загрузки архива при старте нет.
- Проверки локально: **116 passed**, включая fake NDJSON endpoint, импорт страниц backfill, checkpoint и повторный incremental без дублей; `compileall`/`diff --check` — следующий прогон перед публикацией PR.
- Реальный аккаунт/архив не использовались. Смена аккаунта и API 429 потокового endpoint в реальной сети не проверялись; 429 покрыт общим fake transport тестом P0.

## Блок 3 — анализ завершённых партий (PR #11, ветка `codex/m4-analysis`)

- Добавлена схема `analysis_runs`, `position_assessments`, `move_classifications`; оценки сохраняют единый POV белых, отдельно CP и mate, depth/nodes/PV.
- Lichess PGN annotations `[%eval ...]` импортируются как отдельный источник `lichess-pgn`; официальный accuracy сохраняется отдельно от собственной классификации.
- Локальный UCI engine запускается только по запросу при выборе локального исполняемого файла. Активные статусы игры и ID открытой партии с человеком блокируют запуск. Автоматического скачивания движка нет.
- Кэш привязан к game id, line revision/hash, источнику, engine version и параметрам. Takeback создаёт новую ревизию и не удаляет старые запуски.
- Добавлена версия эвристики классификации потери CP (50/100/200); mate не приводится к искусственному CP. Дополнительный follow-up в PR #13 сохраняет `division.middle/end` и использует границы, иначе фаза честно `unknown`.
- Follow-up в PR #13 добавляет график оценки по ply с POV белых и переход к выбранной позиции.
- Проверки локально: тесты используют fake UCI engine, включая cache hit/close, live game gate, PGN eval import. Полный итог отражён в PR #11.
- Реальный Stockfish и ручная Windows-проверка не выполнялись; график протестирован автоматически в Qt offscreen.

## Блок 4 — общая статистика (PR #12, ветка `codex/m4-statistics`)

- Добавлен read-only `StatisticsService` с фильтрами аккаунта, дат, соперника, часов, источника партии/анализа, цвета, rating band и ECO/названия дебюта.
- Считаются результаты партий, confirmed/evaluated move counts и coverage, собственные ошибки на 100 оценённых ходов, средняя CPL, скачки >=200 cp, разрез классификаций по сохранённой фазе и rating trend при наличии рейтинга.
- Официальный Lichess accuracy отображается отдельным средним и не объединяется с локальными показателями.
- Home показывает краткий отчёт без открытия живой игры и без запросов к сети.
- Проверка по контролируемой фикстуре вручную сверяет числители/знаменатели, частичное покрытие, ошибки и отдельный accuracy. Полный прогон перед публикацией отражён в PR #12.
- Home пока показывает базовый отчёт без интерактивной панели фильтров; данные отсутствующего рейтинга/ECO/phase divisions не додумываются.

## Блок 6 — исправления повторного ревью M3–M4 (draft PR #14 поверх #13)

- Архив игр запрашивается через официальный `until` в миллисекундах (`sort=dateDesc` для backfill, `since`/`dateAsc` для incremental); `before` не передаётся в games endpoint. Запрошены `division=true`, `finished=true`, `ongoing=false`, PGN clocks/evals/accuracy/opening.
- Backfill и incremental cursors раздельны. Записи одной миллисекунды дочитываются точным запросом `[since, until]`; повторы дедуплицируются по remote id, повтор страницы без прогресса и граница >10 000 записей завершаются ошибкой без `backfill_complete`. Backfill cancellation/429 сохраняют resume cursor.
- Standard game upsert, нормализованные revision/positions, оригинальный PGN, Lichess evaluations, account mapping и backfill cursor входят в один SQLite transaction в последовательной writer queue; вызывающий sync worker ждёт durable commit. Ошибка транзакции не продвигает checkpoint. Экспорт предпочитает сырой Lichess PGN, чтобы не терять `[%clk]`/`[%eval]` и комментарии.
- Не-standard variants (включая Chess960) сохраняются как metadata + original PGN и `analysis disabled`, без ложной стандартной линии. В `account_games` сохраняются color и рейтинги относительно каждой учётной записи; импорт другого аккаунта не меняет `games.color`.
- Puzzle incremental следует descending `/api/puzzle/activity`: читает страницы `before` назад до watermark с перекрытием, вычитывает одинаковую date-ms границу, сохраняет attempt + restart cursor до следующей страницы и поднимает high-watermark только по завершении. 2501 attempt test отменяется на странице 2 и возобновляется без потерь.
- P1: Stockfish блокируется, пока передан хотя бы один активный human game id, в том числе если анализируемая партия другая; старт новой human-партии отменяет дальнейший анализ позиций. Не покрывает партии, не видимые локальным сессиям Chess Coach.
- Статистика отделяет ничьи, явно подтверждённые PGN/result statuses, от unknown/aborted; использует account-specific color/rating и детерминированный `run_id` при равном `finished_at`. Одной известной границы фазы недостаточно для догадки о middlegame. Экран явно маркирует смешанный срез; интерактивные фильтры остаются backlog.
- Restore после 429 не удаляет OAuth credential. Connect остаётся выключенной на время `Retry-After`; по окончании появляется явная кнопка «Повторить подключение», которая делает один restore без дублирования event stream. Реальные сетевые запросы не запускались.
- SQLite schema: `user_version=5`, миграция добавляет owner-specific `account_games` color/rating и resumable puzzle-page fields; существующие игры и ревизии сохраняются.
- Локальная проверка на Windows / Python 3.11.5: `.venv\Scripts\python.exe -m pytest -o addopts= -q` — **138 passed**; `python -m compileall -q src tests` — PASS; `git diff --check` — PASS.
- Регрессия архивной пагинации обработала 2501 synthetic game в трёх страницах, а отдельный fake проверил 1005 записей на одинаковой миллисекунде. Асинхронная запись новой SQLite игры ожидалась до возврата; принудительная ошибка writer сохранила прежний cursor. Puzzle fake отдал 2501 попытку в реальном descending порядке, симулировал остановку на второй странице и resume до всех 2501 без пропусков. Это mock/локальная регрессия, не live API импорт.
- Windows CI Python 3.12 — ожидает запуска после публикации ветки. Реальные архив, Puzzle OAuth/activity, GUI владельца и Stockfish E2E — **НЕ ПРОВЕРЯЛИСЬ**.
