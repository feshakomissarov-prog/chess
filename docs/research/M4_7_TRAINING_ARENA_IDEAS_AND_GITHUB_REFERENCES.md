## 1. Цель и пожелания владельца

Сделать Chess Coach инструментом самостоятельного шахматного обучения, а не просто линией оценки. Игрок может разыграть дебют/позицию за обе стороны, передать ход учебному боту, выбрать его силу, нарисовать свою идею стрелками, проверить её с помощью Stockfish **по запросу**, сохранить исходную идею и движковое опровержение, после чего попробовать снова без подсказки.

**Первичные идеи владельца:**
1. Иногда видеть оценку Stockfish во время игры против компьютера, но **не показывать автоматически по умолчанию**, чтобы не ослаблять навыки расчёта.
2. На локальной доске разыграть несколько дебютных ходов и «передать управление боту», продолжая **с этой позиции** на заданном уровне.
3. В дебюте показывать возможные ходы и позже — короткие комментарии о структуре и планах, желательно ступенями.
4. Отмечать стрелками кандидатные ходы/планы, кнопкой проверять их; сохранять замысел, вариации и оценки как пометки для будущего разбора.
5. Поддержать развитие учебного режима без перегруженных глобальных настроек, связать его с будущим голосом и тренером.

**Принцип:** запись идеи до показа оценки важнее постоянного присутствия сильнейшего хода на экране. Разовый успех с открытой подсказкой не эквивалентен освоенному навыку.

## 2. Сначала безопасность: Lichess AI в официальном UI ≠ Lichess AI через наш Board API

[Официальные правила Fair Play Lichess](https://lichess.org/page/fair-play) разрешают внешнюю engine-помощь в игре против встроенного Lichess AI НА ОФИЦИАЛЬНОМ сайте/мобильном приложении. Но отдельно для **стороннего клиента, использующего Board API**, правила запрещают помощь движка во время real-time игры, даже casual/unrated. [Официальная документация Board API](https://lichess-org.github.io/api/) прямо говорит, что engine assistance запрещена. BOT-аккаунт на Lichess — не тождествен встроенному AI.

**Наш дизайн:** подсказки/оценка/проверка стрелок ВО ВРЕМЯ ПАРТИИ — только полностью локальный учебный режим с собственной локальной сессией и проверкой отсутствия живой human-партии в связанном приложении; не включать их в Board API даже против встроенного Lichess AI. Не делать «unrated = подсказки разрешены». При network 429, unknown safety, против человека — fail closed.

**Два независимых режима:** 
- **Lichess AI (онлайн)**: уровень 1–8, без движковых подсказок в нашем клиенте, аннотации вручную, глубокая проверка только ПОСЛЕ окончания. [POST /api/challenge/ai](https://lichess-org.github.io/api/) может принимать кастомную стартовую FEN, это также описано для [berserk create_ai(position)](https://lichess-org.github.io/berserk/api.html). При реализации отдельно проверить тип варианта, FEN, очередь хода и серверные ограничения. Подготовительная локальная линия НЕ является частью новой серверной истории автоматически.
- **Локальная тренировочная партия**: локальный Stockfish со сниженной силой играет за компьютер, можно показать оценку, исследовать ветки и подсказки, но только по выбранному режиму. Человекообразный Maia рассматривается позже.

Нельзя обходить запреты, просто открыв позицию live human game на «Локальной доске». Доступ к engine должен проверять session safety, origin и право на анализ, включая смену аккаунта/сети.

## 3. Учебные режимы и настройки — гипотезы для будущего обсуждения

| Режим | Когда подсказка? | Как сохраняется результат |
|---|---|---|
| **Самостоятельно** (DEFAULT) | Полоска оценки, лучшие ходы и варианты скрыты; игрок делает собственные ходы/стрелки | «самостоятельная попытка», разбор только по завершении |
| **Контрольные точки** | Оценка по отдельному запросу; по умолчанию без готового лучшего хода | отметить когда и что показали |
| **С подсказками** | По нажатию — от общих ориентиров/наводящих вопросов до фигуры, клетки и линии | учитывается степень помощи; не считать чистым успехом |
| **Свободное исследование** | Пользователь явно включает live eval / 1–3 PV, можно отменять и создавать ветки | сохранять дерево вариантов и авторство идей, без переписывания исходного PGN |

Мягкое ограничение подсказок (например, 3 за тренировку) — **предложение**, не обязательное правило. Не принуждать отключать помощь насовсем; важно стимулировать последующее решение без неё.

**Глобальные Settings → Обучение**: помощь по умолчанию = самостоятельно; постоянная оценка = OFF; проверка стрелки = по запросу; показ best move = по запросу; уровень локального бота = средний; сохранять планы/ветки/попытки = ON; предлагать разбор после игры = ON; дополнительные engine nodes/Hash/Threads — в Advanced. **Перед каждой партией** обязательно отображать выбранный учебный режим, силу бота, собственный цвет, позицию и часы. Не помещать все двадцать переключателей в обычные настройки.

## 4. Сценарий «Разыграл дебют → передал ход компьютеру»

Три источника:
1. Выбрать дебют/линию из CC0 базы ECO либо будущего своего репертуара.
2. Разыграть нужные ходы за обе стороны на свободной доске.
3. Открыть завершённый PGN на интересной позиции и выбрать «Продолжить отсюда».

Проверка корректной позиции/FEN: очередь хода, право рокировки, en passant, fullmove/halfmove, легальные ходы, ничья/мат/пат. Сильный аналитический Stockfish и ослабленный **бот-соперник** — разные профили: нельзя выдавать оценку слабого бота за объективный анализ. Стоковый Stockfish 19 предлагает Skill Level или UCI_LimitStrength/UCI_Elo, но «движковое Elo» не означает точный рейтинг человека/Lichess и отличается при разных контролях. Не обещать слабый уровень младше минимально достижимого самим движком; режим «Новичок» может потребовать другого оппонента.

Действия: «Начать с этой позиции», «Повторить с тем же соперником», «Попробовать другой ответ бота», «Вернуться в дебютное дерево», «Сохранить как тренировку». Желательно сохранить исходный вариант для сравнения после партии; при повторе не давать одному искусственно случайному ответу становиться доказательством знания дебюта.

**После M4.6:** маршрут Играть → Тренировочная партия, на доске инспектор «Ходы», «Мой план», «Оценка», «Дебют», в M5+ — «Мои мысли», позже «Тренер». Доска и тема наследуются из M4.6, новый отдельный GUI-shell не создавать.

## 5. «Мой план»: стрелки ≠ шахматные ходы ≠ дерево вариантов

Разделить три сущности:
- **Ручная аннотация**: стрелка/круг/выделение (может указывать план, а не легальный ход).
- **Кандидатный ход**: пользователь выбирает конкретное начало/конец, программа проверяет легальность; сохраняет, что пользователь придумал его ДО раскрытия engine.
- **Линия/вариант**: последовательность легальных ходов обеих сторон, каждая со своей board state; несколько альтернативных веток не смешивать в одну «линию».

**Оценить идею**: после явного согласия проверить конкретный ход, оценить позицию после него с лучшей защитой соперника и сравнить с исходной позиционной оценкой, отдельно хранить CP/mate white POV, PV, движок, nodes/depth, score provenance. Нельзя делать вывод «ошибочная стратегия» из одной CP-разницы. **Проверить линию**: несколько ходов последовательно, без выдуманных SAN/неправильной стороны. **Сохранить план**: исходная ручная заметка + версия после engine + комментарии + ссылка на позицию. **Попробовать ещё раз**: вернуть позицию, скрыть ответ и проверить самостоятельное усвоение, не стирать старую попытку.

Будущая модель хранения (НЕ миграция сейчас): training_session, attempt, position_plan, branch; ссылки game_id/line_revision/ply/position_uid, engine version/budget, assistance/reveal status, created_at. Аннотации и варианты не должны перезаписывать импортированный PGN; экспорт PGN — отдельная задача. Рассмотреть SQLite additive schema только на стадии утверждённого ТЗ. Эта модель должна принимать позже записи голоса/объяснений из M5.

## 6. Как оценивать обучение, а не только удовольствие от Stockfish

Отдельно учитывать: решения самостоятельно / после подсказки и её уровня; исходную идею vs выбранный ход; ошибки на сопоставимых собственных ходах; повторную попытку после скрытия решения; результат на **новой похожей позиции** (проверка переноса); интервальные повторения спустя дни/недели; успех с разными оппонентами и дебютными ветками. Не выдавать победы над слабым ботом за реальный Elo, «off-book» не равно плохой ход. Не использовать official Lichess accuracy для локальной тренировки — нужна отдельно проверенная formula.

**ТОП-3 идеи для нашего проекта:**
1. **Дебютный sparring из выбранной позиции** (Opening Trainer): ближайший реальный use case.
2. **Сохранение мыслей ДО проверки движком + повтор без ответа** (синтез CARA/Blitzr/Mainline): наш главный образовательный контур.
3. **Помощь ступенями и отдельные режимы изучения** (Blitzr/Tabia/qam4): от вопроса/цели до фигуры/поля/конкретного хода.

Дополнительно в сохранённом каталоге: Chess Mistake Coach, Praxis Chess, chessrepeat, PrestonYadegar/chess-coach и др. — здесь построчно не перепроверены; если понадобятся, изучать для конкретной учебной задачи.
