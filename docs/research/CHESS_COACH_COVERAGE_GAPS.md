## I. Как правильно измерять покрытие

Нужны **четыре разных уровня покрытия**, которые не следует путать:

- **D0 — материал/данные:** позиция, PGN, двигатель, справочник, учебный пример доступны.
- **D1 — обнаружение:** программа может корректно определить характерную тему/ошибку и её доказательство.
- **D2 — объяснение:** умеет ответить на **почему**, показать альтернативы/контрпримеры, признать неуверенность.
- **D3 — обучение:** проверяет самостоятельный ответ, перенос навыка и закрепление в будущем.

Наличие базы партий или Stockfish почти всегда даёт **D0**, иногда часть D1, **но не гарантирует D2 или D3**.

**Кодовые статусы:**
- **MAIN** — уже слито в `main` (M0–M2), но не гарантирует совершенство;
- **DRAFT** — реализовано в stacked draft PR #8–#24 на SHA `e57926b9`, в `main` **нет**, CI 184 PASS; **не тестировалось на личном архиве/настоящем Stockfish**;
- **PLAN** — явно заявлено в M5/M6/документах, кода не проверяли;
- **GAP** — нет выделенного полного образовательного модуля; может существовать вспомогательный экран/идея.

## III. Чего особенно не хватает: карта в терминах работы тренера

| Задача живого тренера | Текущая реализация | Будущая обязанность Chess Coach |
|---|---|---|
| Спросить «что именно непонятно» | Нет адаптивного интервью | Контекстный вопрос и уточнение в одной позиции, без огромных форм |
| Проверить ответ до подсказки | Часть задумки в PRODUCT_VISION; UI самостоятельного ответа не реализован | `SelfReview` + `DiagnosticAttempt` |
| Различить знание темы и качество расчёта | Не реализовано | Диагноз по K × S; несколько гипотез, а не один ярлык «blunder» |
| Объяснить тему на подходящем уровне | M6 планируемый | Библиотека понятий/доказательств, объяснения на русском |
| Дать контрпример | Нет | «Когда этот принцип не работает», неверные планы с аргументами |
| Проверить перенос | Нет | Другая позиция/цвет/дебют/вариант с самостоятельным решением |
| Назначить упражнения из своего архива | DRAFT данные есть; учебный контент не создаётся | `training_items` и `training_attempts`, проверка разных верных ходов |
| Спланировать неделю обучения | Нет | Малые цели, задачи 5/10/20 минут, приоритет по личным пробелам |
| Проверить через месяц | Нет | Отложенные тесты/FSRS и честная неопределённость |
| Рассказать, насколько объяснение надёжно | Нет | Sources/Evidence, версия проверяющих правил, отказ при недостатке фактов |

## VI. Что НЕ делать сейчас

1. **Не давать Codex новый огромный учебный пакет**, пока он исправляет M3/M4 и не проведена безопасная приемка PR #8–#24 и новых fix PR.
2. Не сливать draft PR и не запускать реальные OAuth/Stockfish/массовый импорт без владельца.
3. Не объявлять «шахматная стратегия реализована», если программа только показала Stockfish `+0.8`.
4. Не переносить целиком чужой комплексный веб-проект в Python/PySide6 без оценки лицензии/архитектуры.
5. Не копировать материалы учебников и коммерческих уроков только потому, что их темы публично перечислены.
6. Не добавлять всем этим будущим модулям таблицы SQLite, пока нет отдельного ТЗ по одному тестируемому инкременту.
7. **Сохранять прежнюю лестницу:** M3/M4 довести и принять; M5 голос/мышление; M6 проверяемый диалог; дополнительные EDU-модули внедрять постепенно в согласованном порядке — без новой «бесконечной» параллельной ветки.

## VII. Как принимать решение о следующем модуле

Каждому кандидату присвоить: `K` (тема), `S` (навык), `D0–D3` (уровень обучения), доказательность правил, шанс ошибок/обмана, стоимость CPU/данных, лицензия, UI/Windows нагрузка, тестируемость и ценность для **реального выявленного пробела ученика**. Требовать **конкретный пример незнания → обучение → новая контрольная задача**, а не просто число новых кнопок.

**Дальше:** выбор 1–2 модулей после реального пилота и отдельного решения владельца. Первая возможная цель — EDU-03 (саморазбор) плюс EDU-02 (проверяемые мотивы), но **это не утверждённый новый приоритет**.
