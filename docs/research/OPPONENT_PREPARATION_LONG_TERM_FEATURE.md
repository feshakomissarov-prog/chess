# FUTURE — подготовка к конкретному сопернику по публичным партиям Lichess

**Идея владельца:** 04.11.2026. **Статус: ДАЛЬНИЙ ROADMAP / исследовательская фича; не согласовано как ближайший этап, не реализовывать сейчас, без отдельного Codex задания.** Архитектурный PR #44 и UX PR #45 не должны включать реализацию.

## 1. Пользовательская задача

Перед новой партией пользователь выбирает Lichess nickname соперника и получает краткое **доказательное** досье по его *завершённым публично доступным* партиям: какие дебюты и варианты он чаще выбирает белыми/чёрными, где результаты хуже/лучше, какими продолжениями можно подготовиться. Далее — дерево вариантов с частотами и, при обоснованной достаточности данных, конкретные типовые проблемные позиции/решения соперника; возможная тренировка этих вариантов в «Обучении → Мой репертуар».

**Пример гипотезы, не вывод:** «Соперник играет за чёрных Каро-Канн в 34/200 релевантных игр; в линии B10… у него 6 побед, 3 ничьи и 11 поражений». Из *малых* выборок **не говорить** «соперник плох в Каро-Канн», тем более без контроля за рейтингом/временем/цветом.

## 2. Источники и реалистичный MVP

- Официальный [Lichess API: Export games of a user](https://lichess.org/api#tag/Games/operation/apiGamesUser), `GET /api/games/user/{username}`, поддерживает ограничение `max`, finished, sort=dateDesc, выбор типа/цвета и opening/moves в ответе при доступности. Проверить контракт и лимиты на момент будущей реализации; **нельзя** предполагать, что каждый PGN содержит ECO/глубокий анализ.
- Первый кандидат **до 500 последних доступных завершённых партий** (настройка: последние 100/500/1000 или временное окно), **строго с учётом квот Lichess**, cache/asynchronous pagination/cancel, 429 Retry-After, cooldown, HTTP auth and public visibility. Если меньше — показывать реальное N; если обрыв/часть приватна — **не считать покрытие 100%**. Дополнительные партии загружаются только после явного пользовательского решения или согласованного background quota.
- Для дешёвого **дебютного** анализа может быть перспективен **Lichess Opening Explorer player**: `https://explorer.lichess.ovh/player` (отдельный домен/условия/rate limits, поддержка и доступность API проверить перед проектированием). Он не заменяет гарантированно полноценный список реальных партий и может иметь отдельные ограничения. Не предполагать, что у нас право получать любые скрытые данные.
- Собирать **победы/ничьи/поражения с точки зрения соперника**, цвет соперника и его дебютный repertoire. Важна ориентация: пользователь спрашивает **«что мне подготовить за белых против его чёрных»** и **«что мне подготовить за чёрных против его белых»**. Долю побед в каком-либо дебюте соперника отдельно от доли результата нашего будущего игрока; гипотеза рекомендаций — не доказанная вероятность.
- PGN opening labels/ECO — исходный источник и русская локализация по проверенному словарю, плюс конкретная **последовательность ходов**, с учётом транспозиций: название дебюта само по себе не гарантирует одинаковую позицию/вариант.
- Источники: `opponent_username` (public), `retrieved_at`, subset size / actual total known/unknown, time range, perf type, opponent color, official game status, rating bands, opening label/ECO, moves/position hash when available. Не строить выводы по live games.

## 3. Метрики и что значит «слабая линия»

**Иерархия:** (1) частоты выбора дебютов и первых N полуходов; (2) W/D/L и score rate по цвету/контролю; (3) при достаточном количестве партий — вариативность популярных линий; (4) только после дополнительной статистической проверки — слабые точки, (5) при доступных уже рассчитанных оценках — ошибки/потери по конкретным позициям. Запуск локального Stockfish для сотен партий **не входит в быстрый MVP**.

Обязательные элементы:
- `opponent_wins`, `draws`, `losses`, `n` и выбранная формула `score% = (W + D/2)/N` отдельно от `win% = W/N`. Не путать эти величины, не выдавать маленькие `n` как достоверную закономерность.
- Показатель распространённости конкретного дебюта `games_in_opening / total_games_as_this_color` и показатель результативности `W/D/L среди игр в этой линии`. В нужном месте показывать обе доли, иначе `20%` двусмыслен.
- Периоды и контроли **не перемешивать молча**: rapid ≠ blitz/bullet, меняется репертуар соперника со временем. Отдельно учитывать соперников по рейтингам. Наличие `n=3` → «данных недостаточно».
- Выбор позиции/варианта по последовательности FEN (transpositions) и UCI/SAN, не лишь по ECO-тегу. Противник мог сыграть линию белыми или чёрными; рекомендации должны соответствовать **стороне игрока**.
- Для каждой рекомендации объяснять доказательства: «за последние 500 завершённых игр: N за чёрных; из них M в Каро-Канне; в выбранной ветке K; проигрыши P; нет анализа X». Лучше `у него такие результаты` чем `он слаб в такой позиции`.
- **Не считать статистическое неудобство противника доказательством объективно плохого хода**. Если нужно, позже оценить линию Stockfish на разрешённых завершённых играх вне активных human sessions; контекст рейтинга и цвет.
- Применять сглаживание/доверительные интервалы или минимальное количество партий как gate на вывод «уязвимость»; пороги и корректную интерпретацию утвердить отдельным аналитическим ТЗ. Не создавать из 500 партий ложный Elo конкретного дебюта.

## 4. Где расположить в будущем UX

Предпочтительный путь **«Анализ → Исследование дебютов → Подготовка к сопернику»**, позднее возможно shortcut «Мои партии → карточка соперника» или «Играть → Подготовиться», но **не показывать советы во время активной человеческой онлайн-партии**.

```text
┌──────────────────── ПОДГОТОВКА К СОПЕРНИКУ ──────────────────────────────┐
│ Ник Lichess [ Player42                 ] [Изучить профиль]              │
│ Объём [последние 500 ▼] Контроль [Blitz ▼] Период [Все доступные ▼]     │
│ Проверено: 347/500 завершённых публичных партий · Источник: Lichess    │
│                                                                        │
│ [Против его белых]           [Против его чёрных]                       │
│                                                                        │
│ ТОП ДЕБЮТОВ         N партий · W/D/L · Частота · Score%                 │
│ Каро-Канн (чёрными) 34 · 12/8/14 · 18%* · 47%                 [Детали]  │
│ ...                                                                    │
│                                                                        │
│ ДЕРЕВО ВАРИАНТОВ / КОНКРЕТНЫЕ ПОЗИЦИИ                                  │
│ [Доска] [Варианты ходов] [Данные N] [Объективная оценка при разрешении]│
│                                                                        │
│ [Сохранить в репертуар] [Тренировать линию] [Вернуться в Анализ]      │
└────────────────────────────────────────────────────────────────────────┘
Все данные УСЛОВНЫЕ. Знаменатель 18% — игры соперника чёрными, не все игры.
```

**Нет** интеграции этого досье в правую панель *активной* игры, live score advice, PV или обновления рекомендаций во время human live match. Предматчевая подготовка — предмет отдельной оценки правил Fair Play; при любой неопределённости не показывать позиционно-специфичные советы.

## 5. Нефункциональные и юридические границы

- Только документированные публично разрешённые данные, уважать пользовательские настройки приватности, отсутствие скрытых токенов/профилей; не добывать личные данные и не делать automated requests на неофициальные закрытые endpoints.
- По умолчанию анализ запускается **по явному поиску пользователя**; если фоновый кэш — ограниченный срок хранения, источник, дата, отзыв, clear-cache control. Никакого бесконечного сканирования чужих аккаунтов.
- Network lane с приоритетом живой игры и safety; архив соперника не держит global API lock, не запирает UI, не тратит Stockfish ресурсы в live human games. Кэш/PGN соперника **не добавлять автоматически** в личный архив пользователя и не загрязнять персональные метрики.
- Не раскрывать свои/чужие локальные приватные PGN из Chess Coach; логирование без username/PGN/tokens, кроме безопасно редактируемого user-visible названия выбранного аккаунта.
- Rate-limited/blocked/empty profile/short sample/private/variant non-standard/draw-heavy states. Перед новой фазой подтвердить Lichess API/terms, корректность дебютов/результатов, допустимость в рамках fair play и согласовать отдельный критерий качества.

## 6. Фазы далёкой реализации — НЕ ближайшее задание

1. **MVP**: до 500 завершённых публичных партий, W/D/L и дебюты отдельно по цветам и контролю, анализ только после завершения загрузки или на доступной части с явным n/N; offline cached.
2. **Openings explorer**: точная позиционная карта популярных линий и транспозиций, фильтры и сравнение периодов.
3. **Deep weakness evidence**: редкие позиции/варианты + valid evals с provenance, числа, сравнение с аналогичными игроками и ограничение статистических выводов.
4. **Training link**: выбор собственных линий и создание тренировок в «Обучении → Мой репертуар»; сохранять их как идеи, а не гарантированный способ победы.
5. **Опциональный соперник из карточки партии** с разрешённым профилем, без auto bulk fetch.

**Ключевой критерий:** помочь подготовиться к типичным вариантам соперника, не обещая объективно «эксплуатировать слабости» по малой статистической выборке. Приоритет реализации определить позже; сейчас сохраняем идею в ROADMAP как дальнюю возможность.
