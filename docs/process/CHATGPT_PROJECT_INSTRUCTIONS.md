# Однократная инструкция для ChatGPT Project «Шахматы»

Репозиторий содержит постоянный контракт для Codex, но **не может автоматически изменить персональные или проектные настройки ChatGPT**. Чтобы любой новый чат внутри проекта следовал одним и тем же правилам, владелец может добавить в инструкции проекта следующий текст (дословно или по смыслу):

> Для любого ТЗ или ревью Chess Coach сначала открой актуальные файлы GitHub-репозитория `feshakomissarov-prog/chess`: корневой `AGENTS.md` и `docs/process/VERIFICATION_PROTOCOL.md`. Применяй постоянный контракт `CC-VERIFY-01` независимо от истории чата: быстрый адресный L1 после маленьких правок, тематический L2 после блока изменений, полный exact-head Windows CI L3 только перед сдачей и после изменений, влияющих на поведение. В каждое создаваемое или обновляемое ТЗ обязательно включай маркер `<!-- verification-contract: docs/process/VERIFICATION_PROTOCOL.md -->`, конкретный раздел «План проверок и стоимость CI» (L1/L2/L3 с командами и триггерами) и «Критерии приёмки и доказательства». Используй `docs/specs/_TASK_TEMPLATE.md`. Не запускай большие CI на каждый косметический коммит, не выдавай synthetic проверки за владельческую приёмку, не мержи без разрешения. Передавай Codex прямые ссылки на документы в GitHub. Не дублируй ранее известные ошибки, обновляй единый реестр.

**Важно:** инструкция в настройках проекта — дополнительная страховка для GPT. Автоматическая проверка новых и обновляемых ТЗ в GitHub остаётся необходимой, поскольку контекст чата и память могут отсутствовать.

После включения регламента в `main` файлы нужно читать из `main`. До слияния PR политики читать из его ветки `policy/tiered-verification-contract-2026-11-14`. Не утверждать, что контракт уже действует для всех веток, пока туда не попали изменения.
