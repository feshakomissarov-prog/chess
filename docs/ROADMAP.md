# Chess Coach — дорожная карта

**Статус:** план на начало разработки; сроки не назначены.  
**Документы:** [PCD](PCD.md) · [PRD](PRD.md)

## Порядок работы

Не строить сразу всё приложение. Каждый инкремент должен запускаться, иметь проверяемые критерии готовности и не ломать предыдущие функции. Для крупных изменений Codex работает в отдельной ветке/PR, а не бесконтрольно переписывает main.

| Этап | Результат | Проверка |
| --- | --- | --- |
| **M0 — UI и локальная доска** | Рабочее окно PySide6, доска в выбранном стиле, легальные ходы, список ходов, ручные стрелки и подсветка | Пользователь запускает программу на Windows и проверяет поведение мышью; тесты шахматной логики |
| **M1 — проверка Lichess API** | OAuth и минимальный технический сценарий приглашения/присоединения; проверка игры без часов и со стандартными часами | Реальная тестовая партия с другом; записаны ограничения API |
| **M2 — игровой клиент онлайн** | Синхронизация ходов/результата, отправка ходов, часы, обработка потери связи, сохранение партии | Полная нерейтинговая партия внутри Chess Coach против участника в браузере |
| **M3 — запись размышлений** | Микрофон, фрагменты по изменениям позиции, локальные файлы/SQLite, фоновая расшифровка | Партия с комментариями, затем верные привязки к ходам; можно сразу играть снова |
| **M4 — библиотека и Stockfish** | История, PGN/Lichess импорт, поиск, статусы, движковая аналитика после игры | Импорт и разбор нескольких партий без дубликатов |
| **M5 — интерактивный разбор** | Точки интереса, самостоятельная оценка, варианты и объяснения; опциональный ИИ-тренер через API | Пользователь проходит полный разбор выбранной критической позиции |
| **Позднее** | Профиль повторяющихся ошибок, дебюты, задания на следующие партии, проверка прогресса | Отдельные требования и тесты каждой функции |

## Ближайшая задача для Codex — M0

Реализовать **только** описанный в [PRD §9](PRD.md#9-первый-инкремент-для-codex-m0--интерактивная-офлайн-доска) инкремент.

Ориентир: классические чёрно-белые фигуры, тёплая светло-бежевая/коричневая доска как на предоставленном автором изображении, спокойный интерфейс с доской слева и списком ходов справа. Фигуры и ресурсы брать из источников с проверенной лицензией; чужую картинку нельзя автоматически считать готовым набором ассетов.

**Ожидаемые артефакты:** работающий код, `requirements.txt` или `pyproject.toml`, инструкция запуска на Windows, базовые тесты, краткий список того, что пока не работает.

**Не делать в M0:** подключение Lichess, запись звука, Stockfish, GPT, запросы в сеть, упаковку в exe. Не надо писать фальшивые интеграции под видом работающих.

После демонстрации M0 пользователь даёт отзыв по размеру фигур, цветам, стрелкам и расположению панелей. Затем открывается M1.

## Технические правила на старте

- Отделять шахматные правила от отображения.
- Не хранить в git токены, пароли, персональные партии и базы данных.
- Не включать в онлайн-игре стороннюю шахматную помощь, включая численные оценки позиции.
- Сохранять простую возможность локального запуска и тестов.
- Правила для Codex в `AGENTS.md` подготовить на старте M0, адаптировав к фактическому стеку, а не копировать без проверки из чужого проекта.
