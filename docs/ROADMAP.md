## Архивный план завершённого блока M4.5 (решение от 2026-11-01)

**Единое подробное ТЗ v2.0 для десктопного Codex:** [M4_5_BATCH_ANALYSIS_PERSONAL_DIAGNOSTICS.md](specs/M4_5_BATCH_ANALYSIS_PERSONAL_DIAGNOSTICS.md). **Журнал прогресса и восстановление контекста:** [M4_5_EXECUTION_LOG.md](handoffs/M4_5_EXECUTION_LOG.md), **эпик [#28](https://github.com/feshakomissarov-prog/chess/issues/28)**. Codex получает только GitHub-ссылки и работает автономно по этапам 0–I в **одной feature-ветке и одном draft PR**, с коммитами и записью состояния после каждого этапа; сам не сливает в main. Не начинать с нуля: SQLite v9 и одиночный Stockfish уже есть.

1. **Паспорт и coverage:** current line, Lichess/Stockfish eval pairs, точность/ошибки, source/version/полнота, без повторных расчётов.
2. **Быстрое пополнение:** использовать готовые Lichess-оценки, дозагрузить появившиеся частичные, затем один локальный Stockfish с ограниченным бюджетом; новые партии выше старых.
3. **Многоуровневая классификация:** severity, missed opportunities, положительные события, проверяемые motif tags, без навязанной причины и без нового движкового расчёта по умолчанию.
4. **Дебюты/фазы:** CC0 lichess-org/chess-openings и Lichess division, выявление ранних собственных ошибок, по цвету/контролю/источнику.
5. **Сводная аналитика:** средняя **сравнимая** точность партий (n/N), ошибки на партию и на 100 оценённых собственных ходов, фазы, дебюты, последние 90 дней против полной исторической шкалы.
6. **Кодекс ночью:** этапы 0–I в одном PR, проверяемые коммиты, журнал handoff после каждого; SQLite v9 миграция минимальна, личные данные не трогать, real OAuth/Stockfish не активировать без разрешения.

**Почему M4.5, а не перенумерация:** ранее согласованные M5 (голос) и M6 (ИИ-тренер) сохраняются, но стартуют после завершения аналитической платформы. Старые документы M3/M4 остаются историей реализации; новые требования имеют приоритет только в части *следующего* блока.

**Ограничение Lichess:** документированный публичный API предоставляет экспорт игр с готовыми evaluations и кэш отдельных cloud-positions, но не гарантирует публичную возможность массово заказать серверный анализ. Поэтому основной гарантируемый механизм полного покрытия — **локальный Stockfish**. Соблюдать один сетевой запрос за раз, HTTP 429 и ограничения Lichess, не обходить лимиты. См. [официальные API](https://lichess-org.github.io/api/) и [API tips](https://lichess.org/page/api-tips).

**Технический долг:** [Issue #5](https://github.com/feshakomissarov-prog/chess/issues/5) содержит отложенные локальное обновление/QA новой UX-версии, реальный Stockfish E2E и резервную копию перед миграцией. Он не препятствует *проектированию* M4.5, но релизный запуск анализа на пользовательской SQLite должен проходить с защитой данных.
