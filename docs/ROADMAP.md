## Порядок работы

Не строить сразу всё приложение. Каждый инкремент должен запускаться, иметь проверяемые критерии готовности и не ломать предыдущие функции. Для крупных изменений Codex работает в отдельной ветке/PR, а не бесконтрольно переписывает main.

| Этап | Результат | Проверка |
| --- | --- | --- |
| **M0 — UI и локальная доска** | Интеграция `chess-widgets` в PySide6-окно, стиль по референсу, клик-клик и drag, тестируемый premove, ручные пометки, история и настройки | Пользователь запускает программу на Windows и проверяет поведение мышью; тесты шахматной логики |
| **M1 — проверка Lichess API** | OAuth и минимальный технический сценарий приглашения/присоединения; проверка игры без часов и со стандартными часами | Реальная тестовая партия с другом; записаны ограничения API |
| **M2 — игровой клиент онлайн** | Синхронизация ходов/результата, отправка ходов, часы, обработка потери связи, сохранение партии | Полная нерейтинговая партия внутри Chess Coach против участника в браузере |
| **M3 — база и архив** | Эволюция SQLite: партии, ходы, позиции, текстовые заметки; полная первоначальная выгрузка Lichess + инкрементальная синхронизация | Миграция старых партий без потерь, нормализованные ходы и позиции, нет дублей, нет повторного полного архива |
| **M4 — аналитика и личные задачи** | Оценки Lichess и локальный Stockfish, график/ошибки по фазам, общая статистика; отдельный импорт собственной истории задач Lichess (`puzzle:read`) | Статистика с корректным знаменателем и coverage, задачи импортируются без дублей, анализ только завершённых игр |
| **M5 — голос и визуальные планы** | Микрофон пользователя, сегменты по подтверждённым изменениям позиции (с первого хода белых), история стрелок/кругов, группы A/B, транскрипция, воспроизведение | Повторное открытие партии воспроизводит последовательность мыслей, рисунков и аудио, включая takeback |
| **M6 — интерактивный ИИ-тренер** | Версионированный пакет PGN + оценки + транскрипт + события рисунков; позже диалог и упражнения | Локальный экспорт без отправки в облако, будущий отдельный ИИ-модуль по согласию владельца |
| **Позднее** | Профиль повторяющихся ошибок, дебюты, задания на следующие партии, проверка прогресса | Отдельные требования и тесты каждой функции |

## Технические правила на старте

- Отделять шахматные правила от отображения.
- Не хранить в git токены, пароли, персональные партии и базы данных.
- Не включать в онлайн-игре стороннюю шахматную помощь, включая численные оценки позиции.
- Сохранять простую возможность локального запуска и тестов.
- Корневой `AGENTS.md` уже подготовлен по мотивам других репозиториев владельца; Codex обязан соблюдать его и не переписывать без отдельной задачи.
