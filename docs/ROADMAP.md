## Порядок работы

Не строить сразу всё приложение. Каждый инкремент должен запускаться, иметь проверяемые критерии готовности и не ломать предыдущие функции. Для крупных изменений Codex работает в отдельной ветке/PR, а не бесконтрольно переписывает main.

| Этап | Результат | Проверка |
| --- | --- | --- |
| **M0 — UI и локальная доска** | Интеграция `chess-widgets` в PySide6-окно, стиль по референсу, клик-клик и drag, тестируемый premove, ручные пометки, история и настройки | Пользователь запускает программу на Windows и проверяет поведение мышью; тесты шахматной логики |
| **M1 — проверка Lichess API** | OAuth и минимальный технический сценарий приглашения/присоединения; проверка игры без часов и со стандартными часами | Реальная тестовая партия с другом; записаны ограничения API |
| **M2 — игровой клиент онлайн** | Синхронизация ходов/результата, отправка ходов, часы, обработка потери связи, сохранение партии | Полная нерейтинговая партия внутри Chess Coach против участника в браузере |
| **M3 — запись размышлений** | Микрофон, фрагменты по изменениям позиции, локальные файлы/SQLite, фоновая расшифровка | Партия с комментариями, затем верные привязки к ходам; можно сразу играть снова |
| **M4 — библиотека и Stockfish** | История, PGN/Lichess импорт, поиск, статусы, движковая аналитика после игры | Импорт и разбор нескольких партий без дубликатов |
| **M5 — интерактивный разбор** | Точки интереса, самостоятельная оценка, варианты и объяснения; опциональный ИИ-тренер через API | Пользователь проходит полный разбор выбранной критической позиции |
| **Позднее** | Профиль повторяющихся ошибок, дебюты, задания на следующие партии, проверка прогресса | Отдельные требования и тесты каждой функции |

## Текущая задача — стабилизация PR #3 и подготовка запуска с рабочего стола

- **[PR #2 — доска и M0](https://github.com/feshakomissarov-prog/chess/pull/2)** — draft, база для [PR #3 — Lichess](https://github.com/feshakomissarov-prog/chess/pull/3), тоже draft. Код не слит в main.
- Владелец уже **играл** из Chess Coach с Lichess AI и другом. Отдельные крайние случаи не приняты, авторизация и игровой клиент существуют, их не нужно переписывать с нуля.
- Новый этап: **[ТЗ — возврат хода с AI, отзывчивость доски, headless Qt-тесты, ярлык Windows](specs/PR3_TAKEBACK_INPUT_PERFORMANCE_DESKTOP.md)**. Приоритет — доступный takeback через сервер, отсутствие всплывающих тестовых окон, отзывчивость управления мышью и простой запуск двойным щелчком.
- Должны сохраниться OAuth, ручные стрелки правой кнопкой мыши, premove, игра с человеком/AI, восстановление после обрыва, PGN/SQLite и результат партии. Не смешивать отмену непосланного предхода с откатом уже выполненного серверного хода.
- После исправления — приёмка владельцем и отдельное согласие на merge: PR #2 → main, затем PR #3 → main. Возможные конфликты с новой документацией main разрешать аккуратно.
- **Следом:** отдельное проектирование окончательного UI/UX, затем M3 — запись голоса на каждой смене позиции (с первого хода белых), M4 — postgame Stockfish и библиотека, M5 — ИИ-тренер. Голос и движок сейчас не добавлять.

## Технические правила на старте

- Отделять шахматные правила от отображения.
- Не хранить в git токены, пароли, персональные партии и базы данных.
- Не включать в онлайн-игре стороннюю шахматную помощь, включая численные оценки позиции.
- Сохранять простую возможность локального запуска и тестов.
- Корневой `AGENTS.md` уже подготовлен по мотивам других репозиториев владельца; Codex обязан соблюдать его и не переписывать без отдельной задачи.
