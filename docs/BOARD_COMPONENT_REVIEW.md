**Дата изучения:** 2026-10-31  
**Статус:** исследование + решение владельца: `chess-widgets` выбрана как основа M0. Код пока не интегрирован.  
**Контекст:** [PCD](PCD.md) · [PRD](PRD.md) · [ТЗ M0](specs/M0_BOARD_UI.md)

## Критерии выбора

Цель — удобная Windows-доска в стиле присланного владельцем примера, при сохранении Python/PySide6 и возможности в будущем принимать подтверждённые события Lichess. Нужны: клик-клик, drag-and-drop, ручные стрелки/кружки, **предходы**, превращение пешки, переворот, история и режим просмотра. Критично иметь **одного владельца состояния партии**, а не два синхронизируемых источника истины.

## Важная проверка исходников chess-widgets

- [README](https://github.com/leszekhanusz/chess-widgets/blob/main/README.md) прямо заявляет поддерживаемые click-to-move, drag-and-drop, highlighting, flipping.
- [Код виджета](https://github.com/leszekhanusz/chess-widgets/blob/main/src/chess_widgets/board.py) был выборочно прочитан: виджет хранит `_board` и применяет собственный `push()` в `play_move()`; в `_find_move()` выбор promotion не реализован как полноценный диалог. Это **не запрещает** повторное использование, но не позволяет без проверки считать виджет полноценным контроллером сетевой партии.
- [generate_assets.py](https://github.com/leszekhanusz/chess-widgets/blob/main/generate_assets.py) генерирует SVG вызовом `chess.svg.piece`.
- [LICENSE](https://github.com/leszekhanusz/chess-widgets/blob/main/LICENSE) — MIT, copyright © 2025 Leszek Hanusz.
- Заявления «MIT» для исходного Python-кода **не достаточно**, чтобы автоматически установить статус производных SVG: оригинальные Cburnett-фигуры имеют несколько вариантов лицензирования ([python-chess SVG docs](https://python-chess.readthedocs.io/en/latest/svg.html)). Перед копированием в репозиторий/сборку выбрать совместимые условия и сохранить нужные notices/attribution.
- `python-chess` сам по себе GPL-3.0-or-later; **отдельная лицензия итогового приложения пока не выбрана**. Перед публичным распространением собранного ПО необходимо решить совместимость лицензий и обязанности распространения исходников.

## Принятое решение

**Интегрировать `leszekhanusz/chess-widgets` как базовый виджет M0, а не переписывать доску с нуля.** Но ставить чёткий технический порог:

1. Возможно ли внешнему контроллеру владеть единственным `chess.Board`, получая из UI только запрос `MoveIntent` без самовольного `push()`? Можно ли адаптировать это малым, понятным изменением или тонкой локальной обёрткой?
2. Реализуются ли manual arrows/circles и premove *без* ломания событий click/drag и отзывчивости?
3. Есть ли корректный диалог promotion для четырех вариантов?
4. Сохранится ли возможность заменить локальный драйвер позиции на Lichess без переписывания всей доски?
5. Проверена ли лицензия распространяемых SVG/включены notice?

Если ответы на 1–4 отрицательные и требуется масштабно переписать почти весь виджет, не продолжать «любой ценой»: либо предложить собственную доску на `QGraphicsView` при сохранении PySide6, либо отдельный согласуемый spike на `Chessground + QWebEngineView + QWebChannel`.

**Не изменять стек на React/Electron/Flutter без отдельного решения владельца.** При создании M0 Codex должен указать, что именно взято из стороннего проекта и по какой лицензии; форк/копирование — только если действительно необходимо, иначе использовать зависимость зафиксированной версии с атрибуцией.

## Решение для следующего этапа

Библиотека выбрана владельцем как основа. При технической невозможности выполнить критичные требования на ней Codex не меняет направление самостоятельно: документирует ограничение и возвращает решение владельцу. Детальный контракт — [M0_BOARD_UI.md](specs/M0_BOARD_UI.md), раздел 10.
