## R-V3-01 (P1): кнопки «Выбрать партию» и «Продолжить последний разбор» исчезают из основного блока главной

**Факты из кода:** `src/chess_coach/window.py:2775–2788` создаёт `self.home_review_button` и `self.resume_review_button`, помещает обе в `review_buttons`, находящийся в `play_layout`. Но в **том же** `_build_home_page()` на строках **2822–2827** *те же экземпляры QWidget* повторно добавляются в `more_layout`, затем `more_layout` переносится в `home_more_content`, который **скрыт по умолчанию** (строки 2830–2843). Qt не может показывать один QWidget одновременно в двух контейнерах: при добавлении в другую layout он переносится к её родительскому виджету. В результате задуманные основные действия «Выбрать партию» и «Продолжить последний разбор» **скрываются в «Другие разделы и синхронизация»**. Кнопка «Завершённые партии» в тех же дополнительных действиях дублирует основной маршрут.

**Как исправить:** определить единственного владельца для каждой кнопки. `home_review_button` и `resume_review_button` должны оставаться внутри `home_play_card`; убрать их из списка secondary controls. `home_games_button` может остаться вторичной точкой входа, но лучше устранить дубликат на основе уже принятых UX-решений. Не создавать новый Qt-псевдоклон с одинаковым state без необходимости. Проверить видимость `resume_review_button` при наличии сохранённого workspace и его правильный callback.

**Обязательный тест:** `window.show()` при закрытой `home_more`: `home_review_button.isVisible()==True`, `home_review_button.parentWidget()` принадлежит `home_play_card`, `resume_review_button` при включённом состоянии видим и находится **там же**, навигация открывает нужную карточку, не меняя game/session. Затем открыть/закрыть secondary controls и убедиться, что primary buttons не пропадают. Не ограничиваться `.text()` и `.parentWidget() is not None`: они проходили на сломанном коде. ## R-V3-02 (P1): основной график проводит ломаную сквозь шахматный мат как будто это численная оценка

**Факты из кода:** `src/chess_coach/ui/game_review.py:99–123` в `ReviewGraph._values()` устанавливает `score=0` для `mate_white != None`, помечая отдельно мат; `_nice_axis_limit` честно исключает такой score из масштаба, а paint рисует мат специальным маркером на краю. Но `_continuous_segments(values)` (примерно строки 151–154) требует только `second.ply == first.ply + 1` и **не исключает** `mate is not None`. В `paintEvent` основной линии для этих пар вызывается `painter.drawLine`, и маркер матовой оценки соединяется с обычной cp-точкой прямой, создавая ложную непрерывную численную кривую. Заявление в отчёте «матовые и отсутствующие оценки не соединяются как обычные» выполняется лишь для missing, не для mate. Это *не Fair Play*, но ошибка визуальной шахматной семантики.

**Минимальное воспроизведение:** `_continuous_segments([(0, 30, None), (1, 0, 3), (2, 20, None)])` сейчас возвращает **две** линии (0→мат, мат→2), тогда как граф cp должен иметь **ноль** cp-сегментов для этой тройки. При обычной паре `(0,30,None),(1,20,None)` один сегмент должен сохраниться. Маты рисуются самостоятельными заметными метками `M3/−M2`, не cp=0. В режиме Δ продолжают исключаться пары с матом.

**Как исправить:** `_continuous_segments` соединяет только соседние *числовые* оценки с `mate is None` с обеих сторон; `paintEvent` использует отфильтрованные пары. Оставить маркер мата отдельным объектом с контекстной подписью. Если последовательность матов требует графического соединения, это должен быть иной явно обозначенный mate-only layer, не часть cp-линии. Qt regression на `normal→mate→normal`, `normal→mate`, `mate→normal`, `normal→normal`, sparse gaps и tooltip, плюс screenshot/assert что линия не пересекает область мата. Не использовать искусственные ±1000 cp.
