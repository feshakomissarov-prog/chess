## U10 — P1 — «Анализировать позицию Stockfish» недоступно в обычном приложении

**Доказательство:** \`src/chess_coach/window.py:2973–2998\` допускает \`_set_position_evaluation_enabled\` и \`_start_position_evaluation\` **только при \`self.offline_mode == True\`**; \`tests/test_window.py:586+\` прямо закрепляет, что в обычном режиме кнопку не видно. Однако \`--offline\` проекта — QA smoke с **отдельной пустой временной SQLite и настройками**, не нормальная работа с историей владельца; владелец уже жаловался на отсутствие оценки на обычной свободной доске. В результате заявленный U8 практически недоступен при обычном запуске. Это сознательное safety ограничение, но **не полноценная реализация исходного UX**.

**Требование:** без ослабления Fair Play ввести настоящий понятный **учебный локальный режим** в нормальном desktop-контексте (с той же пользовательской DB/settings), с явным opt-in, при котором проверено, что режим не связан с активной Lichess human game. Если есть подключённый аккаунт, safety preflight обязательно fail-closed и контролируется пока UCI выполняется; если token/network state неизвестно или есть human game — analysis disabled, pending UCI остановлен, PV hidden. Если у локального пользователя вообще нет подтверждаемого safety-контекста и нельзя доказать отсутствие live human game, **не выдумывать «безопасно»** — добавить понятную причину блокировки и зафиксировать U8 PARTIAL; никогда не превращать \`--offline\` smoke в обход. Открыть позицию завершённой партии и анализировать её только после того же safety contract. Любые изменения режима/session/identity немедленно обнуляют evaluation generation и скрывают подсказки. Реальную пользовательскую базу в тестах не открывать.

**Acceptance:** fake safe offline local study в обычном \`--manual-connect\`/normal context: по явной кнопке видна корректная белая POV оценка; fake current human game/429/stale/unknown/disconnect -> 0 UCI starts + PV hidden. Debounce 4 быстрых хода -> оценивается только финальная FEN; no SQLite mutation/no stale info. Если безопасно не реализовать без архитектурной переделки, явно пометить \`PARTIAL\` (не DONE) с оставшимся UX и не заявлять обычную локальную оценку готовой. **Это не требование разрешить движок онлайн-человеческой партии.**

## U11 — P1 — автообнаружение не находит Stockfish, установленный самим Chess Coach

**Доказательство:** \`src/chess_coach/engine_manager.py:32–49\` ищет только \`.../stockfish/19/stockfish.exe\` либо \`.../19/stockfish-windows-x86-64-avx2.exe\`, но реальный путь официального установленного ZIP по execution log: \`%LOCALAPPDATA%\ChessCoach\engines\stockfish\19\stockfish\stockfish-windows-x86-64-universal.exe\`. После сброса/перемещения QSettings, удаления старого path или на другом профиле **кнопка «Найти» вернёт «не найден» при наличии собственной установки**. \`tests/test_engine_manager.py\` проверяет только explicit configured path, не lookup managed nested install.

**Требование:** discover проверяет **фактический canonical путь установленного им официального release** (плюс явно поддерживаемые архитектуры), предпочтительно через установленный manifest/app-managed запись, с ограниченным поиском внутри **только app-managed root**, без сканирования всех дисков. Отдельно поле configured path, найденный candidate path, verified status; пересохранение настроек только после явной UCI-проверки. Устаревший/отсутствующий executable не считается ready. Не выполнять неожиданный \`exe\` только ради отображения результатов поиска. Если путь найден из QSettings и валиден — не требовать переустановку.

**Acceptance:** тест устанавливает ZIP с вложенным \`stockfish/stockfish-windows-x86-64-universal.exe\`, очищает настроенный путь, \`discover_stockfish(environ={LOCALAPPDATA,...})\` возвращает установленный путь; UCI verify test + GUI settings, file removed/corrupt, reinstall with previous working engine; no recursive scans outside allowlisted path; Unicode имя пользователя.

## U14 — P2 — кнопки анализа могут снова стать активными при небезопасном/неполном состоянии

**Доказательство:** \`window.py:1384–1401\` задаёт readiness на дату открытия BatchAnalysisDialog, однако \`:1403–1416\` \`set_running(False)\` безусловно включает Start и Resume после завершения/паузы, даже если движок/аккаунт уже недоступны. \`_lichess_status\` и \`_lichess_authenticated\` не обновляют этот dialog.set_readiness для уже открытого окна (в отличие от \`open_settings()\`). Сам backend \`_start_batch_analysis\` проверяет readiness, поэтому **обхода fair-play не обнаружено**, но GUI сообщает неправильное состояние и пользователь вновь сталкивается с неработающей кнопкой.

**Требование:** store last-ready snapshot / recompute readiness при connect/disconnect/429/installer settings/cancel/finished. \`set_running(False)\` не может включать кнопку, если readiness false. Весь UI event security state честен; backend остаётся independent fail-closed. No new engine on open.

**Acceptance:** открыть Batch без connected -> Start disabled; connect while dialog open -> enabled only after UCI verified+auth status; disconnect/429 during running -> paused, after complete button disabled; reinstall/install missing path -> disabled until verify; stale callbacks ignored. Existing 342 baseline maintained.
