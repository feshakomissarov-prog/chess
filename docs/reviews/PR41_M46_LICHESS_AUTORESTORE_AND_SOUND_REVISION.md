## A1 — автоматически восстанавливать последний аккаунт при обычном запуске приложения

**Воспроизведённая причина:** `src/chess_coach/window.py:2051` уже вызывает `self.lichess.restore()` для normal launch. Но `launch_chess_coach.cmd` запускает `pythonw -m chess_coach --manual-connect`, а `scripts/create_desktop_shortcut.ps1` создаёт ярлык с `Arguments="-m chess_coach --manual-connect"`. `debug_chess_coach.cmd` делает то же самое, и `tests/test_launcher.py` закрепляет старое поведение. Поэтому реальный ярлык **не** пытается читать ранее сохранённые OAuth/PAT credentials при старте.

**Требования:**
1. Для обычного `Chess Coach.lnk` и `launch_chess_coach.cmd` использовать **normal launch `pythonw -m chess_coach` без `--manual-connect`**. Пересоздать/обновить существующий ярлык с правильным `Arguments`, `WorkingDirectory`, иконкой и прежним валидированием Python venv. Учесть уже существующий ярлык: если он указывает на ту же безопасную исполняемую среду, обновить аргументы, не удалять произвольные сторонние ярлыки; при конфликте цели оставить безопасную ошибку.
2. **Специальные режимы сохранить:** `--manual-connect` по-прежнему означает **никакого чтения credentials и никаких сетевых запросов до явного действия пользователя**; `--offline` сохраняет изоляцию пользовательских credential/DB и отсутствие сети. `debug_chess_coach.cmd` **оставить в `--manual-connect`** для диагностики или явно документировать его специальную семантику. Не ломать оба CLI-флага.
3. При normal launch без токена: UI сразу работоспособен локально, никаких OAuth browser popups, никаких повторных запросов каждые N секунд, понятный статус «Не подключено — подключите Lichess». С токеном: **одна асинхронная попытка** через `LichessService.restore()`; не блокировать GUI/SQLite startup, не читать токен через QSettings/файлы/лог, использовать строго Windows Credential Manager. Метод выбирается последним корректным `lichess/selected_auth_method` (`oauth` или `personal_token`). Не смешивать два слота; не переключаться на другой без явного намерения пользователя.
4. На successful account check/event stream установить статус подключённой учётной записи только после подтверждения **текущей auth generation**; на 401/403/expired/revoked — статус «Токен недействителен — подключить заново», без автоматического OAuth browser; не удалять PAT при отказе OAuth и наоборот. На 429/Retry-After и offline network error — информативный статус и ограничение повтора; не делать tight retry loop. Со сменой auth_method/logout/revoke всё старое session status/event callback отбрасывается. При явно нажатой пользователем кнопке «Отключить сеанс» **не восстанавливать соединение в рамках текущего процесса**, пока пользователь не инициирует connect; при следующем обычном запуске сохраняемый credential можно использовать только согласно понятной политике «disconnect vs revoke» (проверить текущую семантику и показать пользователю, что токен не удалён). Опциональная настройка «Подключаться при запуске» (default ON) желательна, но не должна мешать режиму manual-connect.
5. **Критический Fair Play invariant:** auto restore ≠ **свежий safety preflight для анализа**. После подключения всё равно `check_active_games_for_analysis` для session/account/generation/current line; при human active/unknown/reconnecting/429 никакого движка, PV, стрелок, phase stats и hints. Не открывать автоматически ранее сохранённый анализ в доверенном состоянии. PAT/OAuth auth errors не обнуляют защиту.
6. **Тесты:** проверять файлы launcher+shortcut (нет `--manual-connect` у normal, `--manual-connect` остаётся у debug); fake WindowsCredentialStore для OAuth/PAT, selected method, no credentials, invalid/expired, 429, disconnect/revoke, generation stale, startup no synchronous blocking; no auth read or network in `--manual-connect`/`--offline`; normal auto-login does **not** grant analysis lease. Зафиксировать, что повторный запуск ярлыка активирует существующее приложение, а не создаёт второе.

**Приёмка владельцем:** закрыть программу → запустить **обычным ярлыком** → при наличии сохранённого токена статус сам меняется на «Подключено: ...» без нажатия «Подключить Lichess», браузера или нового ввода PAT. В отсутствие токена/интернета остаётся рабочая локальная доска. Кнопка подключения доступна для ручного восстановления.

## S1 — полностью заменить текущие плохие звуки на принятые владельцем, добавить старт партии

**Серьёзный UX blocker:** текущие два `move-recording-v1.wav` и `capture-recording-v1.wav` уже неоднократно **отклонены владельцем на слух**. Пройденные Qt-тесты и CC0-лицензия **не означают**, что звук подходит. Нельзя просто увеличить громкость/переделать синтез и снова поставить те же два samples.

**Референсы владельца:**
- Начало партии: https://www.myinstants.com/en/instant/lichess-beep-21696/ — **эталон слухового впечатления**, не автоматическое разрешение на копирование.
- Локально на Windows: `C:\Users\Михаил\Downloads\lila-master.zip\lila-master\public\sound` — пользователь скачал архив проекта Lichess; Codex может **только читать и прослушивать** звуки в этой директории/ZIP, не переписывать и не публиковать весь пакет.
- Загруженный в чат отдельный образец: файл `freesound_community-ficha-de-ajedrez-34722.mp3`, **длина 2.064 секунды**; это именно отдельная запись удара/перемещения шахматной фигуры, **не подтверждено**, что он тождественен «Lichess Beep» по ссылке. Первичная опубликованная страница: https://pixabay.com/sound-effects/film-special-effects-ficha-de-ajedrez-34722/ — автор `lucho0880` (через `freesound_community`), указан **Pixabay Content License**, а не CC0. Проверить условия конкретной лицензии до распространения готового WAV; хранить credits.
- Предварительно выделенный пример **0.435–0.960 c (~525 мс)** из загруженного файла: короткий пик около `0.46 s`, срезаны пустое начало/хвост, короткие fade и ограничение пика. Пользователь должен **послушать и принять**, прежде чем считать это финальным звуком. В репозитории пока файла **нет**; Codex получит его только после явной передачи владельцем на свой компьютер, не искать путь из ChatGPT в его Windows.

**Что сделать:**
1. Формально выделить **три разных audio cues**: `game_start`, `move`, `capture`. Пользователь прямо просит *Lichess-like beep* **при начале партии**, но простого перемещения фигуры **при ходе**, а не сигнал для всех событий. Отменённый предход, перемещение по истории и запрос анализа не являются game start. Для `game_start` выбрать узнаваемый короткий beep **не более ~0.4–0.8 с**, обрезанный от тишины, без 1–2 секунд лишнего. Для `move`/ `capture` найти естественные «шахматные» сэмплы, **не использовать отвергнутую пару в default**.
2. **Перед новой установкой** сформировать короткие прослушиваемые demo previews **для всех трёх** категорий (либо 2–3 альтернативы), показать владельцу файлы/кнопки в настройках. **Не принимать художественное качество автоматически.** Codex должен предложить конкретные **проверяемые** файлы, а не просто фразу «нашёл натуральные».
3. **Лицензии:** `https://github.com/lichess-org/lila/blob/master/COPYING.md` явно относит часть `public/sound` к **non-free**, хотя `public/sounds/futuristic`, `nes`, `piano`, `sfx` перечислены как AGPLv3+. Поэтому нельзя вслепую копировать содержимое `public/sound` в Chess Coach: отдельно сопоставить выбранные файлы с лицензиями/авторством; если у нужного Lichess beep нет прав для распространения, брать оригинальный звук из совместимо лицензированного источника или получить разрешение. Myinstants даёт возможность слушать/скачивать, но **не устанавливает право на включение в продукт**. Для загруженного Pixabay файла соблюдать конкретную Pixabay Content License, особенно при возможном распространении приложения. Скрипт Codex не должен удалять/редактировать `lila-master.zip`.
4. **Реализация:** все три samples по умолчанию включены согласно предпочтениям пользователя, `QSoundEffect` предзагружает assets и проверяет `status/isLoaded`, файловый путь должен быть корректен при запуске через ярлык и exe/package; `preview('game_start')`, `preview('move')`, `preview('capture')` доступны отдельными кнопками. Настройки volume/mute и persist между запусками, без stale cache. Отдельные события normal move / capture (один ход — ровно один сигнал); `game_start` **ровно один раз на действительно начавшуюся новую партию**, при replay/refresh и reconnect не срабатывать. Проводка local free board/AI online/human online должна учитывать, было ли реально событие старта, а не просто открыли экран.
5. **Надёжность:** при новой 2-й, 3-й партии, повторном входе из home, restore workspace, показе после sleep, game_start/move/capture снова звучат; если аудиодрайвер недоступен — дружелюбный статус «Звук не воспроизводится, проверьте устройство» вместо ложного «PASS». Несколько каналов не должны накладываться без необходимости. Убедиться, что muted notification не звучит, а capture не выдаёт move+capture.
6. **Тесты:** file metadata/duration/silence/peak, process at 44.1 kHz mono PCM16, sound cue routing, duplicate event & retry, new game local and Lichess AI, audio unavailable gracefully; Qt mock verifies source+loaded state; реальные устройства в CI отсутствуют — финальное `S1` принимается **после прослушивания владельцем** на Windows в первом и повторном матче.

**Обязательно:** `docs/SOUND_ASSETS_CREDITS.md` обновить: автор, license, URL, src name, timestamp crop, SHA256, обработка, distinction reference-only vs included file. При отсутствии достоверных прав `game_start` demo использовать только как временный preview **вне распространяемого пакета**, и явно писать, что это не финальный bundled asset.
