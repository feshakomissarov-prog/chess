## P0 — безопасность: обязательно до любых других изменений

### P0-1. Проверенный safety lease остаётся разрешённым после начала человеческой онлайн-партии

**Где:** `src/chess_coach/window.py` `_review_safety_games_received`, `_lichess_event` (`gameStart`), `_invalidate_analysis_preflight`; `src/chess_coach/ui/game_review.py` `start_training`, `show_hint`, `check_training_move`.

Успешный snapshot разрешает `review_workspace.training_allowed`. При новом человеческом `gameStart` текущий код останавливает массовый/позиционный analysis, но **не снимает уже выданное разрешение** на сохранённые PV-подсказки. `_invalidate_analysis_preflight` отзываeт workspace safety лишь при *ожидающем* запросе; после success запрос уже снят. Исполнение тренировки/раскрытие подсказок не перепроверяет актуальность lease.

**Исправить:** централизованно аннулировать и скрывать учебные подсказки/результаты при новом human-game, неизвестном или устаревшем состоянии, 429, смене аккаунта/auth generation, отключении; в уже начатом упражнении принудительно остановить проверку и показ решения. Безопасный офлайн-режим без подключения к человеческому live-game сохранить. Fail closed при неопределённости.

### P0-2. Поздний safe-result партии A может разрешить упражнение партии B

**Где:** `_request_review_training_safety`, `_review_safety_reply_is_current`, `_open_saved_game`.

В context хранится `game_id`, однако при приёме ответа не сравнивается с реально открытым workspace. Открытие B не инвалидирует pending request A. Результат A может вызвать `set_training_safety_result(True)` уже для B.

**Исправить:** safety request жёстко связать с `game_id + line_revision + line_hash + account_id + auth/session generation`. При смене game/линии/аккаунта/маршрута инвалидировать запрос; поздний результат не должен обновлять B и не должен разрешать ход/подсказки.

### P0-3. Сохранённые оценки и CP доступны в review во время live human game

**Где:** `_open_saved_game`, `GameReviewWorkspace.load_game`, `ReviewGraph`, `select_ply`.

`_review_training_safety()` ограничивает только кнопку упражнения. При активной человеческой Lichess-партии открытие другой завершённой партии по-прежнему загружает/рисует график движковых оценок, а `select_ply` показывает CP. В нормативном §5.1 и §11 прямо требуется скрывать engine hints/PV при live human-партии **также при переходах в другие окна**.

**Исправить:** сделать единый read-only visibility safety gate для Stockfish/Lichess PV/CP/engine-best/движковых подсказок во **всех** game-review поверхностях. При live human игре можно оставить простое воспроизведение PGN/ходов без eval/PV. При получении события старта игры моментально очищать видимые ранее оценки. После завершения/восстановления состояния — только новый актуальный safety preflight. Не допускать leakage через tabs, график, подписи, hotkeys и stale signal.

**P0-тесты:** success safety→new human `gameStart` (до и во время exercise); pending safety A→switch B→late success; OAuth↔PAT, disconnect, 429, stale generation, unknown truncated snapshot; live human→open finished game→в UI нет CP/PV/hint ни по клику, ни по старым виджетам; offline isolated exercise в прежнем режиме работает. Проверять с fake Qt/event-barrier, не делать реальных запросов.

## P1 — обязательные пользовательские требования M4.6, не выполненные кодом

### P1-1. Главная: четыре KPI не соответствуют утверждённому контракту

**Где:** `src/chess_coach/ui/dashboard.py:dashboard_snapshot`, `window.py:_build_home_page`.

ТЗ §4: **Партий; Средняя точность (официальная, n/N); Разобрано (complete/partial + coverage); Ошибки /100 оценённых собственных ходов**. Фактически сейчас: «Завершённые партии», «Мои результаты», «Покрытие анализа» (все complete/partial вместе одним %) и «Задачи Lichess». Значения считаются по глобальной таблице `games`, а не явно выбранному account/scope; linked accounts могут приводить к неверной перспективе. Структурно корректное число не заменяет требуемый KPI.

**Исправить:** нормативные четыре KPI, selected account/source/scope, явные n/N и статусы полного/частичного анализа, правильный decision denominator. При недостатке официальной accuracy выводить «н/д» и источник, не вычислять фиктивную local accuracy. Дополнительные результаты/задачи оставить во вторичных областях, если полезны.

### P1-2. Последние 3 партии не являются «богатыми карточками» из §4.1

**Где:** `window.py:_refresh_home_dashboard`, `ui/dashboard.py:game_card_text`.

Создаются трёхстрочные по сути QPushButton с результатом, соперником, датой, clock и дебютом; высота всего 68. **Нет обязательных пяти показателей:** accuracy, inaccuracies, mistakes, blunders, verified strong moves; нет source/coverage/status на карточке. ТЗ требует min height112 и явный unknown/partial, а не просто ссылку.

**Исправить:** bounded data adapter по выбранному account и последней текущей линии для **только трёх** завершённых партий; статистика каждой с provenance и n/N, без full-scan PGN и без UCI-on-open. Реальные cards со второй строкой пяти метрик, source, частичным покрытием; no-analysis state честен.

### P1-3. Главный экран всё ещё длинная техническая панель

**Где:** `window.py:_build_home_page` — после метрик и последних партий добавлен заголовок «Ещё», за которым сразу идут 10+ постоянно видимых QPushButton (архив, пилоты, статистика, массовый анализ, настройки и т.д.). Верхние CTA — узкие кнопки «Lichess AI»/«Свободная доска», тогда как §4 требует две полноценные карточки действий «Играть» и «Разобрать», приоритет активной партии/последнего разбора.

**Исправить:** сделать основную Home композицию по §4: два основных действия, контекстное продолжение игры/разбора, 4 KPI, 3 информативные партии. Технические операции — в соответствующих разделах или действительно сворачиваемом «Ещё». Не удалять существующие возможности из приложения, только убрать визуальное нагромождение.

### P1-4. График partial analysis неправильно выбирает ходы и дорисовывает пропуски

**Где:** `src/chess_coach/ui/game_review.py:ReviewGraph._values/paintEvent/mousePressEvent/keyPressEvent`.

X-axis max = **последний оценённый ply**, а не общая длина сохранённой партии. Для partial результатов end/right click недостижимы поздние ходы; если нет оценки в середине, линия `zip(coords, coords[1:])` соединяет точки через пробел и притворяется непрерывным анализом. Клик округляет произвольный ply и не ищет **ближайший действительно оценённый** (в нарушение §5.1–5.2). Tooltip/source/budget/coverage не реализованы.

**Исправить:** ось 0..full game N; разрывы вместо ложных соединений; график выбирает ближайший реально сохранённый scored ply, а нотация при этом умеет навигацию по всем N. Сохранить выбранный ход и подсветку, курсор не выходящий за пределы. Добавить hover/click explanation для оценки, качества, источника и отсутствия данных; не фабриковать severity/CP. Тест: >=70 полуходов, sparse/mate/unknown оценка, пропуск в середине и в конце.

### P1-5. Единый разбор пока не покрывает обязательные «ключевые моменты»

**Где:** `GameReviewWorkspace` имеет вкладки «Ходы», «Показатели», «Заметки», но нет пути для **предыдущей/следующей ошибки** и просмотра `analysis_events`/PV по selected ply, требуемых §5.1, §5.3. Кнопка «Следующая ошибка» есть только внутри упражнения, это другая функция.

**Исправить:** на текущем сохранённом `analysis` показать доступные events/facts и проверенные PV, если safety позволяет; навигацию по previous/next own/move error с корректным ply. Не придумывать события, если evidence отсутствует. Сохранить единый workspace и без анализа.
