## Результат первой части: НЕ ПРИНИМАТЬ до исправления P0

### P0-1. Успешная проверка Lichess оставляет тренировочные подсказки разрешёнными после начала партии с человеком

**Факты в коде (SHA выше):**
- `src/chess_coach/window.py`: `_review_safety_games_received` разрешает `review_workspace.training_allowed` по безопасному ответу Lichess; `_lichess_event(gameStart)` останавливает анализ и массовую очередь, **но не отзывает ранее данное разрешение на упражнение**.
- `_invalidate_analysis_preflight` сбрасывает разрешение в workspace только при `_review_safety_request_id is not None`; если запрос уже успешно завершился, флаг остаётся `True`.
- `src/chess_coach/ui/game_review.py`: `start_training`, `check_training_move`, `show_hint` опираются на сохранённый `training_allowed`/локальное состояние; после появления живой человеческой партии можно получить подсказку из сохранённого PV.

**Нужно:** любой `gameStart` с человеком, потеря безопасного статуса, переход/разрыв сессии, 429, неизвестное состояние должны немедленно обнулять safety lease и запрещать раскрытие учебного решения; если упражнение уже запущено — остановить его и скрыть ранее раскрываемые PV/варианты/подсказки. Разрешение нельзя считать бессрочным. Не блокировать чистую офлайн-тренировку без Lichess аккаунта, но обеспечить жёсткую изоляцию от live human game.

### P0-2. Запоздалый ответ проверки для партии A способен разрешить упражнение в другой партии B

**Факты:**
- `_request_review_training_safety(game_id)` сохраняет `game_id` в `_review_safety_context`.
- `_review_safety_reply_is_current` сверяет generation, пользователя, service, но **не сверяет сохранённый game_id с фактически открытой партией**.
- `_open_saved_game` открывает другой `review_workspace.load_game`, но не инвалидирует pending safety request. Ответ для A вызывает `set_training_safety_result(True)` и перезагружает уже открытую B.

**Нужно:** привязывать проверку к identity текущего review (game_id + line_revision/hash, account + session generation), отменять при переходах/смене линии, отвергать старый ответ без изменения состояния B.

## Обязательные тесты

1. Позиция завершённой партии A, безопасный Lichess snapshot => разрешение; затем `gameStart` с человеческим соперником => упражнения и подсказки немедленно блокируются; если упражнение было начато, раскрытие/проверка запрещены.
2. Safe snapshot A, затем Disconnect / смена OAuth↔PAT / новый auth generation / 429 => ранее выданное разрешение отозвано; UI и callbacks не обходят блокировку.
3. Pending safety для A; открыть B; поздний safe-result для A => B остаётся заблокированной.
4. Pending safety с неизменным username, но сменённой session generation => reject.
5. Confirmed offline isolation: локальное учебное упражнение без live Lichess работает, а live human game никогда не получает engine hints.
6. Полный Windows CI на итоговом SHA, regression around game review/session generation; ручная проверка владельцем после технической готовности.
