## 3. Архитектура × UX — результаты проверки

- **Хорошо сочетаются:** модульный монолит/единый runtime с 6 Qt страницами, Lichess live lane с постоянной доской/сменой route, одна SQLite с shared data projections для Home/Details/Review/Progress, один Stockfish admission с Review/Batch/FEN и один inspector существующих background jobs. Новые микросервисы для этого не нужны и ухудшили бы консистентность account/game/safety.
- **Требуют адресной перестройки UI:** result finalization из `MainWindow`, скорлупа Home `QScrollArea`, перевод обычных Library/Statistics/Puzzle dialogs в страницы, отдельный route/selection state, связь cross-page Fair Play lease и совместное score/provenance преобразование. Эти изменения перечислены как A0–A12 в ТЗ.
- **Чего не делать:** пересобирать из пустоты ARCH-01, копировать Stockfish manager или SQLite по вкладкам, мигрировать схему ради UX, изобретать новый скоринг, заново писать готовый ReviewGraph и звуки, запускать побочные эффекты при смене route.
- **Оптимизация без ложных SLA:** один ресурс на вид/операцию, bounded queries/пагинация, lazy render, coalesced Qt status, account/version-aware cache invalidation; если обнаружен bottleneck, записать воспроизводимый trace и исправить, **не обещать цифры без измерения**.

## 4. Состояние перед выдачей задания

**Документационный результат:** обновлены AGENTS, PCD, PRD, PRODUCT_VISION, ROADMAP, PROJECT_STATUS, README, ARCH-01 target/execution docs и согласованные UX документы; единый [ARCH-UX-01 v1.1](../specs/ARCH_UX_01_UNIFIED_EXECUTION_SPEC.md) отсылает сюда. **PR #45 docs-only; код PR #44 в ходе этой сверки не менялся.**

**Не проверялось и не должно объявляться PASS:** новый UX пока не реализован, CI v1.1 не запускался (только docs), физические Windows screens/DPI/sounds, реальные токены, локальный пользовательский архив и настоящий Stockfish. Реализованный Codex код подлежит новой независимой проверке, новой приёмке и **не сливается автоматически**.

**Готовность к передаче:** Да, как **ТЗ для реализации**, а не как готовая программа. Владелец вручную передаёт ссылку desktop Codex; исполнитель проверяет актуальные PR/head перед изменениями и ведёт журнал A0–A12.
