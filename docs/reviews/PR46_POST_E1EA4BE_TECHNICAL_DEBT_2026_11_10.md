## TD-01 [P2] После восстановления Home из кэша пропадают известные даты последних партий

- **Факты:** `dashboard_preview_snapshot()` выбирает `last_move_at` и `game_time_precision` ([dashboard.py:96–106](https://github.com/feshakomissarov-prog/chess/blob/e1ea4be86507b7fa41f6028715e1ed4a2f62f6cc/src/chess_coach/application/dashboard.py#L96-L106)). UI `format_game_activity_time()` использует именно эти поля, а без них выводит «Время начала неизвестно» даже при известном `started_at` ([ui/display.py:47–66](https://github.com/feshakomissarov-prog/chess/blob/e1ea4be86507b7fa41f6028715e1ed4a2f62f6cc/src/chess_coach/ui/display.py#L47-L66)). Но `_split_snapshot()` **не сохраняет** оба поля в Tier A ([dashboard_cache.py:194–211](https://github.com/feshakomissarov-prog/chess/blob/e1ea4be86507b7fa41f6028715e1ed4a2f62f6cc/src/chess_coach/application/dashboard_cache.py#L194-L211)).
- **Независимое подтверждение из собственных evidence Codex:** после восстановления кэша [green-3320-navigation-profile.json](https://github.com/feshakomissarov-prog/chess/blob/e1ea4be86507b7fa41f6028715e1ed4a2f62f6cc/docs/ux/evidence/pr46-home-cache-remediation/green-3320-navigation-profile.json) три карточки показывают «Время начала неизвестно», в то время как предыдущий свежий preview ([green-3320-telemetry.json](https://github.com/feshakomissarov-prog/chess/blob/e1ea4be86507b7fa41f6028715e1ed4a2f62f6cc/docs/ux/evidence/pr46-home-cache-remediation/green-3320-telemetry.json)) показывал даты. Это не сетевая проблема Lichess.
- **Будущее исправление:** сохранить компактные `last_move_at` и `game_time_precision` с типовой валидацией/миграцией форматной версии; не смешивать known date-only и timestamp; гарантия одинакового текста карточек fresh SQL → cached restart. Тест на реальных структурах dated last_move/precision (включая UTC conversion) и рендер Qt.

## TD-02 [P2] Ошибка нового фонового aggregate заменяет уже показанный last-good на «н/д»

- **Факты:** [window.py:3604–3609](https://github.com/feshakomissarov-prog/chess/blob/e1ea4be86507b7fa41f6028715e1ed4a2f62f6cc/src/chess_coach/window.py#L3604-L3609): при `error is not None` код выставляет **всем** значениям Home «н/д» и заменяет подробности сообщением об ошибке, не сверяя с `_latest_dashboard_snapshot`. Это существовало и на `fa2053c8`; ошибка не порождена исправлением раздела 11.
- **Контрсценарий:** валидный ранее сохранённый Tier B показан в stale-режиме после новой партии → фоновый full aggregate завершается `sqlite3.OperationalError`/ошибкой чтения → сохранённые исторические цифры визуально исчезают до следующего успешного refresh. SQLite/кэш при этом не удалены.
- **Будущее исправление:** при transient error сохранить видимые last-good числа и source timestamp текущего scope, отдельно показать «обновление временно недоступно»; только при отсутствии каких-либо валидных фактов показывать «н/д». Regression test с явным `error` из worker при наличии cached B и без кэша. Не нарушать cross-account и Fair Play.

## TD-03 [P2] Валидный JSON envelope с повреждённой записью профиля не использует резервную previous-копию

- **Факты:** `DashboardSnapshotCache._read_document()` возвращает первый JSON-документ с корректным внешним envelope, не валидируя scoped tier content ([dashboard_cache.py:364–404](https://github.com/feshakomissarov-prog/chess/blob/e1ea4be86507b7fa41f6028715e1ed4a2f62f6cc/src/chess_coach/application/dashboard_cache.py#L364-L404)). `load()` валидирует `tier_a/tier_b` **после** возврата ([dashboard_cache.py:407–442](https://github.com/feshakomissarov-prog/chess/blob/e1ea4be86507b7fa41f6028715e1ed4a2f62f6cc/src/chess_coach/application/dashboard_cache.py#L407-L442)) и в случае неверной структуры возвращает None, не пробуя `.previous`.
- **Будущее исправление:** bounded per-scope fallback на last-good backup при неправильном содержимом primary даже если JSON синтаксически корректен; не показывать устаревшую формулу, чужой профиль или повреждённую запись. Тест main valid-envelope/invalid-tier + previous valid, а также обе повреждены → безопасный cache miss.
