## 2. KPI завершённых партий и точности

### HIMG-07 — убираем «Выбранный аккаунт»

- Полностью убрать строку `Выбранный аккаунт` **только из KPI «Завершённые партии»**. Она расходует место и не сообщает новой информации. Сам фильтр/привязку профиля, account scope и достоверность не удалять.
- Основной показатель — реальные завершённые партии выбранного аккаунта. Под ним компактно `С оценками: N` и при необходимости Lichess/Stockfish с **достоверным смыслом существующих полей**; при отсутствии числа — `—` или понятное `Нет данных`, без фантазий.
- «Точность»: фактическое сохранённое значение + краткие строки с **отдельными источниками** Lichess/Stockfish и denominator/охватом, где это уже требуется STAB-01. Нельзя подменять локальную расчётную точность официальной и наоборот.
- Сохранить реальное обновление 3325→3326 после появления новой партии, correct account switching, last-good Tier B и офлайн-состояния. Значения 3325/82.9% на изображении — исключительно пример.

## 3. Recent games: расширенная карточка партии (главный визуальный приоритет)

### HIMG-08 — три информационные зоны В КАЖДОЙ карточке

1. **Левая зона — информация:** результат с цветовым акцентом (победа — зелёный, поражение — красный, ничья — нейтральный), соперник / `Lichess AI level N` если действительно применимо, дебют (когда известен), общая точность с источником (когда посчитана), **краткая дата + время без длинной фразы `Завершена:`**, число ходов. Если контроль времени не известен, не писать громоздкое `Контроль не указан`: убрать строку либо показать `—` при явной необходимости. Не приписывать дебют/результат, которого нет в записи.
2. **Центральная зона — табличная сводка:** `Я | Соперник` и три строки `Неточности`, `Ошибки`, `Зевки`, значения из уже имеющейся **достоверной классификации сохранённых оценённых ходов**. Привязывать `Я` к реальной стороне текущего пользователя в этой партии; у локальной партии без определённого владельца использовать `Белые / Чёрные` вместо ложного `Я`. Нельзя перепутать стороны в игре за чёрных. Если анализа нет/неполный, показывать `—`, и корректную компактную причину по tooltip; не считать отсутствие оценки нулём. Не использовать придуманную таблицу 3/7/1/3 с картинки.
3. **Правая зона — график оценки позиции:** чистый сглаженный по стилю (но НЕ искажающий реальные данные) line/area chart с нулевой линией, понятной легендой **`+ белые / − чёрные`**, осью `Преимущество (в пешках)` и метками хода / стадии партии. Без серых точек-маркеров на каждом ходе и без перекрывающих график жёлтых предупреждений `за пределами...`. У карточек одинаковая шкала и компоновка там, где сравниваются численные оценки.

### HIMG-09 — математическая и шахматная корректность графика

- Для исторических **разрешённых** оценок использовать сохранённые centipawn оценки: (value\_pawns = white\_cp / 100). **Всегда белая перспектива независимо от результата партии и цвета владельца**: выше нуля преимущество белых, ниже — чёрных; интерфейс должен прямо это объяснять. Цвет результата карточки и знак/цвет кривой — независимые вещи (например, можно выиграть чёрными при отрицательных white_cp).
- Для mate-информации не подменять мат значением «+6 пешек»; отдельный знак/tooltip `M+` / `M−` по фактической стороне, при необходимости визуальный boundary marker без неправдивого численного значения. Нельзя делать `float('inf')` и выводить артефакты clip.
- Если реальная оценка вышла за текущий диапазон оси, подстраивать scale по данным в пределах разумных ограничений либо явно ставить корректный edge marker и полный tooltip; **никаких торчащих жёлтых надписей**. Не отбрасывать реальную информацию молча.
- По X — реальный номер `ply` или хода; стадии `Дебют / Миттельшпиль / Эндшпиль` показывать как визуальные подписи. Границы стадий рассчитывать по доступной шахматной логике/проверенным phase data; при отсутствии надёжного определения использовать нейтральные метки прогресса, не выдавать произвольные 1/3 за реальные стадии.
- Сохранить пропуски данных как пропуски (разрывы/пунктир и tooltip `нет оценки`), не интерполировать несуществующие оценки как фактические. Сглаживание допустимо только антиалиасингом/визуальным рендером, без переписывания значений.
- Ресурс: использовать лёгкий `QPainter`/существующий безопасный Qt review chart компонент с **отключёнными маркерами** и адекватным компактным режимом; не запускать Stockfish из Home, не вычислять оценку синхронно на UI-потоке, не добавлять новые дорогие зависимости.

### HIMG-10 — компактность без потери смысла

- На референсном размере **все три** последние игры полностью видны в одном общем блоке; карточки допускается сделать значительно выше текущих, за счёт пространства, которое раньше оставалось пустым снизу справа.
- Левый контент каждой карточки, таблица и график вмещаются в её рамки; заголовки, точность, результат, даты, значения, подписи шкалы не обрезаны.
- Высоту и ширину вычислять от фактической доступной области, длинные дебюты корректно сокращать **с tooltip**, текст ключевых метрик не сокращать до нечитаемого.
- Нажатие карточки продолжает открывать соответствующую сохранённую партию/разбор через прежний маршрут; клавиатура/фокус/Enter работают, не только декоративный hover. Кнопка `Все партии` продолжает открывать библиотеку.
- Не отображать анализ и оценки для текущей human live game, не обходить Fair Play safety gate. В недоступном случае скрыть реальные оценки/таблицу/график и показать корректное объяснение. Не показывать сохранённую старую оценку в качестве якобы безопасной новой.

## 4. Рейтинг задач

### HIMG-11 — приятный, но честный график

- Сохраняется KPI `Рейтинг задач`, реальное число и `Весь прогресс`.
- Тренд по действительно сохранённой истории рейтинга: более аккуратная зелёная линия/градиент, ровная координатная сетка/подписи осей с реальными значениями и диапазоном дней. Линия не должна искажать хронологию или добавлять фальшивые точки.
- Это **низший визуальный приоритет** по сравнению с последними партиями, задачей и правдивыми данными. Если комплексный редизайн грозит стабильности, оставить действующий график, подчистив только явный clipping/пустоты.

## 5. «Следующая задача» — реальная позиция и переход в задачи

### HIMG-12 — содержимое карточки

- Заголовок `Следующая задача`, мини-доска **8×8** с корректно выставленными шахматными фигурами, подпись `Задача Lichess`, «Найдите лучший ход за белых/чёрных» **из фактического turn**, rating/theme только из реальных данных, крупный CTA `Решать задачу`.
- Источник — разрешённая функция Lichess/уже сохранённая задача или задача для повторного решения из реальной локальной истории. **Проверить существующие возможности репозитория и допустимые официальные API/условия** до реализации внешнего запроса. ## 6. Скорость, безопасность и границы изменений

- Все визуальные улучшения Home **не ухудшают существующее P0 требование:** для профиля с сохранённой рассчитанной сводкой **полные достоверные сохранённые показатели ≤1000 мс от первого видимого кадра окна** при каждом проверенном штатном запуске. График recent и пазл превью могут дозагружаться после первой осмысленной отрисовки, **но сами данные count/accuracy-source/rating/3 recent games и их основные тексты — нет**.
- Нельзя делать запрос Lichess/Stockfish/тяжёлую SQLite агрегацию в конструкторе Home или в GUI thread. Кешировать/переиспользовать preview, lazy-paint тяжёлый контент. Не скрывать 15-секундный холодный расчёт как «успешный P0» без разъяснения различия first-ever/no cache и warm.
- Сохраняются выбранный аккаунт, предыдущие настройки, SQLite / миграции и Fair Play. Не добавлять динамическую оценку на живой human online партии.
