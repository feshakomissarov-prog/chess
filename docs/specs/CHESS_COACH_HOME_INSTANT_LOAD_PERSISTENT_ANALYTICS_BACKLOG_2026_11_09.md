# Chess Coach — Home Instant Load / сохранённая аналитика

**Статус:** согласованная продуктовая идея / BACKLOG, **не ТЗ на немедленное исполнение**.  
**Приоритет по времени:** после завершения и приёмки Draft PR #46, до следующего крупного расширения функционала.  
**Решение владельца:** 09.11.2026.  
**Текущая реализация:** `show_home()` вызывает `_refresh_home_dashboard()`; повторно запускаются preview SQLite и полный aggregate, даже без изменений данных. Есть частичное сохранение предыдущего snapshot в памяти, но полноценного reuse и постоянного кэша между запусками нет.

## Продуктовая цель

Главная должна открываться сразу при запуске программы и при каждом возвращении из других разделов. Пользователь видит уже подготовленные результаты анализа **завершённых партий**, а не повторную загрузку/пересчёт при каждом заходе.

## Ожидаемое поведение

1. **Первый запуск без кэша:** фоново построить быструю сводку и подробную аналитику, сохранить готовые результаты после успешного расчёта.
2. **Повторный запуск программы:** сразу читать последний сохранённый согласованный snapshot с локального диска; без обязательного полного расчёта при отсутствии изменений источников.
3. **Возврат на Home:** переиспользовать готовый snapshot без нового полного SQL aggregate, без сброса на «загрузка» и без мерцания карточек.
4. **После изменения данных** (новая/изменённая завершённая партия, синхронизация, пересчитанные оценки, история задач, версия метрик): обновить только затронутые представления, где это корректно; если инкрементальный расчёт невозможен, пересчитать нужную сводку **один раз** в фоне и атомарно заменить кэш.
5. **Закрытие приложения:** уже готовые результаты сохранены по мере завершения расчётов, а не только в `closeEvent`. При аварийном завершении последний подтверждённый snapshot остаётся целым.
6. **Нет изменений:** не инициировать повторные полные пересчёты ни на старте, ни при навигации; смена аккаунта/фильтра выбирает свой корректный кэш.
7. **Во время фонового обновления:** показывать прошлое согласованное значение, при необходимости ненавязчивый индикатор актуализации, без долгого блокирования UI. Новые/изменившиеся карточки и источники не должны показывать неверные старые метрики.

## Ограничения и корректность

- Понятие «аналитика»: показатели по **ранее сыгранным, завершённым партиям**, архив, оценки источников, графики, задачи, не движковый анализ текущей позиции.
- Разнести **быструю сводку** (счётчики/последние партии) и **подробную** (точность/ошибки/охват/источники/тренды). Разрешить независимое обновление и fallback.
- Персистентность в существующей локальной SQLite либо эквивалентном локальном хранилище; без сервера, новой технологии, переписывания Qt или изменения личных PGN. Конкретный способ хранения решить после измерений и проверки схемы.
- Ключ кэша включает профиль/аккаунт, фильтры и версии алгоритмов/источников; проверка актуальности по устойчивой ревизии данных, а не только по времени запуска. Изменения внешнего Lichess после закрытия могут быть обнаружены при последующей синхронизации, поэтому нельзя считать онлайн-источник навсегда неизменным.
- Сохранять existing Fair Play / safety contract: **хранение разрешено, показ оценочных подсказок в UI только при действующем разрешении**. Сама обычная статистика по завершённым играм не должна беспричинно инициировать сетевую проверку при каждом переходе. Не расширять требования до анализа онлайн-партии.
- Параллельные вычисления, отмена, смена аккаунта, новая партия во время aggregate, revision mismatch и старые callbacks не должны возвращать устаревшие данные.
- Не допускать разрастания кэша без ограничений; предусмотреть версию схемы, очистку/инвалидацию и миграцию без потери исходных данных.
- Не обещать фиксированное число миллисекунд без реальных замеров на Windows и пользовательском объёме данных.
