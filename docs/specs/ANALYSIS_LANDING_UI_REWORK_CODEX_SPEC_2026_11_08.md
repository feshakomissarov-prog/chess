## 1. Зачем существует эта страница

Отвечает на один вопрос: **«Что я хочу исследовать?»**. Не должна быть панелью технических настроек или большим PGN редактором.

Четыре осмысленных входа:
1. **Разбор партии** — отдельный ранее работающий путь к своим партиям, внешнему PGN или FEN/расстановке. Сейчас реализованы core review/import/editor. Клик открывает вложенный выбор материала, не начинает Stockfish.
2. **Исследование дебютов** — изучение СВОИХ дебютов/результатов. **Сейчас** работает только существующая статистика из «Прогресса», поэтому обозначение «Частично доступно». Полный explorer позже.
3. **Диагностика слабостей** — будущая доказательная персональная аналитика повторяющихся ошибок, фаз и задач. Пока карточка неактивна.
4. **Подготовка к сопернику** — будущая аналитика публичных партий конкретного человека по контролям/цветам/частотам, **отдельная самостоятельная задача**, хотя будет разделять модель дебютов. Пока карточка неактивна.

**Массовый анализ** — не пятая карточка. Очередь и управление существующим пакетным Stockfish живут в глобальном сервисе **«Фон»**. Конфигурация вычислений, автоматизации и ресурсов — в **«Настройках»**. В «Моих партиях» остаётся явный анализ выбранной игры. Три точки доступа могут вести к общему manager, не создавать три очереди.

## 2. Компоновка по изображению

**Сохраняем исходную палитру:** тёмный navy/indigo, приглушённая лаванда/фиолетовый primary, серо-синие вторичные поверхности. Использовать существующие Qt/QSS tokens, текущий шрифт и style components. Не менять внешний вид всей программы ради одной вкладки.

**Sidebar/shell AS-IS:** название Chess Coach, состояние пользователя/Lichess, «Подключить/Отключить Lichess», шесть главных разделов Главная / Играть / Мои партии / Анализ (выделен) / Обучение / Прогресс, «Настройки» снизу. Общая маленькая «← Назад» вверху main. Справа общая кнопка «Фон», с двумя компактными чипами готовности/текущего задания при наличии реальных данных — подробности в §5. Шапка **общая для всех вкладок**, а не новая локальная панель Анализа.

**Заголовок:** один крупный «Анализ». В текущем source два QLabel/заголовка — второй убрать. Под ним одну короткую строку «Выберите направление анализа», без четырёхстрочного технического вступления.

**Главное содержимое:** ровно 4 крупные равные карточки в **2 колонки × 2 строки**:
- верх слева: «Разбор партии»;
- верх справа: «Исследование дебютов»;
- низ слева: «Диагностика слабостей»;
- низ справа: «Подготовка к сопернику».

Ориентир для desktop из approved render около 1672×941: content начинается примерно x=210, верхние карточки в области y≈214–480, нижние y≈508–748; между колонками ≈25 px. **Не задавать абсолютные координаты**, это визуальное сравнение, а не hard-coded layout. Qt QGridLayout с одинаковой шириной, одинаковой высотой row, равномерными отступами 16–28 logical px. Внутри каждой: квадратная подложка иконки слева, жирный заголовок, 1–2 строки пояснения, один нижний широкоформатный control, короткий status. Bottom controls **на одном уровне по ряду**. Не делать плитку вдвое выше остальных из-за длинного текста.

**Рабочие верхние кнопки** лавандовые, соответствуют текущим primary style. **Нижние две** disabled, «🔒 В разработке», более нейтральны, но читаемы; не выглядят как кликабельный активный primary. Disabled must not emit click, navigate or create blank page. Tooltip/accessible description сообщает назначение.

**Не присутствует на landing:** textarea «Внешняя партия или позиция», два PGN buttons, отдельный expanded PositionSetupWidget с шахматной доской, «Массовый анализ» и большая кнопка «Открыть очередь», технические конфиги движка, вторая строка большого «Анализ». Все функции PGN/FEN/редактора переезжают во вложенное «Разбор партии» и сохраняются.

**Responsive:** native Qt 1672×941, 1366×768, 1280×720, 1120×640, DPI 100/125/150%; sidebar open/closed. Если две колонки вместе с ним теряют минимум для readable controls — переход на одну колонку с вертикальной прокруткой main content, НЕ горизонтальная прокрутка всего окна; header chips не должны выталкивать «Фон», Back и title; никаких overlay/clipped action controls. Tab и Enter/Space только для реально работающих кнопок, не для двух future controls.

## 3. Функциональные карточки и маршруты

### 3.1 Разбор партии — AL-01, рабочая

Title «Разбор партии», описание «Мои партии, PGN, FEN и ручная расстановка позиции», CTA «Открыть разбор», статус «Работает».

**По нажатию:** открывается вложенная страница **«Выбрать материал»**; дальнейшая архитектура должна сохранить:
- «Из моих партий» → выбрать завершённую из существующего каталога → единый Review.
- «Открыть файл PGN» → существующий Windows file picker → валидировать/выбрать партию → Review (временный).
- «Вставить PGN» → поле вставки только на вложенной странице, parse/errors/несколько партий и выбор нужной → Review.
- «Вставить FEN» → отдельное небольшое поле, валидация позиции → Review/редактор.
- «Расставить позицию мышью» → PositionSetupWidget с выбором всех фигур, удалением, side-to-move, castling, en passant, доска, «Начальная позиция», «Очистить», «Открыть позицию в разборе»; **собственное рабочее пространство**, без наложения кнопок на доску.
Функции существуют в текущем AnalysisLandingPage, но избыточно открыты на landing. Переместить и **переиспользовать**, не терять backend/PGN/File/FEN handling. Исходная партия не перезаписывается временным вариантом. Внешняя PGN/FEN не попадает в архив неявно. **Ни один выбор не запускает Stockfish сам**. Нужна корректная source-aware Back. Подробный UX вложенного «Выбрать материал» будем утверждать следующим этапом; **до этого часть ТЗ не считать готовой к Codex**.

### 3.2 Исследование дебютов — AL-02, частичная готовность

Title «Исследование дебютов», описание «Мои дебюты, варианты, результаты и типичные ошибки» (описание цели, НЕ текущие доступные данные), CTA «Открыть статистику», статус «Частично доступно». Реальный route — **уже существующая страница статистики дебютов в «Прогрессе»**, без фальшивого opening explorer. Back возвращает на старт «Анализ».

В будущем: дерево ECO/вариантов, дебютные исходы/точность по источникам, фильтры по цвету и контролю, size of sample, транспозиции, просмотр подтверждённых ошибок и стратегических идей; не выдавать ошибку Stockfish за доказанное непонимание теории. Личный репертуар **Обучения** — отдельная будущая функция.

### 3.3 Диагностика слабостей — AL-03, FUTURE

Title «Диагностика слабостей», описание «Повторяющиеся ошибки, фазы партии и учебные приоритеты». Action disabled «В разработке» с lock icon. Без clicked/noop, пустого окна, фиктивных графиков и запросов. Future модель A×(B1+B2)→C→D→E: темы и когнитивные операции, evidence, слабости как вероятные гипотезы, упражнения и проверка переноса на новых партиях. **Ошибка хода ≠ доказанная причина ошибки.**

### 3.4 Подготовка к сопернику — AL-04, FUTURE

Title «Подготовка к сопернику», описание «Публичные партии соперника, дебюты и уязвимые линии». Action disabled «В разработке». В будущем: ввод username, только допустимые публичные Lichess игры, фильтры контроль/цвет/даты, частоты дебютов, варианты, проверенные PGN и оценки, размер выборки, указание неопределённости; малый sample — «Недостаточно данных». Подготовка только **до** человеческой партии; никаких подсказок в live human game. Сохранить отдельную плитку даже если частично переиспользуется Opening Explorer.

## 5. Общая шапка: два компактных прогресса, только настоящие данные

**Чип 1 «Готовность данных»** — один конкретный честный показатель, предпочтительно «Партий с валидными оценками X/Y сохранённых завершённых партий текущего аккаунта». Если неизвестен полный размер Lichess архива, нельзя вычислять % синхронизации. Импортированные игры != ready Stockfish != official Lichess coverage. Данные NaN/invalid-only/partial не считать готовой полной точностью. Без denominator показывать «Подсчитываем» / count, не 28%.

**Чип 2 «Текущий анализ»** — только реальная текущая Stockfish задача (X/Y позиций при known Y), состояние queued/running/paused/error из существующего coordinator. Если idle — короткое «Нет активного анализа» или скрытый idle чип. Несколько задач — единственный current job и переход в общий «Фон», не суммировать несопоставимые denominator. Не хардкодить 15/85.

**Нажатие «Фон»** → один уже существующий inspector Background Operations, со всеми archive sync, Lichess/backfill statuses и Stockfish job queue. Не дублировать его на Analysis Landing или в Settings. Global header source data account/generation-safe, A→B смена сразу сбрасывает stale metrics; не показывать чужую очередь.

## 6. Ограничения и состояния

- Открытие страницы/выбор карточки — без сетевого POST, создания игры или автоматического анализа. Только явно требуемое действие во вложенной workflow, с текущими safety checks.
- Active human Lichess game / unknown live status → никакой Stockfish PV/eval/accuracy/график/подсказки через импорт PGN/FEN или через sidebar. Fair Play fail-closed, в том числе cached tooltip/accessibility content.
- Offline/no-games: доступные существующие локальные партии и PGN/FEN работают в разрешённых состояниях; не рисовать данные, которых нет. Future disabled независимо от сети.
- Empty stats/loading/429/failed job: честный label/состояние, без «готово 100%» и фальшивого spinner. Смена аккаунта/партии/ревизии отсекает устаревшие ответы.
- Не трогать текущий SQLite/PGN original, line revisions, secret storage, remote Lichess credentials, шахматные алгоритмы.
- Вложенный editor/PGN импорт не должен открывать дублирующие самостоятельные программы или создавать 2 Review.
