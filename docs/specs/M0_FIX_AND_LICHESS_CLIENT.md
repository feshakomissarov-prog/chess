## 0. Результат и порядок

**Цель:** получить работающее Windows-приложение Chess Coach, в котором пользователь авторизуется в обычном Lichess-аккаунте, создаёт партию по ссылке для друга, играет **внутри Chess Coach**, получает ходы соперника из Lichess, может играть с Lichess AI, видит часы/историю/результат и сохраняет завершённую партию локально. Одновременно исправить замечания к M0.

Не смешивать все изменения в один неразборчивый коммит. Последовательность:
1. **Блок A: исправить M0** в существующем PR #2, добавить тесты, не сливать.

## 2. Блок B — архитектура и безопасность Lichess

### 2.1. Авторизация

- **OAuth2 Authorization Code + PKCE** для настольного приложения. Авторизация открывается в системном браузере; приложение получает результат через предусмотренный безопасный callback и проверяет `state` и PKCE.
- Использовать **обычный аккаунт человека**, не Bot API. Не просить пароль Lichess.
- Запрашивать минимальные OAuth scopes, нужные конкретным методам: как минимум `board:play`, `challenge:write`; `challenge:read` только при необходимости. Авторизация должна восстанавливаться после перезапуска, если токен действителен, и безопасно сбрасываться при отзыве.
- Хранить секреты в Windows Credential Manager через `keyring` или эквивалентный безопасный системный механизм; не в QSettings/plaintext/.env/git/логах.
- Кнопки **«Подключить Lichess»** и **«Отключить»**, понятные состояния без токена/подключения/ошибки.

### 2.2. Сетевой слой

- Отделить BoardView/GameController от HTTP, OAuth и событий. Сетевой сервер Lichess — источник истины о подтверждённых онлайн-ходах.
- NDJSON stream читать **в фоне**, не блокируя поток Qt. Поддержать `GET /api/stream/event` (уведомления) и `GET /api/board/game/stream/{gameId}` (gameFull, gameState, end, opponentGone).
- **Не открывать несколько глобальных event stream с одним токеном** — они отключают друг друга.
- Переподключение после обрыва, backoff, таймауты, корректное завершение задач при закрытии окна, запрет двойной отправки ходов.
- HTTP ошибки 400/401/403/404/429/5xx — понятные сообщения. При rate-limit соблюдать инструкции Lichess (`429` → пауза минимум минута), не долбить сервер частыми опросами.
- Для тестов — fake transport/записанные NDJSON фикстуры; **автотесты не делают реальные вызовы в Lichess**.

## 3. Блок C — пользовательские сценарии игры

### 3.1. Создание партии по ссылке (главный приоритет)

Пользователь выбирает **«С другом по ссылке»**, цвет (белые/чёрные/случайно), контроль времени: прежде всего **без часов** и **3+2** (можно добавить 10+0, 15+10), casual/rated там, где поддерживается.

- `POST /api/challenge/open`: получить `id`, `url`, `urlWhite`, `urlBlack`.
- Присоединить **самого создателя**, авторизованного в Chess Coach, через `POST /api/challenge/{id}/accept?color=...` и показать ссылку для друга.
- **Важная неопределённость:** полный цикл «авторизованный создатель создал open challenge и самостоятельно принял, друг перешёл по ссылке» документально не проверен реальной игрой. Сначала выполнить самый короткий end-to-end тест, записать фактические HTTP ответы. Если текущий API не позволяет такой порядок — остановить затронутый сценарий, предложить проверяемые альтернативы владельцу; **не выдавать open challenge за работающий сценарий**.
- Не предполагать, что `challenge/open` уже означает старт партии. Дождаться `gameStart` и полного состояния `gameFull`.
- Статусы: создаётся / ожидаем второго игрока / игра началась / отменено / ошибка / истекло.
- Ссылка копируется кнопкой. В приложении нельзя оставлять собственный аккаунт зрителем вместо игрока.
- При наличии опции `rated=true` проверять допустимые комбинации по ответу сервера и фактическим ограничениям; не пытаться обойти запрет.
- Unlimited — **отсутствие шахматных часов**, не перепутать с correspondence с ограничением дней на ход. Для `open` пример официального API возвращает `timeControl.type=unlimited`; но поведение проверить реально.
- Любые **рейтинговые тесты только с явного согласия владельца**, чтобы не менять рейтинг неожиданно.

### 3.2. Игра против конкретного друга

- `POST /api/challenge/{username}` — ввод имени Lichess, вызов по имени.
- Поддержать casual 3+2 и unlimited (спецификация содержит отдельный режим `unlimited`), по возможности rated для допустимого контроля.
- `keepAliveStream` для ожидания ответа (обычный real-time вызов иначе может быстро истечь); принять/отклонить/отменить должны быть корректно отображены.

### 3.3. Игра с компьютером

- `POST /api/challenge/ai`, уровни **1–8**, выбор цвета, без часов или 3+2, если поддерживается.
- **Lichess AI — не локальный Stockfish Chess Coach**; не запускать свой движок для игры или анализа.
- Правильная обработка gameStart/ходов/завершения.

### 3.4. Игра случайным соперником

Вспомогательный сценарий: `POST /api/board/seek` по документированным контролям (rapid/classical/correspondence). **Не делать случайный блиц через Board API**, если он запрещён. Если реализация seek значительно увеличит объём или потребует экспериментировать с рейтинговыми играми, вынести этот сценарий в отдельный этап с записью ограничения; **основной приоритет — друг по ссылке и AI**.

## 4. Игровая доска в онлайн-режиме

- Визуальная основа остаётся `chess-widgets` и существующий `BoardView`.
- Оба способа хода (клик-клик/drag). При локальном MoveIntent проверка шахматных правил, но **не считать онлайн-ход подтверждённым до подтверждения сервера/синхронизации**.
- Получение ходов соперника в реальном времени; синхронность доски, списка SAN, часов (если они существуют), игрока/цвета, статуса.
- **Предход** — только намерение, не меняющее подтверждённую позицию; автоматически отправлять после события хода соперника и новой проверки легальности, без двойных отправок.
- Стрелки/выделения остаются ручными; пользователь может просматривать историю и возвращаться к актуальной позиции. В истории **нельзя** отправить ход из устаревшего состояния.
- Корректно обрабатывать promotion, castling, en passant, мат, пат, ничью, сдачу, истечение времени, abort, зависшее соединение и reconnect.
- После реконнекта запрашивать актуальное состояние и сравнивать с локальным подтверждённым журналом; **не отправлять повторно** неподтверждённый ход без проверки.
- При игре без часов **не показывать фиктивные часы**; соответствующий UI скрыт или «без часов».
- **Строгий Fair Play:** никакой оценки Stockfish/графика/лучших ходов/подсказок GPT во время онлайн-партий с людьми; не выполнять фоновый анализ позиции.
- Кнопки игровой активности должны быть согласованы с фактическими правами и API; опасные/необратимые действия требуют подтверждения.

## 5. Блок D — локальное сохранение

- Сохранять полученные подтверждённые ходы и базовые метаданные партии **по мере поступления**, а не только при закрытии, включая ID Lichess, цвет, соперника, дату, rated/casual, контроль времени и результат.
- Минимальная локальная SQLite-таблица или другой устойчивый формат, совместимый с планируемой библиотекой: предотвращение повторов и дублей после reconnect, возможность экспортировать PGN; без преждевременной сложной «аналитической базы».
- В идеале отдельный лёгкий список завершённых партий с кнопкой «Открыть»; полноценная библиотека с фильтрами остаётся на M4.
- Локальная запись **не должна делать** запросов к облачному GPT и не включает микрофон; голос/Whisper/Stockfish — последующие этапы.
- Если приложение аварийно закрылось, при следующем запуске должно корректно восстанавливать последнюю текущую онлайн-партию (если ещё идёт) или завершать сохранение по данным Lichess.
