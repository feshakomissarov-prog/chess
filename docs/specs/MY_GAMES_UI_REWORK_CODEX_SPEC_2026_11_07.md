## 3. Левый столбец — каталог и навигация

### 3.1 Верхняя поисковая строка

- Видимый placeholder **«Поиск по сопернику, дебюту или дате»**; существующий handler поиска, SQL paging, debounce и generation cancellation сохранить. Текст не должен сбрасываться при выборе/разборе/возврате.
- Справа **«Фильтры»**, суффикс **«(N)» только при реально активных фильтрах**. По клику раскрывает существующую панель с account, opponent, opening/ECO, color, outcome, source, time control, analysis availability, analysis source, period/date, search. Не удалять фильтр даты; не менять смыслы вариантов и связанных SQL queries. Кнопка «Сбросить» внутри панели — сохранить/предусмотреть, если есть фильтры. Открытость не должна неявно изменять выборку.
- Фильтры занимают левый столбец как временная вложенная панель с собственным scroll/collapse, **не добавляют постоянную третью колонку**. Развёрнутые фильтры не должны перекрывать/обрезать правую карточку или закрывать pager.

### 3.2 Закреплённая зона активных игр

- Показывать **только когда сессии реально есть**, отдельный однозначный status «В ИГРЕ», достоверные opponent, цвет, контроль, чей ход при подтверждении, и кнопку **«Продолжить»**.
- Нажатие «Продолжить» → существующая команда открытия/возобновления именно указанного game_id/current account; не перепутать с Review сохранённой партии. Учитывать несколько одновременных active sessions; если N>1 — явно выбрать конкретную, не спрятать остальные.
- Не запускать непроверенный engine, не показывать accuracy, CP, game score graph. Если дата/контроль/соперник не известны — нейтральная подпись; состояние «загружается» без ложного «ваш ход».
- Поле из макета «OpponentName» — **образец**, не реальное имя. Не показывать «В ИГРЕ» в демо для пустого/отключённого аккаунта.

### 3.3 Список завершённых партий

**Каждая строка содержит строго следующие смысловые группы** (возможен перенос на 2 строки при реальной ширине):
1. Слева результат **«Победа» / «Поражение» / «Ничья»** с существующим цветовым акцентом от перспективы аккаунта; текст обязателен, иконка вспомогательная.
2. Имя соперника/AI level из **подтверждённых account/player/PGN полей**, единое в списке, правой карточке и Review. Если невозможно определить — **«Неизвестный соперник»**. Не заменять Stockfish на Lichess AI или наоборот по умолчанию.
3. Свой цвет **«Белыми» / «Чёрными»** (иконка + слово); если невозможно определить — «Цвет неизвестен», никакой догадки по result/white_player.
4. **Моя точность** 0…100% с указанием источника **«Lichess» или «Stockfish»** и корректным статусом coverage; если нет достоверной валидной точности — **«Не оценено»**. Краткий текст можно вынести в отдельную правую область строки.
5. Второстепенная строка: дата/время (с точностью, которую реально знает storage), контроль времени если определён, ECO/название дебюта при наличии. Без выдуманного «3+2» у correspondence/unknown.

**НЕ В СПИСКЕ:** ошибки/зевки/неточности, два отдельных процента accuracy, диаграмма, технический backfill/provenance, PV и длинные формулы.

- Выделение — одна лавандовая рамка/заливка в существующей палитре, как в макете; выбранный item — именно ID игры. Не выбирать другую игру при позднем ответе SQL.
- **Один клик** выбирает и подгружает правую карточку; **двойной клик** допускает уже существующий переход в Review, если он был до изменения, и остаётся эквивалентным явному «Открыть разбор», не становится новой функцией. Клавиши ↑/↓ меняют выбор, Enter открывает Review, Tab проходит кнопки.
- Производительность: сохранить Qt view/delegate + paginated query, **не заменять** всё на тысячи QFrames/QWidgets одновременно; loading/skeleton или placeholder при асинхронном запросе; не выполнять N тяжелых review/SQLite анализов в GUI thread ради каждой отображаемой строки. Для точности списка использовать **пакетный/агрегированный source-aware summary для текущей страницы**, с безопасным deferred loading и cancellation. Если существующий query не содержит accuracy, добавить bounded чтение только для страницы, с тестом 3k+ игр и 1k+ сохранённых анализов.

### 3.4 Пагинация — только под левым списком

- В пределах границ левого каталога один горизонтальный ряд: **[←] [Страница X из Y · N партий] [→]**; отступы и фон соответствуют макету.
- Стрелки действительно переходят на соседнюю страницу текущей выборки, **не меняют** фильтры; блокированы на первой/последней, текущая страница валидирована после изменения фильтра.
- **Глобальный «← Назад» в шапке** — это совсем другая операция (назад по маршрутам), и не должен мигрировать в paginator.
- Если выборка пуста: «По этим фильтрам партий нет» и единый неактивный pager без вводящих в заблуждение «стр. 1 из 0».

## 4. Правая карточка — конкретная партия

Правая панель имеет компактную внутреннюю композицию и **закреплённый низ с действиями**. При 1672×941 всё существенно важное видно **без внешней прокрутки**; на меньшей высоте прокрутка допустима **только внутри содержимого деталей**, footer с «Открыть разбор» остаётся видимым.

### 4.1 Заголовок и метаданные

- Первая строка **«Победа · [имя соперника]»**, цветовая семантика result согласно существующим токенам, без повторного result в нескольких крупных строках.
- Вторая компактная строка: **«♟ Чёрными · 06.11.2026 · 3+2 · A40 Дебют ферзевой пешки»** — **только схема**, в production брать real selected game/account data и форматировать точно. Все meta известны независимо от анализа. Не превращать «неизвестно» в «без часов», если это не доказанный тип игры.
- Одна широкая строка **«Белые [имя] · [1–0 / 0–1 / ½–½] · Чёрные [имя]»**. Если PGN scoreboard не подтверждён, показать нейтральное «Результат уточняется» без придуманного счёта. Выигрыш от перспективы аккаунта должен соответствовать белым/чёрным.
- Если данные после финального save ещё приходят, показать «Метаданные обновляются», обновить этот же game/account/revision без сброса выбранной строки.

### 4.2 Блок двух точностей

Две одинаково оформленные компактные карточки в одной строке:
- **«Моя точность» → 84.0% · Stockfish** (пример);
- **«Точность соперника» → 92.8% · Stockfish** (пример).

В реальности:
- Определять own side по авторитетному account/player/color; opposite только когда он определён. При неизвестной стороне не приписывать цифры «мне», можно показать подписанные «Белые / Чёрные» до выяснения, без фальшивого own.
- Если есть официальная Lichess accuracy и она валидна для соответствующего side, **предпочесть её в краткой строке**; иначе сохранённую локальную accuracy. При одновременно доступных источниках показывать также альтернативу в tooltip/expanded provenance; **не сливать значения из разных алгоритмов в одну цифру**. Если стороны сравниваются по разным источникам, метить источник каждой явно и не позиционировать как одинаковую методику.
- Пусто/частично/недостоверно → **«Не оценено» / «Часть ходов оценена»** с корректным denominator. Не интерпретировать NaN/invalid/partial как имеющуюся точность. 0% только если фактически рассчитанное значение 0, не как fallback.
- Источники серверной готовой аналитики и локального SF сохраняются и не переписывают друг друга.

### 4.3 Ошибки и охват

Компактная таблица, не два дублирующих визуальных блока:
| Показатель | Я | Соперник |
| --- | ---: | ---: |
| Неточности | n | m |
| Ошибки | n | m |
| Зевки | n | m |
| Оценено | n/N | m/M |

**Строгие требования:** над числами понятные заголовки «Я» и «Соперник»; никакой дублированной третьей колонки из автоматически сгенерированного изображения; данные классификации только если анализ реально классифицировал эти ходы; при отсутствии данных — «—», не «0». Охват относится к своей метрике, не выдавать число позиций как число ходов одной стороны; если схема не даёт корректного per-side denominator, показывать одну строку **«Охват графика X/Y позиций»** отдельно вместо ложных n/N по сторонам. Название/источник классификации остаётся доступным. Раздел избыточной информации можно сделать раскрываемым, но **ошибки и зевки должны быть видны в деталях**.

### 4.4 Точность по фазам

Три равных мини-блока (в одну строку при нормальной ширине): **«Дебют», «Миттельшпиль», «Эндшпиль»** с **моей** точностью (и подписью «Моя», если иначе двусмысленно) для каждой фазы. Данные уже предусмотрены в review.local_phase_accuracy; **не выдумывать три цифры из общего %**, не вводить неутверждённую формулу и не считать «фазовую точность Lichess», если фактически это локальный расчёт. При отсутствии фазы/плохом покрытии: «Нет данных». Если среди оценок только частичные, показать origin/coverage и не делать вид, что фаза полная. Будущий переход по фазе в Review допустим только при уже существующем корректном маршруте; никакой новой страницы.

### 4.5 Компактный график оценки

Встраивается **на место существующего compact ReviewGraph** в панели подробностей. **Не менять полный ReviewGraph для аналитического рабочего места**, лучше отдельный rendering policy/compact mode либо безопасный переиспользуемый компонент.

Требования к отрисовке:
- Строго **одна шкала оценки за белых**, X = индекс полуходов по сохранённой PGN, Y = centipawn-equivalent (в шахматных единицах на оси) с нулём посередине; если есть только CP для части партии, прочерк/пропуск по X сохраняется.
- Поверх нулевой горизонтали **светлая/белая полупрозрачная заливка** от нуля до кривой = преимущество белых. Под нулём **темная (но визуально различимая) полупрозрачная заливка** = преимущество чёрных. Цвет **никогда** не определяется стороной владельца. Ось 0 контрастная, линия тонкая непрерывная **только между соседними реально оценёнными полуходами**.
- **Убрать в compact view ВСЕ маркеры каждой точки**: зелёные кружки, красные квадраты, ромбы, треугольники, постоянно видимый текст «за пределом шкалы», цветные пометки ошибок. Полная версия Review сохраняет интерактивные маркеры, CP/Δ, Mate, график для упражнений.
- **Mate — отдельное событие**, не превращать его в fake ±999 centipawns и не соединять через Mate неподтверждённую CP-линию; если нужно пояснение — короткая доступная подпись/tooltip на событии. Обрезание шкалы при extreme value не скрывать без объяснения (узкий tooltip, не огромный текст поверх графика). Пустое место — «Нет сохранённых оценок», не плоская белая линия.
- У графика доступное название «Оценка за белых», источник (Stockfish или Lichess), **«Оценено X/Y позиций»**, реальный номер последнего полухода. В рендере макета надпись «Ход 86» не должна становиться hard-coded путаницей между ходами и полуходами: подписывать реальный unit. Hover/keyboard показывает точную позицию/SAN/score/mate только после safety approval; клик открывает тот же selected ply в Review, как существующий detail_position_requested.
- Без смешения несовместимых source series в одной кривой; выбирать доступный сохранённый источник и явно его указывать. Безопасный redraw на account switch, revoke, stale worker.

Не подменять batch action; manual > background queue per нынешнему §15; check current post-§15 implementation first. На кнопку сразу inline status «Проверяем безопасность / В очереди / Анализируем / Готово / Ошибка/Отменено»; никакого обещания мгновенно завершить engine. Повторный клик не запускает второй процесс |
| «Экспорт PGN» | футер правой панели | существующий экспорт выбранной точной saved PGN линии в файл | не блокировать Qt; выбор папки и отчёт об ошибке; originals unchanged |
| «Заметки» | небольшое «Ещё» либо вторичное действие внутри правой карточки | открыть существующий note editor + «Сохранить» | черновик связан с (game_id, line_revision), не потерять старые заметки/ошибки сохранения |
| «...» | локальная кнопка справа | только вторичные функции: заметки, достоверная «Открыть на Lichess» при существующей проверенной URL, контекст восстановления | никаких пустых/дублирующих пунктов; не открывать чужой URL/токен |
| «Настройки загрузки» | **не на футере** | прежний маршрут в **Настройки → Lichess/загрузка** | существующие autosync/pause опции сохраняются |
| «Обновить одну партию из Lichess» | **не в основном ряду** | исключительно существующий диагностический recovery для конкретной eligible Lichess-записи | account checked; не сбивать global checkpoint, не обходить quotas |
| «Закрыть» старой library | скрытая устаревшая local button | глобальное «Назад» и shell делают её ненужной | не делать вторую обычную кнопку |
| Нажатие графика | правая карточка | открыть тот же game_id + выбранный ply в Review | только при валидных оценках и свежем safety approval |

**Особое требование:** не считать «Открыть разбор» и «Анализ Stockfish» дубликатами. Разбор = открыть уже сохранённый обзор и PGN. SF = создать/продолжить конкретное вычисление после проверки правил. Ручная команда не вправе bypass active human match.

## 7. Адаптивность и доступность

- Базовый визуальный reference **1672×941**, но реальные Windows Qt окна проверять **1280×720, 1360×860, 1120×640**; отдельно scaling **100%, 125%, 150%**. DPI и размеры тестировать реальные, не симулировать одинаковые pixels без devicePixelRatio.
- При достаточной реальной полезной ширине — два столбца. Если sidebar+минимумы левой/правой зоны не помещаются, не сжимать обе колонки до нечитаемости: **master→detail** (список → карточка с явным «К списку»); сохранять game selection/search/pager/scroll и global return-to-game. Не создавать дополнительное модальное Windows окно.
- Правая action row всегда в viewport; на компактных размерах вторичные кнопки могут перейти во второй ряд или в «Ещё», но **Открыть разбор и Анализ Stockfish не исчезают**. Не допускать горизонтальной полосы scroll всей страницы.
- Любой truncation — Qt elided text + доступный полный текст в tooltip/accessible name; tooltips короткие, не на полэкрана. Длинный opponent, русские длинные дебюты, изменившаяся ширина sidebar и длинный статус должны быть тестовыми фикстурами.
- Видимый focus outline, Tab order sidebar→search/filter→list→pager→details/actions; Enter/Space, keyboard screenreader accessible names; результат нельзя передавать одним зелёным/красным цветом.
- В GUI нет hardcoded sample «3313», «84%», «Stockfish level 1», «OpponentName», «сегодня 14:17»; все такие значения приходят из source или явно нейтральных тестовых fixtures.
