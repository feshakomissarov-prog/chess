## U2. Предход сразу после отправки собственного хода — P0
Не блокировать выбор/drag своей фигуры до Lichess ACK. Уже есть optimistic render_board после pending_uci; разделить запрет второго реального POST и разрешение **одного speculative premove** на отображённой позиции. После собственного хода ожидание ACK может занимать >1с, но интерфейс должен сразу принимать premove selection и Esc cancel. Исполнять его только после authoritative confirmation и хода соперника, заново проверив легальность. При definitive rejected move, mismatch, изменении game_id, disconnect, takeback — pending и зависимый premove корректно сбрасываются. При ambiguous POST failure нельзя повторно отправлять ход. Нельзя разрешать действия на неизвестной authoritative стартовой позиции. Никакого engine при live human. Убрать тяжёлые операции с GUI thread. Test delayed ACK 2s: UI позволяет premove до ACK, second POST не появляется до законного состояния; promotion, capture, castling, fail/retry/out-of-order stream, drag/click, latency instrumentation.

## U4. Статистика: понятное разделение
Вместо десятка видимых фильтров и строк-монолитов создать вкладки «Обзор», «Партии», «Дебюты/фазы», «Критические моменты». Дефолт — выбранный Lichess аккаунт, последние 90 дней, кнопка «Всё время». Крупные читаемые summary: W/D/L, число партий, средняя **официальная** точность Lichess n/N, собственные assessed move pairs X/Y, ошибка/партию, ошибки на 100 assessed own moves (при знаменателе 0 => н/д), coverage/source/period. Не смешивать accuracy от движка и Lichess, local accuracy остаётся NULL до настоящей формулы. Партии — постраничная таблица дата/цвет/результат/соперник/ECO/accuracy/errors/coverage, double click паспорт. Дебюты и фазы — компактные таблицы с drilldown, raw internal IDs скрывать. Смешанный аккаунт не превращать в персональный диагноз. Для скриншота 0/465 own pairs одновременно с counts severity проверить SQL source policy; неизвестное не считать нулём ошибок.
