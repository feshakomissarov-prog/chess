## 1. Главное проектное решение

**Не создавать отдельных экранов для каждого события.** Существуют два устойчивых рабочих пространства:
- **GAME** — одна и та же интерактивная доска для активной, локальной и только что завершившейся партии. Меняются только статусы и допустимые кнопки. FOCUS — режим представления того же GAME, не другая шахматная доска.
- **REVIEW** — отдельный уже существующий рабочий разбор законченной партии/PGN с навигацией, доказательной аналитикой и тренировкой. Имеет состояния **без аналитики / обработка / с аналитикой / safety blocked / обучение/вариант**.

**Общая иерархия:** шахматная доска > игроки+часы > история ходов > соответствующие текущему состоянию игровые команды > дополнительные настройки. Выделять перемещения и намерения, а не технические статусы.

## 2. Диагноз трёх скриншотов

1. **GAME:** доска занимает примерно квадрат 528 px в большом окне, при этом справа широкая панель содержит подряд статус, размер доски, блок специальных команд, переход в архив, список ходов, стрелки, пустой «ПРЕДХОД», «Новая партия», Flip, очистку пометок. Сверху два повторяющихся сообщения «Без обычных часов» и длинная кнопка «Режим фокуса» во всю ширину. Активное управление и служебные операции выглядят равнозначными.
2. **FOCUS:** исчезает вся правая панель, но размер доски почти не меняется, большая часть ширины пустует. Подтверждено по source: window.py::_set_focus_mode прячет правый splitter, а _apply_board_size ограничивает доску сохранённым board_target_size (обычно 480) и оставшейся высотой. При фокусе нужно переопределять визуальный максимум, не меняя предпочтение обычного режима.
3. **REVIEW:** слева большая колонка пустой таблицы точности, в центре маленькая доска, справа огромная таблица ходов, снизу график без данных и надписи «Нет сохранённых оценок», снизу три широкие CTA, включая «Разобрать мои ошибки · 0». Технические подписи вроде «Время начала неизвестно» и «Оценка отсутствует» множатся. По source review splitter оставляет левым метрикам ~360–370 px даже без метрик, а график отведён постоянно. Скрин с начальной позицией при 57 ходах САМ ПО СЕБЕ НЕ ДОКАЗЫВАЕТ баг: review может отображать позицию с выбранным полуходом 0; важна явная подпись выбранного хода.

## 3. Цель A — активная онлайн-партия

### Компоновка нормального режима

~~~
┌─────────────────────────── СУЩЕСТВУЮЩИЙ CHESS COACH SHELL ────────────────────────┐
│ Играть / Партия · Opponent · 3+2                 текущая сессия / связь           │
├─────────────────────────────────────────────┬───────────────────────────────────┤
│ [Противник · цвет]            [03:22]         │ ХОДЫ · последняя позиция          │
│ ┌─────────────────────────────────────────┐ │  1. e4       c5                   │
│ │                                         │ │  2. Nf3      d6                  │
│ │            КРУПНАЯ ДОСКА                │ │  3. ...                          │
│ │           АВТОРАСЧЁТ SIZE               │ │                                   │
│ │                                         │ │ [⏮] [◀] [▶] [⏭ к игре]         │
│ └─────────────────────────────────────────┘ │                                   │
│ [Вы · цвет]                  [03:08]         │ УПРАВЛЕНИЕ                         │
│ [⤢ Фокус] [⟳ Перевернуть]                  │ [Предложить ничью] [Возврат хода] │
│                                             │ [Сдаться]                          │
│                                             │ [Входящий ответ: Принять/Отклонить]│
└─────────────────────────────────────────────┴───────────────────────────────────┘
~~~

**Доска:** самая крупная возможная квадратная область в доступной ширине/высоте между игроками, не фиксированный 480/560 при фактических 800 px свободного места. Ориентир desktop — левая часть ~60–70%, правая ~30–40%, при условии минимально читабельных 320–360 px для истории/команд. Вычислять размер по реальному sizeHint/contentsRect и DPI, 8×8 aspect ratio без смещения координат/резких скачков. Сохранённая ручная настройка размеров может существовать, но **по умолчанию адаптивная**; при включении фокуса разрешено временно расшириться сверх ручного normal-size с восстановлением после выхода. Если высота — настоящее ограничение, уменьшать дублирующиеся отступы/заголовки, а не вырезать часы/игровые команды.

**Игроки/часы:** непосредственно над и под доской, именем и реальным цветом; часы крупные и контрастные, только когда есть подтверждённый контроль. Имена одинаково понятны для online/AI/opponent. Если часов НЕТ: **один** неброский факт «∞ Без контроля времени» в строке метаданных/рядом с игроками вместо **двух больших одинаковых строк**; имена обеих сторон сохраняются. Это новая рекомендация, уточняющая прежний UX-GAME-01 — требует согласия владельца. Если часы неизвестны из-за connection/pending: «Проверяем часы», а не якобы «без часов» и не выдуманное 00:00.

**Правый блок** делим на две явные секции:
1. Ходы в формате № / Белые / Чёрные, выделена актуальная или выбранная история; собственный scroll; четыре кнопки истории одной компактной строкой и ясно отличающаяся **«К текущей позиции»**. Просмотр предыдущего хода не позволяет послать неверный ход с исторической позиции. Новый подтверждённый ход корректно отмечается, а board-move intents работают только на latest authoritative board.
2. **Управление партией**: всегда на виду, если поддерживаются для состояния: «Предложить ничью», «Вернуть ход» (AI) / «Предложить возврат хода» (человек), «Сдаться» с подтверждением. Входящие ничья/возврат **первым рядом**, когда есть, с «Принять / Отклонить». «Заявить ничью по правилу» — только если board state это поддерживает. Не прятать игровые команды под «···» ради красоты; disabled с понятной причиной, если нет возможности, и не показывать ложные команды на local.

**Дополнительные функции:** «Перевернуть» — маленькое действие у доски; «Очистить пометки» — вторичное около доски/в компактных настройках доски; изменение размера — компактное меню/настройка, без большого QComboBox справа, по умолчанию «Авто». Переход «Завершённые партии» убрать с игровой командной панели (уже есть главное меню «Мои партии»), «Новая партия» не выглядит доступной во время active human match — доступна через «Играть» с подтверждением/сохранением сессии. Показать краткий session status в одной строке, без буквального «lichess · started» как основного содержимого.

**Предход:** при отсутствии queued premove не занимать целую секцию с заголовком и пустым текстом. Когда premove существует — компактная строка «Предход: [SAN или координаты] [Отменить]» рядом с ходами; Esc и привычный способ отмены сохраняются. Не выводить потенциальный engine-анализ.

| Состояние | Доска/часы | Команды / статус |
| --- | --- | --- |

| Несколько текущих игр | явная текущая game ID / opponent | прежние сессии доступны через Play / global return, не перескакивать сами |

## 4. Цель B — «Режим фокуса»

**Фокус = действительно увеличенная доска, а не лишь скрытая панель.** При включении:
- временно скрыть правую командную колонку и по возможности **свернуть sidebar** (запомнить прежнее состояние, восстановить при выходе), уменьшить несущественную высоту шапки; **пересчитать квадрат доски ПОСЛЕ фактического reflow** в Qt на следующем layout pass;
- доска **увеличивается до min(доступная ширина, доступная высота за вычетом компактных строк игроков/часов и маленького toolbar)**, не зажимается обычным board_target_size; центрирование не создаёт пустую область вместо доски;
- всегда сохранять видимые **реальные часы** (если timed), имена и статус текущего хода; маленькую кнопку «Вернуть панель» всегда можно найти;
- игровые команды не уничтожить: дать компактный **однокликовый «Управление»** (мини-popover/узкая раскрываемая панель с ничьей, возвратом, сдачей и подтверждённым входящим), и при входящем требующем реакции событии показать ненавязчивый indicator; если место допускает, держать микрополосу специальных команд на виду. Фокус доброволен, но не должен делать отказ от ничьей/сдачу недоступными;
- board moves, premoves/cancel, звук, history state, session и Fair Play не сбрасываются; возврат в обычный режим восстанавливает manual board size и sidebar; при resize/DPI не залипать в старых geometry.

**Проверка:** сравнить реальные пиксели/Qt logical размеры board до/после фокуса на 1672×941 и 1280×720. Фокус должен дать **измеримое увеличение при наличии свободного пространства**; если высота ограничивает, предъявить честный geometry report и оптимизировать именно вертикальный occupied-height. Нельзя считать фокус пройденным по одному скриншоту исчезнувшей правой колонки.

## 5. Цель C — завершённая партия на той же доске

**Нормативное решение владельца уже утверждено в UX-GAME-01:**
- никаких popup/overlay, автоматического перехода в Review/архив, новой страницы результата;
- **та же board widget, последняя подтверждённая позиция**, те же имена/статус, часы заморожены по authoritative end, история и её навигация доступны;
- справа **ровно два новых главных действия**: **«Разобрать» и «Вызвать снова»** (для AI логический «Играть ещё с AI»; для local — «Новая локальная партия»). В блоке статус строкой: «Партия завершена · Победа/Ничья/Поражение», без большой карточки результата;
- команды active match (сдаться, ничья, server takeback, premove) исчезают/disabled. Вспомогательные «Экспорт PGN», переворот и пометки — компактно/контекстно, не третья главная CTA;
- Review доступен **только** после подтверждённой корректной terminal line в SQLite и fresh Fair Play gate. Пока ещё сохраняется — честный status и disabled «Разобрать», без потери текущей позиции;
- «Вызвать снова» — новый явный user gesture, не auto-post и не повтор неизвестного POST; human opponent подтверждён, AI создаётся через настоящий AI mode, local запускает новую доску по запросу. Incoming rematch accept/decline только из подтверждённого server event.

**Важно для реализации:** current PR44 уже использует window.py::_show_result → game_page и саму финальную доску; **не переписывать это заново**. Разбирать переход на новый GameReviewWorkspace следует как отдельный навигационный шаг. Если фокус был включён при завершении, показать два действия внутри доступного компактного фокус-панельного controls или явно вернуть правую панель с сохранением последней позиции — owner choice при макете.

## 6. Цель D — локальная свободная доска

- board крупная, строка «Свободная доска · ходы за обе стороны», история+навигация как в GAME; **не показывать** network status controls, resignation/draw/takeback from Lichess, AI level/clock source, friend invite;
- доступные действия: **«Отменить последний ход»**, «Перевернуть», «Очистить пометки», «Новая свободная доска» (с подтверждением при несохранённой линии); локальная история и экспорт PGN, если реально поддерживается, сохраняются;
- «Анализировать позицию Stockfish» — существующая **отдельная учебная/локальная возможность**, но показывать как вторичный явно запускаемый инструмент и только после fresh Fair Play preflight; отключение/ошибка доступны, не запускать при открытии. Если есть active human Lichess match либо безопасность неизвестна, не показывать eval/arrow/PV.
- Не выводить отдельную «Тренировку предходов» в UI; код для тестов может сохраняться. Игровой GUI не становится редактором FEN/дебютным инструментом; это отдельный Анализ.

## 7. Цель E — Review: разбор открытой партии

### REVIEW без данных Stockfish / Lichess

**Главная проблема скриншота 3:** 360 px пустой левой колонки и график без содержимого зрительно отнимают площадь у доски.

**Предлагаемая перестройка:**
- вверху компактная строка «[соперник] · результат · дата/дебют (если есть)» + source-aware Back («К игре» с завершённой доски; «К партиям» из архива; «К анализу» из импорта) и вторичный «Экспорт PGN»;
- широкое центральное содержание **2 колонки**: слева максимально крупная доска; справа **ходы** (scroll + навигация) и небольшой status/selected move. Левые табличные показатели, evaluation bar и полноценный chart **НЕ резервируют пустую постоянную площадь**, пока нет валидных данных/допуска;
- под доступными ходами/в боковой карточке одна понятная строка **«Оценок нет / Анализ не выполнялся»**, основная action **«Проанализировать Stockfish»**, только для finished game+известный game_id и после safety. Не отображать огромную неактивную кнопку «Разобрать мои ошибки · 0» как primary; нет кандидатов — нейтральный текст «Пока нет проверенных ошибок для тренировки»;
- Lichess official accuracy может существовать **без** per-position eval graph: показывать источниковую точность, если есть; не рисовать фальшивый график. Link «Открыть на Lichess» — явно внешняя ручная опция, вторично и только с проверенным source_game_id, НЕ кнопка cloud-analysis API.

### REVIEW с валидным анализом

**Все ниже — только при fresh safety approved.**
- доска остаётся главным объектом слева; справа постоянно видимая история ходов (обязательно), **под** ней компактное описание выбранного полухода / eval / PV, без выдачи предположений за доказанные «причины» ошибок;
- **аналитика по запросу:** сводные показатели «Я / Соперник» точность+источник, неточности/ошибки/зевки, охват и фазы в **раскрываемом боковом блоке**, не вечной отдельной третьей колонке 360 px. Учитывать provisional local phase_accuracy и official Lichess whole game accuracy: не объединять в одну фальшивую цифру. Всегда null vs true zero.
- **график** — компактный обзор преимущества (светлая область за белых выше нуля, тёмная за чёрных ниже) под доской или в резайзируемой панели, **только если есть оценки**. Должен сохранять интерактивность выбора полухода и при необходимости **опциональные маркеры/дельту** полного Review, но дефолт без россыпи символов в каждом ходе, как обсуждали для списка партий. При недостатке высоты — переключатель «Показать график»/свёртка, не обрезать доску и ходы. Не рисовать график при missing data и не занимать 150 px пустотой.
- **ошибки/тренировка:** «Разобрать мои ошибки (N)» доступна только если N>0 проверенных eligible candidates и безопасность подтверждена. Отдельные «Предыдущая/Следующая ошибка», объяснение, учебные подсказки появляются только в контексте размеченной ошибки. Без анализа — сначала Stockfish, **не** псевдо-активная тренировка.
- вторичные действия: «Экспорт PGN»; advanced «События», «Заметки» и временный вариант позиции (существующий ephemeral study) как раскрываемые режимы, не резидентные огромные панели. Исходная PGN/revision остаётся нетронутой при эпизодическом исследовании.
- источник оценок, coverage, depth/phase и точность всегда проверены и подписаны; CP/Δ не путать с качеством отдельного хода. Сохранить AdvantageBar рядом с доской по состоянию, не показывать при нет анализа/safety blocked.
- старт анализа показывает «проверяем Fair Play → задача в очереди → анализируем → данные сохранены / ошибка / отмена», без обещания мгновенного завершения; manual single-game priority по существующему background coordinator, no duplicate jobs.

### REVIEW blocked / pending / import / training

- **Safety unknown/active human:** оставить PGN/доску/ходы только в допустимой части, **скрыть ВСЕ** оценки, график, подсказки, классификацию, точность, accessibility/tooltip/chart cache, PV и анализ-CTA до fresh check. Скрытие UI, а не просто disable button.
- **Review из завершённой игры, My Games, PGN/FEN:** source-aware return target и сохранение selected ply/скролла/состояния списка; внешняя PGN может не иметь Lichess URL, user color или real result — не угадывать.
- **Training mode по своим ошибкам:** временно switch review layout на «задача на доске + условие + ввод своего хода + Проверить / Подсказка / Пропустить / Следующая / Повторить / Вернуться к разбору», данные от verified candidate, no auto hints. Не делать второй независимый тренировочный движок.
- **Ephemeral study:** показать конкретный факт, что ход/вариант временный, кнопки undo/reset branch, baseline actual PGN не менять. Не включать в активную human игру.

## 8. Переходы и ownership навигации

~~~
Играть → режим/старт → [GAME active]
                        ↔ Focus (тот же GAME, те же ходы)
                        ↓ authoritative finish
                     [GAME finished: та же доска]
                       ├─ Разобрать → REVIEW (без оценок / с оценками)
                       │                 ├─ Stockfish (явно и безопасно)
                       │                 ├─ график и навигация хода
                       │                 └─ тренировка из подтверждённых ошибок
                       └─ Вызвать снова → новый verified challenge

Мои партии → выбранная игра → REVIEW → Вернуться к списку с прежним scroll
Анализ → PGN/FEN → REVIEW/исследование → Вернуться в Анализ
Свободная доска → GAME local → безопасная явная учебная оценка/экспорт
~~~

**Два разных «Назад» не должны путать:** глобальный history back остаётся; кнопка внутри REVIEW имеет смысл **вернуться к источнику**, а не всегда «К партиям». Источник открытия сохраняется в existing WorkspaceNavigator/review context. Прямые ссылки from Home/My Games/Finished game должны быть source-correct. Возврат в активную Lichess сессию не сбрасывает board/clock/history.

## 9. Геометрия, accessibility и измеримые цели

- Один основной квадрат board, Qt chess-widgets BoardView, натуральные изображения фигур и цвета клеток **не менять**; UI-тема приложения как сейчас, без палитрового редизайна.
- Desktop ориентиры: при 1672×941 board в GAME target максимально доступной высоты, рядом история/команды min около 320–360 logical px; в REVIEW board повышает доступную площадь за счёт ликвидации пустой третьей колонки. Конкретные px — после измерения native Qt, не жёсткий макет.
- Тесты 1920×1080, 1672×941, 1366×768, 1280×720, 1120×640, Windows DPI 100/125/150%; focus off/on, sidebar collapsed/expanded, game with/without clocks, 15+ moves, very long names, reconnect, incoming offer, finished pending save, Review no-data and analyzed.
- Не допускать, чтобы board растягивалась непропорционально, перекрывала нижние часы, история съедала всю высоту, а main CTA была за границей окна. Минимальная нажатная область touch-like 32–40 logical px, keyboard focus visible, accessible name. Не только PNG — hit test по QRect.
- Измерить board square, available rectangle и занятую controls высоту до/после Focus. Если есть запас места, доска обязана стать больше, иначе report/no-go.
- В одном кадре не показывать 2–3 одинаковых «Без обычных часов», 3 дублирующих Back и большие пустые stats/chart boxes. Во время live human — никакого engine helper.
- Принцип минимальных изменений: тот же MainWindow/game_page/board/sessions/ReviewWorkspace, тот же SQLite/PGN/Qt и LichessService. Пересобрать layout+state-driven widget visibility, не писать новую игру.
