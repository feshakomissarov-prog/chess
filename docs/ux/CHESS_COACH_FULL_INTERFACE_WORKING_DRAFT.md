## 1. Принципы UX и границы

1. **Одно Windows-окно; вкладки / страницы внутри**, диалоговые окна только для подтверждения необратимого действия, выбора файла, аутентификации/специальных настроек. Переходы не плодят floating windows; Back возвращает туда же с сохранением фильтров/scroll selection.
2. **Одна левая навигация** на всех рабочих страницах. В игре/review может схлопываться в узкую колонку; статус аккаунта Lichess виден всегда, disconnected/manual/offline обозначены текстом. Если есть активная игра, «Вернуться к партии» заметна в header, но не заменяет sidebar.
3. **Нет global page scroll для Главной и Моих партий**. Рабочая область использует доступную высоту между application header/footer; только list center scroll в каталоге. Справа фильтры через секции/раскрытия/поиск, без обязательного второго скролла на целевом ноутбуке; при нехватке высоты — переключаемые compact фильтры через overlay/drawer вместо невидимых кнопок. На других страницах допустим локальный scroll внутри таблиц, ходов, урока и списка задач.
4. **Иерархия действий:** одна ясная primary action на карточку / экран, 1–2 secondary и второстепенные в «···». Не показывать одновременно десяток одинаковых кнопок. Основной клик по карточке предсказуем: показать подробности или открыть явно указанное workspace; не менять смысл между похожими карточками.
5. **Отображать источник и полноту**, особенно official Lichess accuracy vs Stockfish, метрики с denominators (решения 45/57 ≠ позиции 115/115), неизвестное = «Нет данных», 0 ≠ n/d. Маты не заменять cp. Для дебюта: русское название из проверенного локального словаря/сопоставления; при отсутствии корректного перевода показывать официальное имя/ECO и «название не переведено», а не машинную галлюцинацию.
6. **Fair Play fail-closed:** в human live Lichess games ни eval/PV/hints/производной от engine диагностики. Активная карточка показывает только разрешённые статус/ход/часы/соперника и действия игры. Review или training после полного свежего preflight; нельзя «подсветить ошибку» через home card во время игры с человеком.
7. **Без лишних модальных всплытий** при обычной фоновой синхронизации; status+source+count+pause в «Фоновые операции» и маленький индикатор. Текстовые empty/loading/error/retry состояния. Не внушать пользователю, что server Lichess в ответе уже посчитал то, чего там нет.
8. **Фокус на ноутбуке** Windows ≈1366×768 (4 cores/8GB/SSD); проверка 1280×720, 1366×768, 1920×1080 и системный DPI. Размеры flex/Qt layouts, не fixed-height до краёв. Тёмный, понятный, минималистичный стиль, цвет не единственный индикатор. Часы и игровые controls имеют приоритет над любой статистикой.
9. Данные, модальность, фильтры и события не должны создавать второй источник истины между pages: одна партия/viewer, один игровой live session, один queue-state, один settings-store. Будущее «Обучение» вызывает существующий PuzzleSession / review, не копирует их алгоритмы.
10. Не превращать будущие функции в кнопки, которые не работают. В публичной навигации текущего релиза доступны только работающие возможности; для будущих — осмысленный design резерв, отдельная спецификация и статус «в разработке» только после согласования.

## 2. Глобальная оболочка и меню — УТВЕРЖДЕНО

**Рекомендуемый постоянный sidebar:**
- Главное / дом.
- Играть / партии онлайн, AI или свободная доска.
- Мои партии / архив, активные, поиск, синхронизация и управление результатами.
- Анализ / завершённые партии, позиции, массовый анализ, исследование дебютов (позже).
- Обучение / начальный экран, задачи, темы, план, репертуар, повторение, персональный тренер.
- Прогресс / статистика по игре, задачам, подтверждённому освоению.
- Разделитель; Настройки и «О программе/диагностика» внизу.
- В header/sidebar профиле: имя выбранного Lichess-аккаунта и состояние подключения, offline/manual, действующая игра/«Вернуться к партии», один ненавязчивый глобальный статус фоновой активности.

**Почему не сливать «Мои партии» с «Анализом»:** в первом управляем сохранёнными данными и находкой исходной партии, во втором проводим вычислительное исследование. Анализ из карточки партии открывается **тем же** разборщиком в аналитическом workspace с выбранной партией. Анализ может начинаться без конкретной партии (FEN/позиция) и работать с многими партиями.

**Почему объединить «Задачи» и «Обучение»:** задачи — одна из практик обучающего цикла (диагноз → объяснение → упражнение → новая позиция → проверка удержания). Внутри «Обучения» первое действие «Решить задачи» доступно одним нажатием; на главной есть прямой CTA «Решить». Если пользователь в пилоте часто решает задачи и считает их самостоятельным основным режимом, можно вернуть 7-й top-level без изменения внутреннего Puzzle workspace — решение не окончательное.

**Активная партия** не является top-level разделом: это persistent state/session, кнопка возврата + статус/часы в header, отдельный full-content workspace, который сохраняет сессию при обычной навигации (не уничтожать при смене вкладок). Действие «Сдаться» в live workspace только с подтверждением.

## 3. ГЛАВНАЯ — УТВЕРЖДЕНО: четыре области, без общей прокрутки

**Область 1 — постоянное меню:** левая навигация глобального shell (не дублируется на каждой странице); профиль и состояние Lichess. На главной остаётся визуальный обзор с выбранной «Главной».

**Область 2 — мой прогресс:** не большая бухгалтерская таблица, а 1 мини-график + 2–3 лаконичных KPI. Первоначальный кандидат — **число ошибок на 100 сравнимых собственных решений по последним завершённым/оценённым партиям**, с графиком по партиям/неделям и подписью покрытия \`N решений / M завершённых партий\`. Альтернатива после согласования — «число партий и ошибки за 7/30 дней» с графиком без ложного процента. Не смешивать bullet/blitz/classical, локальный и официальный accuracy без явной фильтрации; не приписывать улучшение при низком n. Один CTA «Весь прогресс».

**Область 3 — следующее занятие:** ровно одно рекомендованное **доступное** действие (либо «Продолжить упражнение», либо «Повторить ошибку из завершённой партии», либо «Решить задачи Lichess»). Рекомендация «для тебя» доступна только при подтверждённых источниках; пока персональной модели нет — нейтральное «Практика: задачи Lichess», без «мы знаем, что ты слаб в X». Действия «Начать/Продолжить» и «Другие занятия». Не делать карточку бесконечной лентой.

**Область 4 — последние партии:** 3 компактные карточки: дата/время; соперник/AI; источник; результат из перспективы игрока; цвет; контроль; ECO/дебют по-русски при проверенном mapping; небольшие counts хорошо/неточности/ошибки/зевки **с знаменателем/источником**. Primary card click → «Детали партии»; contextual «Открыть»/«Разобрать»; состояние «данных нет» не выглядит как ноль ошибок. Если нет завершённых партий — CTA импортировать/сыграть; а если активная партия — отдельный global return banner (не вытеснять все три завершённые).

**Размеры и адаптация:** sidebar фиксированного разумного диапазона, в content области колонка «прогресс + занятие» и колонка «последние партии». На 1280×720 убрать второстепенные пояснения/миниатюры, но оставить 4 смысловых блока, без scroll внешней страницы; на ещё меньшей высоте явно определён min supported geometry и корректный compact режим вместо обрезания. Не фиксировать 4 равные площади, главная — dashboard, не набор пустых прямоугольников.

## 4. ИГРАТЬ — УТВЕРЖДЕНО: одна внутренняя страница создания партии

**Рекомендуемая структура:** ясный заголовок «Новая партия»; основное поле «С кем?» radio/segmented group, далее контекстные параметры, снизу один большой primary «Создать партию»/«Открыть доску»; второстепенное «Назад». После выбора режима поля не прыгают хаотично и не сбрасывают уже введённые значения без оснований.

**Режимы:** Lichess AI (уровни 1–8, цвет, контроль), друг по ссылке (цвет, контроль, rated/casual если доступен), соперник по нику (ник, цвет, контроль и поддерживаемые условия), **свободная локальная доска** отдельно от «играть против локального Stockfish», который НЕ обещаем пока реализован. Возможность «без часов» только для тех режимов, где API это допускает; корректная валидация при incompatible rated/time.
 
**Контроль:** популярные preset 3+2, 5+0, 10+0, 15+10 (уточнить доступность по Lichess), «Без часов» там, где возможно, «Свой» (минуты и инкремент) с validation. Последний безопасный выбор сохранять как preference, не автоматически начинать матч. Не делать отдельное выпадающее меню для каждой настройки.

**В состоянии создания:** spinner/«Ожидаем Lichess», отмена challenge при наличии документированного способа, ссылка другу copy/открыть; повторное нажатие не создаёт duplicate challenge; при 401/429 показать доступный статус и позволить возврат без зависания; после подтверждённого gameFull перейти на live workspace, не рисовать придуманные часы.

**Карточка режима:** название, одна строка объяснения, маленькая иконка; выбранная строка явно выделяется. Проверка соединения Lichess и будущих ограничений при построении UI, не после «Начать».

## 5. ИГРОВОЙ ЭКРАН — УТВЕРЖДЁННАЯ КОНЦЕПЦИЯ, детали в UX-B1

**Desktop layout:** доска — главное (сохраняет квадратную форму), **часы соперника над, свои под доской**, большие читаемые, источник server+monotonic interpolation с reconnection placeholder; справа список ходов и компактные статусы контроля/имён. Внизу или справа действия текущего режима: «Назад в главное» (не закрывая игру), «Сдаться» (подтверждение), «Предложить ничью» / согласиться / отклонить, «Отменить приглашение» до игры; premove/отмена premove; mute.
 
**Offline/free board:** разрешённые takeback/flip/set up/clear/PGN, никакого сетевого статуса как live. Для live AI — только то, что разрешает Lichess; для **human live** скрыть оценки/PV/ошибки/hints, графики и тренера. При reconnect баннер «Переподключение…» с сохранением authority часов и запрещённой автоматической аналитикой. По finish → экран результата с «Разобрать», «Повторить», «Все партии», «Экспорт PGN». Не перекрывать доску навигацией.

## 6. МОИ ПАРТИИ — УТВЕРЖДЕНО: 1 сводка / 2 список / 3 фильтры

**Правило высоты:** полная страница не скроллится. Заголовок+верхняя панель 1 имеют фиксированную компактную высоту, области 2/3 делят оставшуюся. Скролл **только в списке 2**. На узких экранах фильтры 3 превращаются в collapsible drawer поверх области 2, открываемый «Фильтры (N)», и не требуют глобального scroll. Состояние фильтра и scroll сохраняется при открытии/закрытии подробностей партии.

### Область 1: статус архива и анализа

Вместо одного общего «проанализировано» показывать **разные знаменатели** и источник:
- «Партий всего» (все локальные/импортированные; active/finished отдельно) и «Идут сейчас X»;
- «С оценками Lichess: X/Y завершённых»; «С локальным анализом Stockfish: A/B завершённых»; «С официальной точностью Lichess: M/N» — не объединять оценки и official accuracy;
- «Фоновые операции»: синхронизация партий / серверных оценок / локального анализа (если явно запущен), status queued/running/paused/429/error/complete, source, checked X/Y, last check and next check, короткая progress bar только при реальном известном total;
- действия «Синхронизировать», «Фоновые операции» (expand inspector + пауза/продолжить) и «Настройки загрузки». **Не** инициировать массовый Stockfish автоматически по входу.

### Область 2: карточки партий

**Активные партии всегда наверху** сортировки по статусу независимо от фильтра дат; они выглядят иначе (тёплая accent полоса + текст «В ИГРЕ» и время/чей ход, не только цвет). Если активных много, компактно закрепить первые 1–3 и дать «Все активные (N)» в пределах того же списка. Никогда не показывать engine/accuracy/classification для live human game. Клик по активной карточке → **вернуться на живую доску**, не открыть анализ.

**Завершённая карточка** (в пределах списка):
- строка 1: «Победа / Поражение / Ничья» из перспективы владельца, имя соперника / «Lichess AI · уровень N», дата;
- строка 2: цвет фигур, контроль \`3+2\`, результат, русский дебют + ECO (если trustworthy mapping), источник игры;
- строка 3: «Хороших X · неточностей Y · ошибок Z · зевков B» с ясным источником и знаменателем или «Анализа пока нет»;
- справа малое «Подробнее» / контекстное меню; выбор строки не запускает engine.
- fallback: ambiguous/unfinished import, AI, no opponent, no opening, no source data; не терять дату и score. Ограничить высоту/текст, ellipsis + tooltip, без вертикально огромных карточек.

**По клику на завершённую партию открывать не новое OS окно, а contextual detail drawer / внутреннюю страницу справа/поверх списка**. При ограниченной ширине — отдельный внутрисистемный экран «Партия / Назад к списку» с сохранёнными фильтрами и scroll. Это легче, чем модальные QDialog, и уменьшает потерю контекста.

**Карточка деталей партии:** header игроки/аватары текстовые, цвет/result/дата/control/источник; дебют по-русски/ECO; маленькая read-only доска на интересном/последнем безопасном кадре или последней позиции (без engine hints до preflight); score/source/coverage; мини-график **только после разрешения Fair Play** и если оценки есть; полный подробный review живёт в отдельном workspace. Primary «Открыть партию»; secondary «Разобрать» (с preflight), «Тренировать ошибки» (если источник и разрешение), «Экспорт PGN» и «Открыть на Lichess» (if valid gameId); advanced «Повторно проанализировать» ведёт в Анализ/Очередь, не запускает автоматически. Для active нет detail analysis.

### Детальная карточка — УТВЕРЖДЕНО и дополнено владельцем

При клике по завершённой партии должен открываться **внутренний подробный просмотр с компактным графиком оценки по всей игре** — возможность сразу понять динамику, не заходя в полноценный разбор. Он обязателен при наличии достоверных разрешённых данных; на live human game и при неуспешном Fair Play preflight оценочный график и ошибки скрыты. Источник Lichess/Stockfish, неполнота, перспектива, матовые маркеры и поведение при отсутствии оценок — по [UX-B1 §D4](UX_APPROVED_BASELINE_V1.md). Возврат сохраняет список и фильтры. Никакого автоматического старта Stockfish.

### Область 3: фильтры

Видимые сверху \`Поиск по сопернику/партии/дебюту\`, chips \`Все · Активные · Завершённые\`, \`Сбросить (N)\`. Далее раскрываемые группы: временной период, цвет, результат, контроль, соперник/AI, источник, ECO/дебют, «есть Lichess accuracy», «есть local Stockfish», «нужен анализ»; значения с количеством в локальной базе, если доступны дёшево. Не выводить все селекты раскрытыми по умолчанию; правая панель читаема. Статус активных игр не должен пропасть из-за silent default filter; если явный фильтр исключает active, показать «активные скрыты фильтром» и global Return to game остаётся доступным.

**Продуктовый риск:** 3300+ игр → не создавать 3300 QWidget сразу; page/virtualized model (QListView/QAbstractItemModel или bounded page), сортировки и фильтры с SQL индексацией; UI scroll внутри list only. Без жёсткого performance SLA сейчас. Background refresh обновляет selected card и counters по revision без сброса filter/scroll.

## 7. АНАЛИЗ — УТВЕРЖДЁН: Вариант B, детали в UX-A2

**Принято:** вариант B из [истории сравнения](ANALYSIS_WORKSPACE_DESIGN_OPTIONS.md), требования по источникам и обоим видам оценки в [UX-A2](UX_ANALYSIS_APPROVED_V2.md). Ни OCR, ни отдельной большой карточки FEN. Схемы/поля подфункции «Подготовка к сопернику» — дальняя будущая работа.

**Landing:** компактные actionable модули или tabs. Целевые группы:
1. **Разбор партии:** выбор из каталога (или импорт PGN), board+move list+graph+two-sided metrics+critical moves; engine only after safety preflight, не дублируем "Мои партии". Путь «Мои партии → Разобрать» открывает этот же экран, выбранную партию.
2. **Анализ позиции:** доска/FEN, расстановка фигур, история линий, сохранение локальной позиции (будущая функция), запуск verified Stockfish по разрешению, PV/cp/mate с source/time/depth. Режим изучения не подключается к активному human online game; запрет position hints сохраняется.
3. **Массовый анализ / Очередь:** создание/обзор, выбор партий через фильтр/список, пресеты/custom nodes от 1 млн и выше в согласованных лимитах, progress queued/running/paused/error/completed, resume с исходными UCI params, отмена и global resource/admission policy. **В архиве только status и «Управление анализом» deep link сюда**; одна и та же очередь, не две копии.
4. **Исследование дебютов — концептуально согласовано** (позже): board explorer по ECO/позициям, частота собственных вариантов, переходы, сверенные движком ресурсы; аналитический инструмент отличается от **«Мой репертуар» в Обучении**, где запоминаем и практикуем свои линии. Пока нет проверенного source/тренажёра — не рисовать готовую пустую кнопку.

**Экран разбора партии**: слева доска + управление полуходами, справа tab Ходы / Ошибки / Варианты / Статистика, снизу график cp/mate, в header score quality source, безопасные controls, экспорт, «Добавить ошибку в тренировки» только при наличии evidence. Темы дебюта/миттеля/эндшпиля — содержание разбора и возможные filters, не 3 независимых analytics engine.

## 8. ОБУЧЕНИЕ — УТВЕРЖДЁННЫЙ единый центр с Задачами (детальная сетка позднее)

**Landing / Сегодня:** одно первичное действие «Продолжить [задачи/тема/репертуар]»; под ним учебный план с ближайшими 1–3 шагами, актуальные задания и краткий источник рекомендации/уверенность. Если персональная модель пока не готова, показывать нейтральные задачи Lichess и доступные сохранённые позиции, **не выдумывать персональную диагностику**.

**Внутренняя навигация:** Сегодня / План / Задачи / Темы / Дебютный репертуар / Повторение / Тренер (последние 3 либо будущие). Не создавать пустых tabs сейчас: показывать только реализованные элементы, будущие — в проектной документации.

- **Задачи:** вкладки доступные Lichess / ошибки собственных завершённых партий / повторение / мои наборы (будущее); решатель = board + условие/таймер если задан + ввод хода + проверка ответа + история результатов, без спойлеров до решения. Источник задачи и наличие права puzzle:read обозначить; история попыток Lichess не то же самое, что получение свежих задач по API, не обещать несуществующий endpoint.
- **Учебный план:** «что изучать / почему / какое доказательство / сколько попыток / следующий шаг»; ближайшая session card и кнопка «Начать». Пользователь может выбрать тему вручную, не обязан следовать рекомендациям.
- **Шахматные темы:** каталог тактика/дебютные принципы/структуры/миттель/эндшпиль/расчёт/решения, фильтр сложности/состояния, урок: формулировка принципа → демонстрация на доске → контрпример → самостоятельное решение → проверка. Не считать 263 темы готовыми курсами.
- **Дебютный репертуар** (будущее): мои белыми/чёрными, варианты и планы, дерево, контроль повторений; learning mechanics, а не просто статистика ECO. Explorer из «Анализ» открывается отсюда по deep link.
- **Повторения:** ожидающие позиции/интервалы, завершение, ошибок/пропусков и source; не начислять progress без реальных попыток.
- **Тренер GPT** (будущее): объясняет проверенные шахматные факты и учит, но не угадывает психологический мотив хода; голос после содержательной версии, no live-human hints.

**Сложность:** «Обучение» содержит **оперативный краткий прогресс занятий** (осталось 2 упражнения, прошлый урок), но вся история, статистика и сравнительная динамика живут в «Прогрессе».

## 9. ПРОГРЕСС — УТВЕРЖДЁННАЯ концепция, будущие поля настраиваемы

**Верхние tabs:** Обзор / Мои партии / Ошибки и фазы / Дебютный профиль / Задачи / Компетенции (будущее) / Периоды. Логика фильтров: 7/30/90/все, Lichess vs local games, time control, color/source, analyzed coverage, comparison periods. Не делать «Elo» на основании Stockfish без официального source/методики.

**Карточки:** сыграно X, результат W/D/L, доступный рейтинг Lichess (только source+category, если есть), доля ошибок на 100 оценённых собственных решений с n/N и сравнимой когортой, official accuracy Lichess только при наличии, отдельные Stockfish metrics, часы/контроль при наличии, solved puzzles and topic checks. Graph trending with confidence/coverage, no fake extrapolation from 1 game.

**Учебный профиль** будущий: дебют / миттель / эндшпиль и сильные/слабые стороны показывать только по наблюдаемым сигналам с источниками/объёмом; «Слабая тактика» не выводить из единственного зевка. CTA «Тренировать» ведёт в уже существующий соответствующий exercise, а не копирует решатель.

**Что НЕ здесь:** длинный урок, тренажёр, запуск целой партии. Статистика может предлагать следующий шаг, но выполнение — в соответствующем workspace.

## 10. НАСТРОЙКИ — УТВЕРЖДЕНЫ вкладки и настройки

**Страница внутри приложения**, а не гигантский QDialog. Внутренние tabs: Общие/Внешний вид; Доска и управление; Звуки; Stockfish и анализ (path/test/install/threads/hash/nodes); Lichess аккаунт и авторизация (без показа токенов); Фоновые операции и лимиты синхронизации; Хранилище/резервная копия/диагностика/о программе.

Save/Cancel semantics явные, важные системные операции (disconnect/revoke/delete local data) отдельно подтверждаются. Встроенные controls доступны с клавиатуры/скролла только в контенте длинной вкладки; сохранить прошлые QSettings keys и креденшалы. Status Lichess и background worker как read-only summary; нельзя отключать Fair Play. Кнопка «Проверить Stockfish» не запускает массовый анализ.

## 11. Универсальная анатомия карточек, drawer и пустых состояний

**Карточка = идентичность → статус/контекст → 1–2 осмысленные метрики → primary action → опциональные secondary.** Стабильная высота и alignment в списках; avatar/icon optional, без длинного текста от ChatGPT на home. Цвет помогает, но статус также текст/иконка. Величины с единицами, source/coverage; если данные частичны — «X/Y оценённых». Внутренние scroll only при законной необходимости.

**Типы**: active game (вернуться к доске), finished game (подробнее), sync/job (status and pause), lesson recommendation (продолжить), puzzle collection (начать), learning topic (открыть), KPI/trend (подробный прогресс), Stockfish batch job (пауза/возобновить). Для каждой — title/description/action/state loading/empty/error/disabled. Одно логическое действие имеет один owner, даже если ссылка на него встречается в нескольких местах.

**Детальный просмотр партии (drawer):** не реальный анализатор; короткая статистика, мини-доска, origin/cp-coverage если есть, «Открыть» (простой viewer), «Разобрать» (через safety), «PGN», «Тренировать ошибки» (при наличии), «Lichess» (confirmed URL). Продолжительность/дата/цвет/AI level/ECO; close возвращает тот же scroll+filter.

**Ошибки и крайние случаи:** disconnected/syncing/no-server-data/partial analysis/429/backfill paused/multi-account/no tasks/invalid PGN/finished vs active; каждая страница должна уметь сообщить, что можно сделать сейчас, а не просто показать н/д или пустой прямоугольник. Не инициировать автоматический analysis при просмотре карточки.

## 12. UX-связи и переходы без дублирования

| Откуда | Действие | Куда |
|---|---|---|
| Главная / последняя партия | Подробнее | Мои партии / детальная карточка |
| Главная / рекомендация | Решить/Продолжить | Обучение / конкретная задача или урок |
| Играть / «Создать» | подтверждено Lichess/local | Игровой workspace |
| Глобальный статус активной | Вернуться к партии | Игровой workspace |
| Мои партии / завершённая | Разобрать | Анализ / конкретная партия |
| Мои партии / сводка анализа | Управление очередью | Анализ / Массовый |
| Анализ / подтверждённая ошибка | Тренировать | Обучение / задачи на своих ошибках |
| Прогресс / слабая тема при достаточных данных | Изучить | Обучение / соответствующая тема |
| Обучение / репертуар | Исследовать позицию | Анализ / Позиция / Дебют explorer |
| Настройки / фоновая активность | Подробности | Глобальный inspector / Фоновые операции |

История навигации должна включать selected account, game_id, tab, filters, scroll offset, но не содержать токены/PGN в URL. Возврат из детали → ровно в предыдущий контекст. В live human game любые переходы не должны раскрывать сохранённые подсказки/движок.

## 13. Открытые вопросы — только ещё НЕ утверждённое

**Окончательно согласовано:** 6 верхних рабочих разделов; «Мои партии» отдельно от «Анализа»; задачи внутри «Обучения»; отдельный «Прогресс»; все четыре блока Главной; страница создания игры; трёхзонный каталог и подробности завершённой партии **с графиком**; структура обучения, прогресса, игры и настроек. Источник истины — [UX_APPROVED_BASELINE_V1.md](UX_APPROVED_BASELINE_V1.md).

**Остаётся обсудить:**

**A. Анализ / «Разбор партии» — ЗАКРЫТО.** Источники из архива, внешний PGN file/paste, FEN/editor; одна шахматная доска, без второго каталога. [UX-A2](UX_ANALYSIS_APPROVED_V2.md).

**B. Анализ / «Анализ позиции» — ЗАКРЫТО.** Отдельной большой кнопки нет; FEN и расстановка фигур внутри общего разбора. [UX-A2](UX_ANALYSIS_APPROVED_V2.md).

**C. Анализ landing — УТВЕРЖДЁН** 3 карточки; большой блок дебютов согласован концептуально, **его глубокая детализация всё ещё открыта**, включая далёкую подготовку к сопернику. [UX-A2](UX_ANALYSIS_APPROVED_V2.md).

**D. Обучение / Прогресс**: общая концепция утверждена, но персональные курсы и автоматически диагностированные навыки — будущее; точный UI, исходные источники и настраиваемые карточки проработаем отдельно.

**E. Desktop плотность**: адаптивный UX без page-scroll на ноутбуке, шрифты/размеры/цвета в едином визуальном ТЗ после утверждения рабочих путей.

## 14. Следующие шаги без реализации

1. Согласовать IA (A) и сценарии B/C; уточнить KPI (D).
2. Последовательно утвердить **каждый экран**, карточки, действия, empty/error/partial/fair-play states, и компактный layout на ноутбуке. Владельцу предоставить гибкий макет до кода.
3. Составить wireframes и таблицу «существует → переиспользуем / будущее → отдельно проектируем», не просить Codex заменить реальное поведение неподтверждёнными UI placeholders.
4. После принятия дизайн-концепции сформировать **одно большое, последовательное UX implementation-ТЗ для Codex** в отдельном PR/ветке от принятой архитектуры, с полным Windows CI и физическим acceptance. Не merge UX draft documentation без разрешения владельца.
