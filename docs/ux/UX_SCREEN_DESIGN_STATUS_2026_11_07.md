## Правила единого большого ТЗ (после экранов)

1. Для каждого экрана один owner summary, detailed implementation spec, feature ledger, эталонная картинка **если утверждена**. Не выдумывать approved photo.
2. При переносе: одно действие должно иметь **одну нормальную пользовательскую точку входа**. Дубликаты допустимы только как осмысленные shortcuts, а не разные backend-workflow.
3. Для каждого ранее существующего элемента явно KEEP / MOVE / HIDE DUPLICATE / ADD / PARKED. Не удалять скрытый функционал, заметки или QSettings без решения.
4. Единую спецификацию формировать только на **актуальном SHA после текущего ARCH-UX-01 §15**, с дедупликацией уже исправленных задач.
5. PR #44, PR #45 и main не редактировать в процессе проектирования; текущая отдельная docs-only ветка живёт до решения владельца о переносе документации. Никакого Codex задания до явного распоряжения.
6. Критический gate любого UX: Fair Play, account/source isolation, PGN/SQLite сохранность, честные Lichess statuses, graceful 1280×720/1120×640 и Qt DPI, real Windows visual acceptance.

**Текущее состояние:** подробно проработаны **2 раздела** («Мои партии» и выбор режима «Играть»), но полноценный визуальный эталон пока утверждён только для «Моих партий». Оставшиеся рабочие экраны — отдельные дизайнерские шаги.
