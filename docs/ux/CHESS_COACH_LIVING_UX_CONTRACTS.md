## 1. Общая гипотеза продукта [СОГЛАСОВАНО]

Chess Coach — существующее **Windows desktop приложение** для игры с Lichess AI и людьми, архива собственных партий, анализа Stockfish/готовых данных Lichess и постепенного развития обучения. Это **доработка существующего PySide6 интерфейса**, не новая программа, не web-редизайн и не смена архитектуры ARCH-01.

Порядок ценности:
- сначала чистый, понятный, единый интерфейс и надёжное хранение партий;
- затем глубокая диагностика собственных ошибок и дебютов;
- подготовка к конкретному сопернику;
- тренировки из собственных ошибок, адаптивное обучение;
- AI-тренер — **в последнюю очередь**.

Интерфейс должен отвечать на очевидный вопрос каждого маршрута; действия с высокой частотой доступны за 1–2 понятных шага, редко используемые настройки вторичны. Многофункциональность не означает «показать все настройки одновременно». Не дублировать одни и те же списки, очередь, шахматную доску и сервисные API несколькими независимыми реализациями.

**Стилизация всех будущих макетов:** та же нынешняя тёмная navy/indigo/угольная тема Chess Coach, приглушённый лавандово-фиолетовый primary, тонкие холодные borders, карточки со скруглением, аккуратная типографика, много воздуха, но не гигантские пустые прямоугольники. Никакой новой палитры. Фигуры и клетки могут остаться обычными классическими шахматными. Честная читаемость при 1280×720, 1120×640 и Windows DPI 100/125/150%, без перекрытий и недоступных кнопок.

## 2. Глобальная навигация — НОВЕЙШЕЕ РЕШЕНИЕ [СОГЛАСОВАНО]

**В главном sidebar РОВНО ПЯТЬ разделов:**

1. **Главная**
2. **Играть**
3. **Анализ**
4. **Обучение**
5. **Прогресс**

Отдельного пункта **«Мои партии» в главном sidebar НЕТ**. Полностью готовый экран «Мои партии» **не удаляется**: он становится **вложенным экраном** по пути «Анализ → Разбор партии → Мои партии». На прежних утверждённых изображениях пока присутствует устаревшая шестая кнопка: **при последующей реализации убрать только этот пункт меню, не выбрасывать весь дизайн экрана или его функции**.

**Быстрые обходные маршруты без лишних кликов сохраняем**:
- Главная → последняя/конкретная партия → напрямую в Review, если game_id известен;
- после завершения игры «Разобрать» → непосредственно Review этой партии;
- внутри вложенного архива «Открыть разбор» → непосредственно Review selected game;
- кнопки «Вернуться к партии» и «Продолжить» → существующий live Game Workspace.
- глобальный «← Назад» возвращает по навигации/источнику, а не листает страницы списка. В Review возвращать к тому источнику, откуда открыт материал; не сбрасывать фильтры, выбранную партию, скролл и историю.

**Вложенные экраны:** они **заменяют содержимое основного workspace**, а не распахиваются в длинную страницу под четырьмя верхними карточками. Например, «Анализ → Разбор партии» скрывает четыре стартовые плитки и показывает специальное рабочее пространство. Это решение устраняет проблему «новая панель слишком далеко от нажатой верхней плитки».

**Схема переходов:**

~~~text
Главная ── быстрая партия ───────────────────────────────→ Review
Играть ── создание / продолжение ──→ GAME active
                                       ↓ окончание
                                      GAME finished ── Разобрать → Review

Анализ (4 основных направления)
 ├─ Разбор партии (ВЛОЖЕННЫЙ ЭКРАН, 3 инструмента)
 │   ├─ Мои партии ── выбрать → Review
 │   ├─ Вставить ходы (текст PGN/ходы/FEN, файл .pgn) → Review/позиция
 │   └─ Расставить позицию ── редактор → Review/позиция
 ├─ Исследование дебютов ── СЕЙЧАС → статистика в Прогрессе
 ├─ Диагностика слабостей ── неактивна: в разработке
 └─ Подготовка к сопернику ── неактивна: в разработке

Фон (ГЛОБАЛЬНАЯ ШАПКА) → archive / Lichess / Stockfish queue
Настройки → параметры Lichess, engine, автоматической обработки
~~~

## 3. Общая шапка и фоновая работа [СОГЛАСОВАНО]

В шапке, одинаковой во всех основных маршрутах, сохраняются **«← Назад»**, реальный статус подключения/аккаунта и кнопка **«Фон»**. Рядом — **два компактных индикатора**, не крупные dashboard-панели:
- **Готовность данных к аналитике**: понятная доля **реально завершённых собственных партий с валидной оценкой** из подтверждённого количества партий в указанном аккаунте/выборке. Например, «930/3313 с оценками». НЕ смешивать «архив скачан» и «партия проанализирована». Не писать 80%, если total Lichess неизвестен. Отдельный прогресс загрузки архива доступен во «Фон».
- **Текущая работа**: реальный current Stockfish job «оценено X/Y позиций», либо краткий статус очереди / idle. Никаких фиксированных 15/85 из картинки. Несколько задач: в шапке один понятный active status, полный список — во «Фон».

При отсутствии знаменателя показывать счётчик/«Подсчитываем»/idle, а не придуманную долю. При 429, ошибках и account switch — честный статус, не старые проценты другого аккаунта.

**«Фон»** открывает **один** существующий центр фоновых процессов: загрузка архива, получение готовой аналитики Lichess, очередь Stockfish, статусы, ограничения, pause/resume/cancel/retry где backend действительно это умеет. **«Массовый анализ» больше НЕ отдельная плитка стартового «Анализа»**; его действие доступно в этом центре. **«Настройки»** управляют глубиной/ресурсами Stockfish, загрузкой и автоматизацией, но **не заменяют** рабочую очередь. «Мои партии → Анализ Stockfish» запускает **только выбранную** игру (явный запрос), не Batch window.

Никаких новых дублирующих воркеров, фиктивного прогресса и повторных необратимых Lichess POST после неизвестного исхода.

## 4. Главная [СОГЛАСОВАНО: в основном оставляем]

Главная — **личная обзорная панель**. Пользователь видит настоящее состояние своего аккаунта, недавние игры и полезные входы в конкретные задачи; художественные метрики не хардкодить. Текущая компоновка в основном устраивает владельца; коренной редизайн не планируется. Учитывать глобальное изменение меню с 6 на 5 и появление шапки с прогрессом. Все быстрые ссылки на сохранённые партии ведут напрямую в конкретную партию/Review, не заставляют проходить цепь из 3 экранов.

**Пока не делать:** фиктивные задания, progress/growth graphs без реальных измерений, новую систему персонального коучинга. Окончательная проверка Главной и отдельных мелких элементов — после обсуждения остальных экранов.

## 5. «Играть» — выбор режима [СОГЛАСОВАНО, 2 ВИЗУАЛА ОДОБРЕНЫ]

### 5.1 Раскладка

Вверху одна строка **активных игр** только когда игры подтверждённо есть: «Продолжить» / при нескольких «Все активные N» с выбором точного game_id. Это **не пятый способ начать новую партию**.

Под ней **четыре большие плитки 2×2**:
- верхняя левая **Lichess AI**;
- верхняя правая **Друг по ссылке**;
- нижняя левая **Вызвать игрока** (по нику Lichess);
- нижняя правая **Свободная доска** (локально ходить за обе стороны).

**Клик плитки выбирает режим**, подчёркивает его лавандовой рамкой и меняет **ОДНУ общую панель параметров непосредственно под сеткой**. Клик плитки **НЕ** запускает игру, не делает POST, не обнуляет доску. Отдельный большой выпадающий «Режим игры» и пять альтернативных панелей не нужны; удаляем видимый дубль, сохраняя handlers.

### 5.2 Поля одной панели в зависимости от плитки

| Выбрано | Какие поля показываем | Основное действие |
| --- | --- | --- |
| **Lichess AI** | Цвет Случайный/Белыми/Чёрными; контроль 3+2, 5+0, 10+0, 15+10, Без часов (если поддерживается), Свой; уровень AI 1–8 | «Играть против Lichess AI» |
| **Друг по ссылке** | Цвет; контроль; Обычная/Рейтинговая, только если допустимо сервером | «Создать приглашение» → после confirmed URL «Копировать ссылку»/«Отменить приглашение» вместо повторного «Создать» |
| **Вызвать игрока** | Ник Lichess; цвет; контроль; Обычная/Рейтинговая | «Отправить вызов» → «Ожидаем»/«Отменить вызов» |
| **Свободная доска** | Короткое описание, **нет бессмысленных** сетевых полей/контроля/AI-уровня | «Открыть свободную доску» |

**Свой контроль** раскрывает минуты и прибавление секунд, не отдельное окно. Каждый режим **отдельно запоминает** последнюю комбинацию полей (цвет, контроль, custom values, level, rated, nickname) при смене карточки, возвращении и перезапуске. Не показывать чужой ник при переключении аккаунтов; pending invitation/server ID не сохранять как «навсегда живые» настройки. Последняя выбранная карточка тоже восстанавливается. Повторный старт = один клик по CTA, без автоматической отправки.

**Состояния ожидания** показывать в ТОЙ ЖЕ нижней панели: создание, сервер подтвердил ссылку, ждём принятия, отменяем, отменено подтверждённо, отклонено, ошибка, ограничение 429, исход POST неизвестен. Повторный клик не даёт второй challenge. При отключённом Lichess сетевые CTA неактивны с объяснением, локальная доска доступна. «Без часов» не выдавать за correspondence без проверки реального типа timeControl.

**Пока отсутствующие отдельные режимы:** случайный live matchmaking и локальный Stockfish как соперник. Не рисовать их как работающие плитки.

### 5.3 Визуальный контракт

При normal desktop: одинаковые большие карточки 2×2, прямо под ними одна compact form, видимая контекстная primary CTA, темно-синяя/лавандовая палитра текущего приложения. Два одобренных арта из §12 показывают **AI до запуска** и **друга после создания ссылки**. Остальные состояния конструировать строго из полей этой таблицы, без выдуманных больших диалогов.

## 6. GAME — доска во время игры, фокус, финал, local [СОГЛАСОВАНО, 3 ВИЗУАЛА ОДОБРЕНЫ]

**Один и тот же GAME workspace**, без новой игровой программы и без нового окна результата.

### 6.1 LIVE online game (AI / человек)

Двухколоночная область:
- **слева** крупная квадратная шахматная доска, **над ней** противник+его реальные часы, **под ней** игрок+его реальные часы, компактный статус «Ваш ход» / «Ход соперника»; возле доски маленькие «Фокус», «Перевернуть», «Очистить пометки» (вторичное);
- **справа** история ходов №/Белые/Чёрные с собственным scroll; под ней навигация «В начало / Назад / Вперёд / К текущей»; ниже отдельный блок **«Управление партией»** с «Предложить ничью», «Вернуть ход»/«Запросить возврат хода» по server capability, «Сдаться», подтверждением опасных действий; входящие предложения «Принять/Отклонить» показывать контекстно.

Доска важнее правой панели. Убрать огромный выбор размера доски, большие дубли «Без обычных часов», яркий «Завершённые партии» и пустой блок «Предход». При отсутствии часов оставить **одну** нейтральную надпись «Без контроля времени», а не выдуманный 00:00. Если премув есть — маленькая видимая строка «Предход ... / Отменить». Просмотр прошлого хода не даёт отправить live move со старой позиции; есть явный возврат к текущей.

**Fair Play:** никакой оценки, PV, графика преимущества или engine hints при действующей human Lichess партии либо неизвестном safety status.

### 6.2 FOCUS — то же самое GAME

Правый столбец скрывается, вторичный shell может временно сжаться; **доска ДЕЙСТВИТЕЛЬНО УВЕЛИЧИВАЕТСЯ** до доступной ширины/высоты вместо сохранения прежнего 480 px. Сохраняются имена, действительные часы, чей ход, ходовая сессия, доступный выход «Вернуть панель»; опасные команды доступны через компактное **«Управление» в один клик**, а не исчезают навсегда. После выхода восстановить sidebar, историю, нормальные настройки доски и позицию. Степень увеличения проверить native Qt geometry, не на глаз.

### 6.3 FINISHED — доска остаётся

При подтверждённом завершении **остаться на той же доске и последней позиции**, заморозить часы, оставить имена и историю с навигацией. Справа вместо live команд **РОВНО ДВА ГЛАВНЫХ действия**: «Разобрать» и «Вызвать снова» (AI/человек по допустимому сценарию). Дополнительный «Экспорт PGN» вторичен. Нет ResultPage popup, auto review, auto Stockfish или автоматического отправления реванша. Если противник прислал встречный реванш — обработать подтверждённое приглашение со статусом, но не выдумывать accepted state.

### 6.4 LOCAL FREE BOARD

Доска и история, **отмена последнего локального хода**, переворот, пометки, «Новая свободная доска» по явному действию; без Lichess surrender/draw/takeback и лишних онлайн-часов. Существующая локальная оценка Stockfish только по сознательному запросу и при настоящем fresh Fair Play gate (если параллельно идёт human match — нет). Не путать с редактором произвольной позиции в «Анализе»: там добавляют/убирают фигуры без ходов из стартовой позиции.

## 7. «МОИ ПАРТИИ» — ПОЛНЫЙ АРХИВ ВНУТРИ АНАЛИЗА [СОГЛАСОВАНО, ВИЗУАЛ ОДОБРЕН]

**Новое местоположение:** «Анализ → Разбор партии → Мои партии». **НЕ в главном sidebar.** Переиспользовать **ровно тот же ранее спроектированный полный архив**, а не создавать уменьшенный второй список.

**Главная задача:** найти свою завершённую/активную игру, получить короткие реальные сведения о качестве, выбрать и открыть подробный Review.

**Геометрия:** master-detail, две широкие вертикальные зоны:
- **Слева архив**: компактная сводка «Всего N / последнее проверенное обновление», рядом небольшое «Обновить архив», поле поиска по сопернику/дебюту/дате и раскрываемые **все существующие фильтры** (в том числе дата, контроль, цвет, результат, источник, наличие анализа). При наличии актуальных live games — закреплённая строка «В ИГРЕ / Продолжить». Ниже scroll-перечень законченных партий; в каждой исход, соперник/AI, **мой цвет**, **моя точность + источник** или «Не оценено», дата, контроль, дебют. **Счётчики зевков/ошибок в строках не нужны**. Снизу строго под левым списком **обе кнопки ←/→ и номер страницы ВМЕСТЕ**, а не по разным краям окна.
- **Справа подробности ВЫБРАННОЙ**: результат и стороны, настоящий счёт, мой цвет, дата/дебют, подписанные **Моя точность / Точность соперника** с явными источниками, неточности/ошибки/зевки **Я vs Соперник**, честный охват, три мини-ячейки дебют/миттельшпиль/эндшпиль **только при реально подсчитанных фазах**, компактный график преимущества. Если данных нет — «Не оценено», **не 0% или 0 ошибок**.

**График в архиве** — одна линия без маркера на каждом ходе; видимый ноль; **светлая площадь выше нуля означает белых, тёмная ниже означает чёрных**, независимо от цвета владельца. Источник и покрытие действительные; нельзя соединять пропуски, подменять мат фиктивным ±999cp. Подробные маркеры ошибок и Δ остаются в полном Review.

**Низ правой панели:** «Открыть разбор» (переход в существующий Review выбранной партии), **«Анализ Stockfish»** (именно выбранная game_id, явный safety check, queue/running/completed status, не просто открытие Batch dialog), «Экспорт PGN»; «Заметки» — компактно вторично/в «Ещё». Существующие заметки и исходный PGN не удалять. «Фоновые операции» из низа убрать как дубль глобальной шапки, «Настройки загрузки» перенести в Settings. Ручная синхронизация архива доступна компактно сверху и не означает auto-анализ.

**Ширина/плотность:** высокая полезная насыщенность справа, но не растянутая пустая карточка, нет перекрытий на меньшем окне. При очень узкой ширине master→detail с «К списку» и сохранением selected game/page/scroll/filter, а не горизонтальная прокрутка.

**Быстрые пути:** с Главной/после игры пользователь минует весь архив и попадает в Review точного game_id. Не делать «архив» единственным шлюзом для разбора.

## 8. «АНАЛИЗ» — ЕГО СТАРТОВЫЙ ЭКРАН [СОГЛАСОВАНО, ВИЗУАЛ ОДОБРЕН]

Внутри route «Анализ» **один** крупный заголовок и короткая подпись. РОВНО **4 одинаковые крупные карточки 2×2**:
- **верх слева: «Разбор партии»** — рабочий вход «Открыть разбор» к вложенной странице §9;
- **верх справа: «Исследование дебютов»** — статус **«Частично доступно»**, CTA «Открыть статистику» к настоящей текущей статистике собственных дебютов в «Прогрессе», **не** к выдуманному explorer;
- **низ слева: «Диагностика слабостей»** — видна **НЕАКТИВНАЯ** «В разработке», без пустых экранов и noop-click;
- **низ справа: «Подготовка к сопернику»** — отдельная видимая **НЕАКТИВНАЯ** «В разработке», также без мнимых результатов.

Порядок и позиция плиток — как в утверждённом изображении §12. **Удалить с landing** постоянную огромную textarea PGN/FEN, раскрываемую inline доску с перекрытиями и плитку «Массовый анализ» (сама очередь сохраняется во «Фон»).

Сохранять четыре отдельные продуктовые задачи. «Исследование дебютов» — изучать **свои** частоты/результаты/варианты; «Подготовка к сопернику» — анализировать **конкретный публичный архив другого игрока перед партией** с корректными sample size, цветом и контролем. Это не один и тот же пользовательский вопрос, даже если будущая шахматная модель общая. Не притворяться, что две будущие функции уже написаны.

**Новейшее уточнение к старому макету:** на изображении ещё старый пункт «Мои партии» в sidebar. Согласно §2 он **исчезает из sidebar, но страница архива остаётся во вложенном «Разборе партии»**. Пока НЕ переделывать картинку; исправить при финальной генерации/единых инструкциях Codex.

## 9. «АНАЛИЗ → РАЗБОР ПАРТИИ» — ОДНО ВЛОЖЕННОЕ РАБОЧЕЕ ПРОСТРАНСТВО [СОГЛАСОВАНО]

**Нажатие плитки «Разбор партии» в §8:**
- **заменяет** 4 крупные стартовые карточки на вложенный экран «Анализ / Разбор партии», с видимой навигацией назад к четырём направлениям;
- внутри сверху **ТРИ компактных переключателя-инструмента**, не ещё один ряд больших стартовых 4 карточек:
  1. **«Мои партии»** (по умолчанию);
  2. **«Вставить ходы»**;
  3. **«Расставить позицию»**.
- **одна единая нижняя рабочая область**, её содержимое **меняется** по выбранному инструменту. Переключатель сам по себе не запускает анализ движком и не переписывает архив. Сохранить разумные черновики/выбор при переключениях.

**«Мои партии»** — без сокращений рендерится **весь** архив из §7, со всеми фильтрами, отбором, сохранёнными real metrics, графиком и кнопками. Это **не копия с урезанными фильтрами** и не переход в независимую шестую sidebar вкладку. Можно технически использовать один и тот же компонент/route архива под вложенным parent, главное — один data source/handler и сквозной back.

**«Вставить ходы»** — один инструмент для шахматного **ТЕКСТА**, а НЕ изображения:
- **PGN** = текстовая запись всей партии: заголовки и последовательность ходов, например «1. e4 e5 2. Nf3 Nc6». Полный файл .pgn или просто ходовая нотация → parser → интерактивная история и board в Review.
- **FEN** = текст одной шахматной **позиции** (расположение фигур, кто ходит, рокировки, en passant и counters), не история целой партии.
- по последнему обсуждению не нужно делать отдельную **четвёртую плитку «Вставить FEN»**. PGN/нотация/FEN/файл объединены под **ОДНИМ** инструментом ввода. Различие форматов всё равно нужно валидировать и объяснять; как именно — предмет **следующего короткого обсуждения**.
- **[СОГЛАСОВАНО 08.11]** простая вставка текста/переключение инструмента **не** запускает движок; после явного нажатия **«Открыть на доске»**, успешной проверки формата и открытия временной Review-сессии **автоматически начинается локальный Stockfish-анализ**, если имеется настроенный движок, актуальный разрешающий safety/Fair Play preflight и пользователь не отключил этот режим в настройках. **Не выполнять** автоматический запрос создания серверного анализа Lichess; это другой сервис. Ошибочный текст не должен создавать выдуманную игру или задание; временный внешний материал не должен тайно добавляться к личным сыгранным партиям.

**«Расставить позицию»** — полноценный **редактор произвольной шахматной позиции**:
- большое шахматное поле, палитра белых/чёрных фигур + инструмент убрать фигуру; клик/перетаскивание на клетку;
- чей ход; разрешённые рокировки, взятие на проходе и необходимые поля legal FEN;
- **«Начальная позиция»**, **«Очистить доску»**, **«Скопировать FEN»**, **«Открыть в разборе»**; переворот и локальный Undo редактора — только если действительно полезны/корректны, не обязательны сами по себе;
- отдельная нижняя рабочая область (НЕ распахивать под остальными 4 карточками), никакого перекрытия доски/кнопок на DPI;
- **[СОГЛАСОВАНО 08.11]** по кнопке **«Открыть в разборе»** после проверки легальности временной позиции открывается Review текущего FEN, затем **автоматически** стартует доступный локальный Stockfish-анализ по текущей политике безопасности и настройкам. Показать пользователю состояние «Анализируется… / Остановить / Пауза, если поддерживается / Готово»; нельзя имитировать паузу, если она не предусмотрена движком/задачей. Пока идет active human Lichess game либо серверный status unknown — fail-closed, позицию можно показывать только в разрешенном объеме, двигатель/PV/оценку не открывать. Если Stockfish отсутствует, safety отказал, пользователь отключил автоанализ или локальная очередь занята — честный статус и ручной явный CTA, без фиктивного результата.
- **НЕ дубль «Играть → Свободная доска»**: свободная доска — совершать шахматные ходы за обе стороны; редактор — вручную строить любой setup без истории предыдущих ходов. Переиспользуется общий chess-widgets BoardView/position model, а не второй движок шахмат.

### 9.1. Детальное согласование двух инструментов и автоматической проверки движком [СОГЛАСОВАНО 08.11]

**Суть UX:** пользователь не импортирует партию «для хранения», а осознанно приносит шахматный материал **для исследования**. Поэтому нажатие главной CTA после ввода/расстановки должно **быстро показывать доску и начинать локальное вычисление**, если оно реально безопасно и доступно. Этим новая функция отличается от открытия произвольного текста в простом файловом viewer.

**«Вставить ходы» — визуальный бриф будущей картинки:**
1. Внутри вложенной страницы «Анализ / Разбор партии» три компактных переключателя. Выбран **«Вставить ходы»**; под ними ОДНА широкая рабочая карточка, а не второй список партий и не popup.
2. Слева/сверху ясная подпись **«Вставьте PGN, последовательность ходов или FEN»**, ниже просторное многострочное поле с моноширинным текстом и коротким образцом (пример **не** копировать в реальные данные). Файл .pgn можно выбрать отдельной **вторичной** кнопкой **«Выбрать файл PGN…»** рядом с полем/под ним. Человек может вставить только обычные последовательные шахматные ходы без заголовков PGN.
3. Внизу primary **«Открыть на доске»**. Не две кнопки «Импорт» и «Анализировать», не два обязательных перехода. Маленькая строка состояния под полем: «Ожидает ввода / Проверяем / Некорректный ход на шаге N / Выберите партию из файла / Готово». Выделять точный фрагмент ошибки, если parser способен указать; не молча обрезать текст.
4. Определять по формату **три разных типа данных**: полный PGN со списком ходов и тегами, минимальная последовательная SAN-нотация ходов, одна FEN-позиция без истории. FEN не превращать в фиктивную PGN-партию. Несколько игр в файле → явный выбор конкретной, не auto-import всех и не auto-batch. Легальность ходов проверять chess.Board / python-chess, не regex-only.
5. **Только после явного «Открыть на доске»** открывается единый Review с ходами (для PGN/SAN) либо выбранной позицией (FEN), и **в этом моменте запускается локальная оценка**. При успешном запуске UI видимо показывает running. У пользователя должны оставаться **«Остановить»** и обновление прогресса; «Пауза» только если проверенно поддерживается. Настройки ресурса/autoanalyses — существующие global Settings.
6. Если в живом матче запрещён engine по Fair Play, показывать честную причину вместо Stockfish/подсказок; если запущена другая engine-job, не создавать бесконтрольный второй процесс, а отразить состояние scheduler/очереди. Нет движка/включён offline/manual mode — Review открывается, но явное «Stockfish недоступен / включите» вместо фальшивой оценки.
7. **Временный чужой PGN/позиция** как инструмент для частного исследования допустимы, но это **НЕ** импорт в «Мои партии», который содержит только свои реально сыгранные Lichess/локальные игры. Внешнюю PGN по умолчанию не сохранять, исходники не переписывать. Не делать отдельный массовый просмотр чужого архива.

**«Расставить позицию» — визуальный бриф будущей картинки:**
1. Тот же вложенный route; выбран третий переключатель, рабочая область полностью заменяет текстовое поле. Большая квадратная **доска слева** (главный объект), **справа** компактная палитра для белых/чёрных фигур с режимом **«Убрать фигуру»**. При выборе фигуры клик по полю ставит её; показывать выбранную фигуру/редактируемый статус, корректно перерисовывать.
2. Под палитрой/сбоку группы **«Чей ход»** (белые/чёрные), **«Рокировка»** (четыре согласованных права только если король/ладья стоят допустимо), **«Взятие на проходе»** (лишь юридически допустимые значения) и при необходимости move counters FEN. Понятное предупреждение, если текущая комбинация незаконна/невозможна. Не отправлять невалидный FEN в Stockfish.
3. Низ — действия **«Начальная позиция»**, **«Очистить доску»**, **«Скопировать FEN»** и лавандовая основная **«Открыть в разборе»**. Предпросмотр валидного FEN может быть вторичен, чтобы не съедать площадь доски. Данные редактора сохранять в **временном локальном draft** пока пользователь меняет инструменты; не сохранять как сыгранную игру.
4. **По открытию** та же единая Review-доска, автоматическая **локальная** оценка после проверки safety и легальности; никакой автоматической серверной аналитики Lichess. Остановить/статусы без блокирования окна. Позиция не привязана к fictitious player/победе/точности партии.
5. На небольшом мониторе и DPI 125/150% палитра, рокировка и кнопки переходят под доску/в доступный scroll, **не перекрываются** друг с другом. В отличие от режима «Свободная доска» здесь можно положить фигуру куда нужно без последовательности шахматных ходов.

**Различие трёх механизмов:**
- Выбрать/открыть **старую собственную партию из «Моих партий»** по обычной навигации само по себе **не обязано заново тратить ресурсы Stockfish**: есть кнопка явного анализа конкретной игры, кэшированные законные результаты. Наше одобрение автостарта относится прежде всего к **осознанному открытию только что вставленного шахматного текста/FEN или созданной вручную позиции**, а не к каждой случайной навигации в архиве.
- **Смена вкладок** PGN/редактор не запускает Stockfish. Автостарт **событийный**, идемпотентный, не на каждый repaint/повторный navigate.
- «Автоматически» значит **без дополнительного клика после главной «Открыть»**, но **не** «без safety-проверки», «неограниченно использовать CPU» или «запустить отдельный engine на каждый вариант». При необходимости сохранять настройки CPU/узлов, кэш/отмену, возможность выключить auto-run в Settings. Реально поддерживаемые scheduler/queue capabilities проверить перед единым ТЗ.

**Почему такая модель:** быстрый сценарий «вставил/расставил → открыл → сразу вижу анализ», без искусственной дополнительной кнопки, но без обхода честной локальной вычислительной и игровой политики.

**Три инструмента не равны трём новым главным маршрутам.** Главный пользовательский сценарий — выбрать материал → единый уже существующий Review, где можно двигаться по партии, изучать позицию и при допустимом safety явно запускать локальный Stockfish.

**[НОВЕЕ]** Назначение, состав действий и алгоритм входа для «Вставить ходы» и «Расставить позицию» **СОГЛАСОВАНЫ в §9.1**, но конкретные изображения/пиксельная сетка и мелкие положения элементов **ещё не генерировались и визуально не утверждены**. Допустимо будет доработать расположение при финальных макетах, сохранив пользовательскую логику.

## 10. REVIEW — ЕДИНЫЙ ПРОСМОТР И АНАЛИЗ [СОГЛАСОВАНО, 2 ВИЗУАЛА ОДОБРЕНЫ]

**Review — не ещё одна копия архива.** Открывается по выбранной сохранённой партии, вставленной PGN или корректной отдельной FEN, в рамках уже реализованных ограничений.

**Без сохранённых оценок:** крупная доска и история ходов как две главные колонки; честное «Анализ ещё не выполнен» и одна понятная кнопка «Проанализировать Stockfish», вторично «Экспорт PGN» там, где существует настоящий PGN. **Не занимать треть окна пустыми метриками/графиком, не показывать кнопку «Разобрать ошибки (0)» как главный action**.

**С сохранённой достоверной аналитикой:** доска остаётся крупной; история ходов постоянна; компактные summary (точность Я/соперник, ошибки/зевки, источники/охват, фазы если действительно вычислены), **график оценки с нулевой линией** (в полной версии могут быть опциональные маркеры ошибок и CP Δ), информация о выбранном полуходе и возможный переход в упражнения на конкретных доказанных кандидатах. Аналитика не обязана всегда занимать огромную постоянную третью колонку; график можно сворачивать. При отсутствии конкретного показателя — «Нет данных», не 0.

**Действия:** ручной Stockfish / повторный анализ, PGN export, «Разобрать мои ошибки (N)» **только при N>0 реальных eligible candidates**, навигация по ходам и ошибкам, существующие заметки, события, временное исследование вариантов без перезаписи исходной партии. PGN/FEN parser и position editor **не обходят Fair Play**. При human live/unknown hide не только кнопки engine, но и ранее сохранённые опасные подсказки/оценки, графики, tooltip.

**Вход из разных мест:** «Разобрать» после завершения → тот же Review; «Открыть разбор» в архиве → тот же Review; после импорта → тот же Review/позиция. Контекстный Back ведёт к прежнему источнику и сохраняет выбранный move/filters/scroll.

**На старом одобренном наборе:** изображение №4 — **просмотр уже сыгранной партии без аналитики**, а не live game; изображение №5 — тот же Review с действительными оценками. Не путать эти два экрана при генерации обновлённых эталонов.

## 11. Будущие разделы и ограничения [ПОЗЖЕ / НЕ РАЗОБРАНО]

- **Исследование дебютов [частично сейчас / позже]**: пока реальная статистика в «Прогрессе»; будущее дерево вариантов, ECO, фильтры по цвету и контролю, частоты, оценка выхода из дебюта, размер выборки и транспозиции. Собственный репертуар для тренировки — отдельная будущая задача.
- **Диагностика слабостей [ПОЗЖЕ]**: доказательный анализ закономерностей, фаз, типов решений и проблем; модель компетенций **A × (B1+B2) → C → D → E**: тема, видение/оценка/расчёт/выбор/исполнение и поперечные навыки → evidence → упражнения → проверка переноса. **Ошибка хода ≠ доказанная причина.** Будущие выводы должны ссылаться на реальные партии, выбранные ходы, покрытие/достаточность выборки.
- **Подготовка к сопернику [ПОЗЖЕ]**: отдельный перспективный экран с Lichess username, **только публичными допустимыми партиями**, частотой дебютов, цветами, вариантами, контролем, sample size, реальными источниками; pregame only, никаких подсказок в активной human-партии.
- **Обучение [НЕ РАЗОБРАНО]**: позже — уроки из собственных доказанных ошибок, тренировки, повторение, адаптивный учебный план. Текущую реализованную функциональность сохранить; конкретную компоновку ещё предстоит согласовать.
- **Прогресс [НЕ РАЗОБРАНО]**: настоящее личное изменение навыков/статистики, дебютная статистика (пока сюда ведёт Analysis), реальные измерения и связь с обучением. Отдельный UX впереди.
- **Настройки / общий «Фон» [ЧАСТИЧНО]**: backend существует, визуальные компоновки центра фоновой работы и настроек ещё надо обсудить; нельзя потерять очередь, quotas, синхронизацию, engine budgets.
- **AI-тренер, голос, аватар** — последние этапы. Не размещать завлекательные активные кнопки без backend.
- **Не добавлять без отдельного решения**: случайный матчмейкинг, локальный Stockfish как соперник, чужой личный архив «Мои партии», облачный заказ анализа Lichess, fake AI-подсказки при live human.

### 11.1. Исследование дебютов — история гипотез и отдельных условий [НА ЧАСТЬ ВОПРОСОВ ЕСТЬ БОЛЕЕ ПОЗДНИЕ РЕШЕНИЯ В §11.2]

**Статус:** здесь сохраняется подробная история гипотез, терминов и отдельных условий из первой итерации. **Более поздняя утверждённая архитектура маршрутов — §11.2**, она имеет приоритет при любом конфликте. Макеты не создавать до завершения всей концепции.

**Цель:** человек видит свой реальный дебютный репертуар, интересуется конкретными сильными и проблемными направлениями, сам изучает на интерактивной доске ходы и смыслы, может впоследствии закреплять знания в общей системе обучения.

**Старт / персональная аналитика:**
- Название первого этапа по смыслу близко к **«Мои дебюты»**, не «Исследовать»; отдельное название для следующего исследовательского workspace **ещё не выбрано**: «Изучить» звучит слишком сухо, рассмотреть варианты из двух слов.
- Сверху заголовок «Исследование дебютов», ниже **фильтры**: название, ECO, цвет, контроль, период, минимум сыгранных партий **N (вручную, например 5/10/50)**, возможность выбрать порог оценки выхода из дебюта (например +0,5/+1) — точные поля и дефолты пока не утверждены.
- Два **одновременно видимых** списка/колонки **«Сильные дебюты» / «Проблемные дебюты»**, каждый со своим прокручиванием внутри панели; карточка должна ясно показывать **ПОЧЕМУ** находится в конкретном списке. Название дебюта, цвет, число партий, частота, доля хороших/плохих выходов при выбранном пороге и другие реальные source-backed показатели. Не ставить карточку в категорию без доказуемого основания и понятного качества данных.
- **Отдельный каталог ВСЕХ дебютов**, включая неигранные, с поиском по названию/ECO и возможностью выбрать новую линию для изучения. По пожеланию владельца **вход в каталог виден постоянно**, пока список личных сильных/проблемных прокручивается; точная responsive-реализация и открывается ли каталог отдельной рабочей областью — **ЕЩЁ ОТКРЫТЫ**.
- Важная задача: **«В целом дебют хороший, но я регулярно ошибаюсь в одной ветке или попадаюсь в одну ловушку»**. Такой локальный сбой обязательно должен быть виден и давать переход прямо к конкретному варианту/позиции, а не скрываться за хорошей средней оценкой дебюта.
- Владелец предлагает ранжирование с использованием среднего/медианы оценки **на выходе**, фильтров по достаточному числу партий, частот/вариативности и процента партий с преимуществом. **Способ итогового ранжирования открыт**, отдельное решение требуется. Минимум N — пользовательский фильтр; при неполной аналитике необходим source-aware denominator и различение «не проанализировано» vs «плохо сыграно». Не путать итоговый результат партии с качеством дебюта.

**Изучение/исследование на доске:**
- В центре **одна интерактивная доска** с перебором ходов и ветвлений, не книга из множества длинных текстовых названий. Уместны стрелки потенциальных продолжений: зелёная = сильное, жёлтая = допустимое по согласованной методике; отдельно обозначать состояние просмотрено/изучено/проверено (синий значок/обводка), чтобы качество и факт изучения не конфликтовали.
- Четыре содержательных направления: **(1) Ходы и варианты, (2) Типовые позиции/пешечные структуры, (3) Планы игры, (4) Ловушки**. Это не обязательно четыре независимых страницы. План/структура могут быть контекстно связаны с текущей доской; но **ловушки должны иметь ещё и собственный отдельный просматриваемый каталог** с понятной сортировкой по практической частоте/актуальности. Не разделять учебный каталог ловушек на два самостоятельных раздела «Не попасться» и «Наказать»: это возможные задачи в будущей тренировке.
- На доске пользователь может выбирать альтернативные известные продолжения; изученное по желанию отдельно отмечается. **Одно нажатие на ход не доказывает освоение**; разделение просмотрено/изучено/проверено допустимо, но окончательная модель оценки ещё открыта.
- Глубина не ограничивается искусственным 10-м ходом. Если значимая дебютная теория ветки идёт до 20–30+ хода, её **можно изучить полностью**. Не обязывать человека проходить всё длинное дерево и решать его как единый гигантский тест; от простых часто встречающихся продолжений к редким. Где именно завершать дебютную фазу, как учесть переходы и транспозиции — обсуждаем отдельно, без универсальной фиксированной глубины.
- **Объяснения планов и ловушек** должны происходить из проверенного содержимого, не считать PV Stockfish готовым текстовым уроком. Частоты и объективные оценки — разные характеристики.
- Поддерживаются идеи состояний **«Встречено в моих партиях» / «Изучено» / «Проверено»**; общее интервальное закрепление и повторение — **в общем «Обучении»**, не обязательный отдельный блок открытия.

**Граница «Обучение» vs «Исследование дебютов» — РЕШЕНА ПОЗЖЕ В §11.2:** здесь первоначально обсуждалась третья вкладка «Проверить себя». Владелец **согласовал исключение тестов как отдельного этапа исследования**: практика по дебютам будет внутри общего «Обучения», с возможностью быстрого перехода к нужной ветке из исследователя. Разнообразные компьютерные ответы, обучение по отмеченным вариантам и позднее интервальное повторение остаются концепцией общего «Обучения».

**Принцип работы с данными:** личные Lichess-игры только с реальными оценками и учётом account/source; внешний Explorer показывает частоты в явно названной выборке; Stockfish — оценку конкретной позиции, не «базу планов». Недостаток данных нельзя скрыть одной настройкой фильтра, но окончательная политика empty/low-confidence ещё обсуждается.

**Ключевой вопрос из последнего обсуждения, не потерять:** как именно ранжировать две персональные колонки — **только по оценке выхода из дебюта ИЛИ также по частоте, тяжести повторяющихся ошибок, проблемам отдельной ветки и достоверности выборки?** Владелец попросил вернуться к нему позднее, когда будет больше сил, **не считать выбор сделанным сейчас**.

### 11.2. Согласованная архитектура двух экранов «Исследования дебютов» [08.11.2026; дополнена более поздними решениями §11.3]

**Цель при следующем разговоре:** сейчас проектируем ВЕРХНЕУРОВНЕВЫЙ интерфейс, а не математическую формулу, учебные планы на 30 ходов или отдельный каталог источников. Этот блок должен быть легко восстановим новым чатом. Вопросы ниже разделены на **согласовано / остаётся открытым**. Это не Codex ТЗ и не одобрение макета.

**[СОГЛАСОВАНО] Разделение анализа и обучения:**
- Главный route **«Анализ → Исследование дебютов»** нужен, чтобы понять собственную статистику, найти дебют, выбрать его, просмотреть ходы/позиции/планы/ловушки и отметить полезный материал.
- Главный route **«Обучение → Практика дебютов»** будет отвечать за компьютерные ответы, проверку по изученным веткам, повторение и развитие навыка. **Внутри Исследования нет отдельной третьей вкладки «Проверить себя».** В будущем допустим contextual CTA **«Практиковать эту ветку»** как переход в тот же общий обучающий движок, а НЕ встроенный дублирующий тренажёр.
- Два самостоятельных верхнеуровневых экрана «Мои дебюты» и «Дебютная лаборатория» **не нужны**. Первоначально пользователь открывает **одну страницу обзора/каталога**, а после выбора дебюта — **его вложенное исследовательское рабочее пространство**; словосочетание **«Дебютная лаборатория»** владельцу нравится как название для этого углублённого режима/контекста, **но не второго конкурирующего каталога**.

**[СОГЛАСОВАНО] Первый экран после клика по большой карточке «Исследование дебютов»:**
- В рамках действующей главной шапки Chess Coach **заголовок «Исследование дебютов»**. На экране **НЕТ большой доски/вариантов**: тут обзор дебютов, не занятие отдельным дебютом.
- Сразу ниже **полоса фильтров** (минимум N партий, цвет, контроль, поиск по названию/ECO, период и при необходимости порог оценки при выходе из дебюта; конкретный набор/default позже).
- Ниже **ДВЕ РАВНОПРАВНЫЕ колонки**: **«Сильные дебюты»** и **«Проблемные дебюты»**. В каждой — список **названий целых дебютов, а не отдельных веток**; его можно скроллить внутри колонки. Карточка: название, цвет игры пользователя, количество и частота партий, краткий реальный числовой/текстовый сигнал, **почему** дебют здесь, опционально средняя глубина дебютной последовательности в своих партиях (последнее предложено как гипотеза, не утверждать метрикой).
- **Важная граница:** при хорошем в целом Каро-Канне может быть одна болезненная ловушка. На уровне обзора она НЕ должна стать отдельной карточкой в общем рейтинге дебютов. Обзор может ненавязчиво сигнализировать «Есть проблемные продолжения» внутри существующей карточки **Каро-Канна**; подробности/конкретная ветка/повторяемые ошибки появляются **после открытия** самого дебюта. Владелец явно отклонил предложение смешивать ветки и целые дебюты в одном списке.
- **ОТДЕЛЬНЫЙ «Каталог всех дебютов»** — существует на **этой же обзорной странице**, включает как сыгранные, так и никогда не встречавшиеся пользователю дебюты. В **фильтрах** — переключатель по смыслу «Только из моих партий»: включён = в каталоге лишь реально сыгранные; выключен = вся библиотека. **Не строить отдельную самостоятельную вкладку «Дебютная лаборатория» как второй каталог.**
- Пользователь хочет, чтобы **вход/часть каталога оставались постоянно видимыми**, пока внутри сильных/проблемных колонок прокручиваются списки. Полное содержимое каталога, его высота, поиск/способ раскрытия и адаптивное поведение на ноутбуке **ещё уточняются**; не заставлять все три бесконечных списка одновременно скроллиться одним полотном.

**[СОГЛАСОВАНО] Клик по конкретному дебюту — вложенная страница деталей, её функциональная карта:**
- Переходим **внутрь выбранного дебюта**, а не показываем доску рядом с рейтингом всех дебютов; видим «Исследование дебютов / Каро-Канн · за чёрных», собственную короткую сводку и **одну рабочую интерактивную доску**.
- Человек исследует 4 направления на ОДНОМ материале: **ходы и варианты** (выбор продолжений/стрелки/истории); **типовые позиции** (в т. ч. пешечные структуры); **планы** сторон; **ловушки**. Ловушки также имеют **отдельный собственный каталог внутри выбранного дебюта** с сортировкой по значимости/популярности. Это четыре аспекта исследования, не четыре полноценные отдельные desktop вкладки, пока визуально не решено.
- Внутри выбранного дебюта показывать **проблемные конкретные ветки игрока**, если реально подтверждены: с чем связан недостаток, насколько часто это происходило, возможность перейти к позиции/своей партии. В overview только агрегированное имя дебюта, НЕ отдельные ветки.
- Продолжения могут сопровождаться зелёными/жёлтыми стрелками качества с отдельно указанной частотой; статус посещено/изучено независим от цвета. Полная глубина существенных дебютных линий (вплоть до 20/30+ ходов) по необходимости, но пользователь выбирает, что смотреть, его не заставляют проходить всё дерево.
- Вложенная доска **не заменяет** отдельную свободную доску «Играть», это исследователь; комментарии планов/ловушек должны основываться на проверенном контенте, не на одной engine PV. Удобный Back к обзору сохраняет фильтры и позицию выбранного дебюта.
- Избранное/выбранные для тренировки ветки и быстрый переход в **Обучение** — полезная предлагаемая граница, но точный UX/модель сохранения пока открыть как вопрос, не выдумывать активный backend.

**[ОТКРЫТО] Что НЕ считать утверждённым, вернуться позже:**
1. **Ранжирование двух колонок**: средняя/медиана оценка выхода, частота партий, доли по порогам, тяжесть ошибок и проблема отдельных веток, устойчивость, сравнимость источников и выборок. Владелец отдельно просил **не потерять этот вопрос**. Обязательная логика сортировки — ещё не выбрана; не требовать прямо сейчас сложной формулы.
2. **Последняя геометрия overview:** каталог всех дебютов внизу и постоянно видимая зона доступа, как именно скроллятся 2 колонки/каталог, минимальные размеры и смена вкладок — после функциональной схемы.
3. **Как группировать и именовать дебюты**, где проходит граница родительский дебют→подвариант, почему одинаковое начало за разные цвета даёт разные персональные показатели, как не дублировать транспозиции — методологический вопрос, не мешать сейчас обзору.
4. **Показатель «среднее количество ходов до выхода из дебюта»** как идея владельца: возможен, но методика границы ещё не утверждена, не отображать выдуманные числа.
5. Данные по отдельным дебютам, которых пользователь никогда не играл: персональные метрики = «Нет собственных партий», можно изучать по внешнему справочнику. Источники, локальный кеш и учебный контент предстоит решить.
6. Финальное название внутреннего workspace, конкретные controls и длина описаний, и нужны ли badges изучено/просмотрено — после макета. **Пока картинки не генерируем**.

### 11.3. ОКОНЧАТЕЛЬНО СОГЛАСОВАННЫЙ УРОВЕНЬ НАВИГАЦИИ И НОВЫЕ UX-КОНТРАКТЫ [08.11.2026, v1.4]

**Приоритет над §11.1 и §11.2 при несовпадениях.** Владелец явно назвал представленную в v1.3 общую карту раздела **окончательной в части архитектуры интерфейса**. Мы не строим сейчас весь дебютный шахматный алгоритм; до макетов и будущего единого Codex-ТЗ дообсудим только действительно влияющие на экран пробелы. Все изображения генерируются в конце общего UX-проектирования, старые ТЗ и графические эталоны не редактируем.

#### A. Подтверждённый маршрут и роли экрана [СОГЛАСОВАНО]

1. Главный sidebar **5 разделов** (§2) → **«Анализ»** → одна из четырёх карточек **«Исследование дебютов»** (верхняя правая на 2×2 home).
2. **Экран I: Обзор дебютов.** Вопрос: *«Что я играю хорошо/проблемно и какой дебют хочу открыть?»* Здесь нет большой шахматной доски и дерева вариантов. Есть заголовок, верхняя полоса фильтров, **две колонки ЦЕЛЫХ дебютов** «Сильные» / «Проблемные» со своим scroll, и **отдельный каталог всех дебютов, доступный без ухода с этой страницы**. При прокрутке списков доступ к каталогу остаётся видимым. Длина, порядок и точные widgets будут решены при генерации финальных макетов.
3. **Экран II: Детальная «Дебютная лаборатория» конкретного дебюта** (название нравится владельцу). Открывается при выборе дебюта из любой из трёх областей обзора. Вопрос: *«Какие варианты, структуры, планы и ловушки есть в ЭТОМ дебюте и где именно я ошибаюсь?»* Здесь основная интерактивная шахматная доска + 4 исследовательские области «Ходы и варианты», «Типовые позиции», «Планы игры», «Ловушки». Ветка с конкретной проблемой видна **только после открытия дебюта**, НЕ отдельной карточкой среди верхнеуровневых дебютов. Ловушки имеют собственный каталог в рамках выбранного дебюта и связаны с той же доской; не создавать 4 независимые шахматные программы.
4. **Общий «Обучение → Практика дебютов»** — отдельная главная вкладка; там будут вариативные упражнения и проверки. **Отдельной третьей страницы «Проверить себя» В «Исследовании дебютов» НЕТ.** Допустима поздняя кнопка/ссылка «Практиковать ветку» из лаборатории в общий тренажёр с сохранённым контекстом; не писать второй тестовый backend внутри Opening Explorer.
5. Back II→I восстанавливает фильтры, scroll, выбранный контекст; Back I→Analysis landing. Быстрый переход из личной партии к нужному дебюту/позиции — полезная будущая сквозная связь, но не отдельный новый маршрут.

#### B. Обзор: персональные данные и общий мир [СОГЛАСОВАНО КОНЦЕПТУАЛЬНО]

- **Фильтр «Только из моих партий»:** включён — общий каталог показывает только реально сыгранные игроком дебюты; выключен — каталог включает все доступные названия из внешнего справочника, включая никогда им не сыгранные. **Не** требуется отдельный второй верхнеуровневый каталог или маршрут.
- Подписи источников должны разделять **(1) «Мои партии»** — индивидуальная статистика аккаунта, и **(2) «Общая база»** — частоты ходов/результаты в конкретной публичной выборке (например Lichess при доступности). Можно в исследовании показывать **ОБА показателя рядом**: как часто так ходят в опубликованной базе и как часто так ходил этот пользователь, с собственными знаменателями/источниками и с учётом фильтров. Это **сравнение двух выборок, а не сумма или «общая» средняя без источника**.
- Если пользователь не играл дебют/нет игр/нет оценок, **общедоступная статистика и каталог всё равно дают возможность изучения**. При включённом «Только из моих партий» пустой список допустим, с понятным пустым состоянием и возможностью снять фильтр. **Не выдумывать персональные показатели из внешней базы.**
- В обзорных карточках ранжируются **исключительно дебюты**, а не ветки. Цвет игры пользователя, название, число и частота партий, источник/качество реальной статистики, краткий понятный показатель основания включения. Персональная статистика может включать долю выходов с преимуществом по выбранному порогу, средней/медианной оценке на выходе, точность дебюта, разнообразие сыгранных ответвлений и **гипотезу средней длительности дебютной фазы** — НО точный список и способ вычисления до отдельного решения не утверждены.
- Пользователь отдельно напомнил про идеи **среднего числа ходов, проведённых в дебютной фазе, и средней точности дебюта** как возможные дополнительные показатели; сохранить как **идею**, не выводить число при отсутствии определённой метрики.

#### C. Ранжирование: что на самом деле открыто [ЧЕСТНО СОХРАНИТЬ]

Владелец уточнил: «как сравнивать» может означать три разные вещи: **(а) статистически сопоставить** показатели собственных партий/общей базы, **(б) отсортировать сильные/проблемные целые дебюты**, **(в) выбрать, какой изучать следующим**. Эти вопросы нельзя смешивать.

- **[СОГЛАСОВАНО ПО НАПРАВЛЕНИЮ]** возможные сигналы: количество/частота партий в дебюте (с источником), локальные vs публичные частоты, средняя/медианная оценка на дебютном выходе, процент выходов с преимуществом/недостатком по пользовательскому порогу, точность дебютной фазы при подтверждённой аналитике, повторяющиеся ошибки. Фильтр **«не менее N личных партий»** задаёт минимальную опору для персональной выборки.
- **[ОТКРЫТО]** единая методика сортировки и приоритизации, роль тяжёлых ошибок, конфликты сигналов, какой показатель считать основным/вторичным, как показывать источники при неполных данных. Само наличие фильтра N **не заменяет** необходимость честно обозначить неполную выборку оценённых партий; без Stockfish/Lichess analysis нельзя искусственно вычислять точность.
- **Нельзя интерпретировать частоту конкретного популярного хода как объективную силу хода.** Объективную оценку даёт отдельный подтверждённый анализ; статистический источник и фильтры указываются. Не смешивать «лучший результат всей партии» с «лучшей позицией после дебюта».
- Запрос владельца **не потерять вопрос** о ранжировании и тяжести ошибок; сознательно возвращаемся к нему позже, **не сейчас**.

#### D. Два способа «выйти из дебюта» внутри исследовательского workflow [СОГЛАСОВАНО КАК UX-НАМЕРЕНИЕ; КЛАССИФИКАЦИЯ ОТКРЫТА]

При исследовании дебюта X пользователь не должен незаметно уйти в полное исследование другого дебюта Y, если шахматное продолжение/транспозиция стало в базе относиться к другой дебютной категории. В продуктовом смысле есть два типа конца выбранного учебного пути:
1. **«Дебют завершён → переходим к миттельшпилю»**. Завершить изучение выбранной ветки в том месте, где у неё осмысленная граница дебютной теории; показать текущую позицию и, при наличии проверенных материалов, планы и типичные структуры. Не обрезать все варианты на одном десятом ходу — некоторые реально изучаются существенно глубже.
2. **«Продолжение относится к другому дебюту/семейству»**. Понятно уведомить, что мы достигли условной границы X и нашли переход в Y; **предложить** открыть Y отдельно, но **не переключать автоматически** и не заставлять изучать всё дерево Y, если человек пришёл ради X.

**Важная оговорка:** названия/границы дебютов не образуют безусловную взаимоисключающую шахматную классификацию; транспозиции, варианты и родительские названия пересекаются. Два выхода выше — **желаемое пользовательское поведение**, НЕ утверждение, будто каждую позицию можно однозначно признать «уже французская, больше не Каро-Канн». Фактический метод распознавания и предотвращения ложного обрыва ещё нужно разработать с шахматными данными и мастерами/тестами, а до того избегать автоматического жёсткого исключения линий из X. При отсутствии уверенной классификации показывать связь/пересечение, оставлять исследование осмысленной позиции, а не терять ветку.

#### E. Как учитывать просмотренные ветки [СОГЛАСОВАН ПРИНЦИП, МЕХАНИКА ПОЗЖЕ]

- **Программа должна помнить посещённые позиции/ветки** в конкретном выбранном дебюте, на конкретном аккаунте; не терять после выхода из лаборатории, закрытия приложения и смены выбранного варианта. Нужны состояния «не открывал» и «просмотрел» (например отдельный маркер); **не обязывать пользователя проходить тест, чтобы отметить самостоятельное исследование**.
- **Время нахождения в позиции НЕ служит доказательством освоения:** 1 секунда и 2 часа формально дают факт посещения, но не знак шахматного знания. Это отражает выбор пользователя свободно исследовать, а не навязанные экзамены.
- **«Просмотрено» ≠ «подтверждённо освоено».** При отсутствии тренировки не писать «знаете этот дебют на 90%». Возможный показатель **«Охват просмотренных/изученных веток»** относится к конечному выбранному/доступному дереву, взвешивается по частоте, а не ко всем теоретическим бесконечным вариантам. Что именно считать отдельной веткой, как автоматически отмечать путь и как сохранить через транспозицию — **отложено для техническо-шахматного дизайна**, не блокирует сейчас UI.
- Когда общий тренажёр появится, подтверждённый результат теста от него можно показывать отдельно от просмотренного материала. Автоотметки не превращать в сертификат владения.

#### F. Как человек узнает об улучшении игры [СОГЛАСОВАНО КАК ФУНКЦИЯ / МЕТОДЫ ОТКРЫТЫ]

- Показать **изменение качества собственной дебютной игры по времени**, а не только общую статичную оценку: линия/таблица по неделям, месяцам, в дальнейшем произвольный период; измерения только по реально законченным играм текущего аккаунта.
- Возможные метрики: **средняя точность именно дебютной фазы** (если сохранённая валидная оценка позволяет её посчитать), **средняя оценка позиции на выходе из дебюта с точки зрения игрока**, доли партий с преимуществом/ухудшением по заданному порогу, количество партий/покрытие анализом. Не путать это с общей accuracy за всю партию.
- Статистика должна показывать **количество игр и охват проанализированных позиций за каждый период**, не сопоставлять 2 партии с 200 как равноточные данные. Улучшение по временному графику = **корреляция во времени**, а не доказательство, что выбранная тренировка его вызвала.
- Возможная точка показа — внутри конкретного дебюта (личная динамика), а общая сводка — в «Прогрессе»; **точное место и вид графика пока НЕ утверждены**. Не добавлять третий новый главный экран.

#### G. Визуальный бриф для будущих двух изображений [УТВЕРЖДЁН СМЫСЛ, НЕ САМИ КАРТИНКИ]

**Будущий арт OPEN-1 — «Исследование дебютов: Обзор».** Использовать неизменный Windows Chess Coach shell §13 с **5 пунктами sidebar** и текущей тёмно-синей/лавандовой стилистикой; выбран «Анализ», рядом хлебная крошка «Исследование дебютов». Под заголовком ряд ненавязчивых фильтров: поиск дебюта/ECO, цвет, контроль, период, «не менее N своих партий», переключатель «Только из моих партий». Ниже две **равные прокручиваемые колонки** «Сильные дебюты» и «Проблемные дебюты», в каждой компактные карточки, **только целых дебютов** с цветом, настоящими/примерными подписанными количествами и короткой причиной ранга; не выводить ветки отдельными строками рейтинга. Внизу **доступный независимо от скролла** полноценный каталог всех дебютов с поиском/выбором (честное состояние без личных данных). **Нет большой шахматной доски на OPEN-1**, нет тестового тренажёра. Если не хватает высоты на 1120×640, продумать адаптивную область каталога, не закрывать список навсегда.

**Будущий арт OPEN-2 — «Каро-Канн: Дебютная лаборатория»** (название/сторона illustrative). Открыт конкретный дебют после клика по OPEN-1. Верх: Back к обзору с сохранением фильтров, название/выбранный цвет/короткая личная сводка, возможность переключить сравнение «Мои» / «Общая база» либо увидеть две выборки рядом. Центр: **большая интерактивная шахматная доска** слева, справа или в компактном context panel дерево/список продолжений, частота/качество и история ходов; зелёные/жёлтые указатели не перекрывают фигуры. Четыре исследовательские перспективы **«Ходы и варианты», «Типовые позиции», «Планы игры», «Ловушки»**, отдельный список ловушек этого дебюта; внутри варианта можно увидеть подтверждённые ошибки из собственных партий с ссылкой на конкретную позицию. Ниже/рядом при наличии данных динамика качества по времени и сохранённые маркеры посещения. **Не рисовать 4 независимых доски или третью страницу «Проверить себя»**, future CTA в общий «Обучение» можно показать только с честным статусом. Данные и названия на самом арте — образец, не hard-coded значения.

**Кросс-экранный критерий:** OPEN-1 → click конкретный целый дебют → OPEN-2; Back → тот же OPEN-1 с фильтрами, прокруткой и ранее выбранным дебютом. Перемотка дерева OPEN-2 не переносит на другой дебют автоматически. Визуально проверить source labels и понятность отсутствующих персональных данных. Это детали для **будущей** генерации, сейчас не создавать изображений.

## 13. ВИЗУАЛЬНЫЙ БРИФ ДЛЯ НОВОГО ЧАТА / ГЕНЕРАЦИИ

Если контекст разговора потерян, новый гейм-дизайнер должен воспроизводить изображения по **настоящему UX-контракту и исходным артам**, а не по старой шестипунктной схеме:

1. **Canvas:** widescreen Windows desktop screenshot, предпочтительно 16:9 ~1672×941, детализированная native desktop UI, реалистичные Qt-подобные widgets, без браузерной строки, без случайной декорации и fake dashboard cards.
2. **Палитра:** нынешняя тёмная navy/charcoal/indigo Chess Coach, muted lavender primary selected/button, холодные вторичные cards, тонкие обводки, светлая читаемая русская типографика. Не менять тему, насыщенность и контраст всей программы; chess squares/pieces можно классические.
3. **Постоянный shell:** sidebar **5 ссылок из §2**, текущий аккаунт и статус Lichess при наличии реальных данных/placeholder в mock, «Настройки» внизу, глобальный «← Назад», справа реальные/условные только для демонстрации чипы ready/progress и «Фон». Главный экран не всегда содержит все чипы (idle collapse), не жертвовать шириной content.
4. **Композиция:**
   - Analysis landing **4 tiles 2×2** с точными названиями/статусами §8, НЕТ textarea или Batch tile;
   - Play landing **4 tiles 2×2** и контекстная панель прямо под ними, НЕТ огромного mode combo;
   - My Games вложен в Analysis/Разбор, **полноценный двухколоночный архив**, НЕТ sidebar «Мои партии»;
   - GAME live — большой квадрат доски слева + player/clock сверху/снизу, справа history+actual live actions;
   - Focus — **реально большая** доска без правой панели, часы и management сохранены;
   - Finished — **та же** доска/последняя позиция, справа 2 CTA;
   - Review no-data — крупная доска + ходы + один manual analysis entry, нет пустой третьей колонки;
   - Review with data — доска+ходы+достоверные метрики/график и контекстный training;
   - вложенный «Разбор партии» — 3 компактных переключателя и **ОДНА** изменяющаяся рабочая область.
5. **Качество:** не терять основных кнопок из конкретного состояния; выравнивать поля, горизонтали, одинаковые высоты карточек, не делать огромные подписи вместо доски. Русские подписи должны быть корректны, контент без наложений. Кнопки с будущим функционалом честно disabled. Идеальная картинка не оправдывает неправильные данные.
6. **Валидация после каждой генерации:** самостоятельно проверить число и расположение карточек, отсутствующие/лишние кнопки, соответствие состояния, отсутствие устаревшего шестого пункта, source-accuracy/score semantics и сохранение палитры. Если ошибка — перегенерировать **в рамках будущего этапа макетов**. Не отправлять непроверенные арты как эталоны Codex.
7. **Для передачи Codex позже:** у каждого изображения есть конкретный Windows путь и назначенное состояние. Codex открывает оригиналы и сравнивает реальный Windows screenshot side-by-side на нескольких DPI/размерах. Скриншот = образец композиции, **не доказательство**, что механика уже работает.

## 14. КРИТИЧЕСКИЕ ПРОДУКТОВЫЕ И ТЕХНИЧЕСКИЕ ИНВАРИАНТЫ

- **[ЗАПРЕЩЕНО]** Показывать оценки/PV/подсказки движка при действующем human Lichess матче или неизвестной безопасности; закрытая игровая вкладка ≠ окончание online match; PGN/FEN/Review не обходят проверку.
- **[ЗАПРЕЩЕНО]** Тихо удалять или менять оригинальный PGN, сохранённые заметки, line revisions, account ownership; временная позиция/вариант не переписывает исходную игру.
- **[ЗАПРЕЩЕНО]** Смешивать server Lichess и локальную Stockfish accuracy, выдавать NaN/partial/unknown за 0 или готовый 100%, выводить фиктивную готовность базы.
- **[ЗАПРЕЩЕНО]** После неизвестного исхода remote POST слепо повторять create/challenge/cancel и объявлять отмену подтверждённой без серверного ответа.
- **[ОБЯЗАТЕЛЬНО]** Реальные source-backed метрики, account/generation fencing A→B, стабильные Qt worker и очередь, UI не висит на синхронизации/Stockfish; честный 429/offline.
- **[ОБЯЗАТЕЛЬНО]** Все основные инструменты остаются доступными, даже если их кнопки переехали: фильтры архива, PGN/file/FEN, ручной редактор, batch/engine config, заметки, live game control.
- **[ОБЯЗАТЕЛЬНО]** Дизайн и реальная сборка должны быть протестированы на нормальном ноутбуке и Windows DPI 100/125/150%. Нельзя принимать «похоже на арте», если кнопка перекрыта/недоступна или переход ведёт не туда.
- **[ОБЯЗАТЕЛЬНО]** Для отдельного рабочего состояния пользователь должен понимать, что активировано, откуда взяты данные и куда ведёт главная кнопка.
