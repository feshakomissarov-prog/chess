# Chess Coach — UX-A2: утверждённый раздел «Анализ» и шахматный разбор

**Утверждено владельцем 04.11.2026:** рекомендуемый ранее **Вариант B** (кириллическая «В» в сообщении владельца трактуется как описанный рекомендуемый вариант с **тремя входами**). Источник: [рабочие альтернативы, вариант B](ANALYSIS_WORKSPACE_DESIGN_OPTIONS.md). Этот документ — **утверждённый UX baseline, а НЕ команда Codex начать реализацию**; конкретные глубокообразовательные дебютные данные — будущая реализация.

## A. Три крупные карточки на стартовой странице «Анализ»

1. **Разбор партии / PGN.** Внутренняя страница выбора источника: «Из моих партий» (завершённые), «Открыть файл .pgn» или вставить текст PGN; вторичные инструменты «Свободная доска / редактор» и «Вставить FEN». Никакой фото/OCR/ИИ-сканер. Импорт **не равен экспорту**, внешний временный PGN/позиция не добавляется в свой архив без отдельного действия.
2. **Массовый анализ.** Общая очередь Stockfish по завершённым партиям: выбор партий и параметров, узлы/depth, ход выполнения, pause/resume, caching/retries, проверенные данные. Это **единственная** control-plane очередь анализа; «Мои партии» показывает лишь счётчики и ссылку сюда.
3. **Исследование дебютов.** В будущем большой отдельный инструмент: дерево ходов, ECO, транспозиции, статистика собственных партий/источников, варианты, планы, разрешённые оценки Stockfish. Отличать от «Обучение → Мой репертуар» (учить лично выбранные линии, а не просто исследовать). **Поздняя фича «Подготовка к сопернику»** размещается здесь, см. [долгосрочную концепцию](../research/OPPONENT_PREPARATION_LONG_TERM_FEATURE.md).

### Вход «Разбор партии / PGN»

\`\`\`text
┌──────────────────── ВЫБРАТЬ МАТЕРИАЛ ───────────────────────┐
│ [Из моих партий]   → тот же архив/модальный selection, без     │
│                       второго хранения                        │
│ [Открыть PGN]      → Windows file picker, .pgn; можно текст   │
│ [Вставить PGN]     → paste из буфера                           │
│                                                            │
│ Дополнительные инструменты: [Вставить FEN] [Расставить фигуры]│
└────────────────────────────────────────────────────────────┘
\`\`\`

- **Свои завершённые партии** → один и тот же review workspace из каталога и из Анализа; при открытии исходная партия не переписывается.
- **Внешняя партия**, например чужая → PGN file/paste, временная сессия просмотра, явная отдельная команда «Сохранить в мои партии». При нескольких партиях в PGN — выбор конкретной, без auto bulk analysis.
- **Отдельная позиция** → вставить FEN или расставить фигуры мышью, side-to-move/castling/en passant validity, не обязательно принадлежит сыгранной партии и **не** считается личной игрой.
- **Исследовать с выбранного хода** → открыть копию в варианте, «Назад к оригиналу», никакой записи гипотез в исходный PGN без отдельного Save. Общий вид/доска, без второго engine.
- **Запуск Stockfish** всегда отдельное действие, только с действующим full Fair Play preflight и корректной позицией; открытие PGN/FEN не запускает engine.

## B. Обязательное рабочее пространство разбора: шкала + сохранённый график

**Поправка владельца от 04.11: добавить узкую длинную вертикальную шкалу оценки, как на шахматных сайтах, непосредственно сбоку от доски.** Шкала и нижний график решают разные задачи:
- **Шкала** — ответ «кто сейчас лучше в текущей выбранной позиции». Часть чёрная, часть белая, разделитель сдвигается на основании **доступной разрешённой оценки текущего полухода**; рядом краткое \`+0.7 / -1.3 / M3\` и источник/перспектива. Нельзя делать постоянную 50/50 шкалу и выдавать её за оценку, если данных нет.
- **Нижний график** — история оценки **за всю партию**. Сохраняем **текущую уже реализованную интерактивную графическую систему**, со всеми работающими маркерами ошибок, CP/mate-разделением, синхронизацией позиции и **выбором режима графика** («Оценка позиции» / «Изменение оценки / Δ», и существующие рабочие варианты). Не заменять его маленьким статичным sparkline, не выкидывать график изменений. Переход по точке графика меняет выбранный полуход и соответствующую шкалу.
- Источник у обоих виджетов может быть официальный Lichess или сохранённый локальный Stockfish; не смешивать источники в одном бессмысленном ряду, если они неоднородны. Отдельная маркировка, coverage, depth/nodes только когда известны, н/д vs 0. Если источник для отдельного полухода отсутствует, шкала «Оценка недоступна»; график имеет **разрыв**, не интерполирует неизвестный мат в CP.
- **Перспектива** шкалы/графика должна быть согласована: в исходном состоянии «оценка за белых» (подпись явно видна); при перевороте доски знак/график не меняются произвольно; optional user perspective control должен быть единым и объяснён.
- Мат хранится как **mate**, не искусственный \`+10/20 cp\`. В графике mate отдельными маркерами, CP линии не соединяются через mate points.
- **Fair Play:** при live human игре и при неуспешном/устаревшем preflight **оба компонента одновременно скрываются/маскируются**; нельзя показывать даже один кадр данных до актуального разрешения. При stale account/game/route/lease revoke сменить данные на safe placeholder синхронно.

### Продуктовые действия разбора

Шахматная доска, выбранный полуход, навигация стрелками, колёсико при фокусе на ходах/графике, связанные график и шкала; настройки движка отдельно; разбор хороших/плохих ходов и статистика — в правых вкладках, **не пять отдельных верхнеуровневых страниц**. Кнопка «Сохранить позицию/вариант» позже только явно, без записи в исходную игру. Источник и coverages при клике и изменении account сохраняются/валидируются, а не тихо смешиваются.

На ноутбуке 1280×720: **доска + шкала + часы/имена в разборе если нужны** сохраняют читаемость; вертикальный scroll может быть **внутри панели ходов/таблиц**, нижний график занимает постоянную доступную область; внешний layout не заставляет исчезать последние кнопки. При нехватке высоты вторичные правые табы уплотнять, а не делать доску крошечной.

## C. «Массовый анализ» — согласовано

Первый экран: summary queued/running/paused/failed, выбор завершённых партий по фильтрам каталога, число узлов/глубина/возможность собственных значений, исходные настройки при resume, источник L/S, progress X/Y, cancel/pause/resume, список задач. Не запускать по одному факту открытия вкладки; не делать вторую batch queue в «Мои партии».

## D. «Исследование дебютов» — согласовано по направлению

Большой будущий модуль со списком ECO, поиском дебютов, деревом ходов, локальными и внешними источниками данных, вариантами/планами, explorer+board. Отдельная подфича **подготовка к конкретному сопернику** по его публичным партиям Lichess, с ограничением выборки и честными знаменателями. Подробная внутренняя сетка дебютного explorer и методика данных будут утверждены позже; нельзя выдавать будущие кнопки за готовое сейчас.

## E. Не входит в этот этап согласования

AI фото-сканирование позиций, OCR, телефонное сканирование, чужие аккаунты без допустимых публичных данных, автоматический серверный анализ Lichess без документированного API, запуск двигателя во время live human game. **Не путать шкалу текущей позиции со всей историей графика.** По прошлому решению владельца не делаем обязательных CPU performance SLA в текущем архитектурном рефакторинге.
