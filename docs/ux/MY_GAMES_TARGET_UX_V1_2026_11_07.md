# Chess Coach · «Мои партии» — целевая компоновка UX v1

**Дата:** 07.11.2026  
**Статус:** концепция и отдельный визуальный макет утверждены владельцем; детальное ТЗ подготовлено для будущей отдельной реализации; всё ещё НЕ передано Codex. **НЕ исполнительное ТЗ Codex, НЕ разрешение менять код, НЕ часть текущего §15 PR #45.**

**Контекст:** две предоставленные владельцем фотографии текущего Windows UI, просмотренного при ширине около 1280 и 1680 пикселей; исходники текущей реализации в code PR #44 (контрольная точка 5c375b070e6644dbded5fca62d960fc09c90651e); утверждённый ранее UX-B1 в docs/ux/UX_APPROVED_BASELINE_V1.md на docs PR #45. Новые решения этого файла отмечают **узкие изменения** более ранней концепции UX-B1, не заменяя её полностью.

## 1. Для чего существует раздел

«Мои партии» отвечает ровно на четыре вопроса:
1. **Какую партию я ищу?** Активные партии, поиск, фильтры, история, быстрое листание.
2. **Что это была за партия?** Результат с моей стороны, соперник, мой цвет, дата, контроль, дебют.
3. **Как я сыграл?** Краткая, *достоверная* собственная точность, ошибки и ход преимущества — при наличии безопасных оценок.
4. **Что дальше?** Разбор, явно запрошенный Stockfish, экспорт, при необходимости обновление архива.

Не предназначен для общей диагностики слабостей, учебного плана, полноценных задач, настройки движка или технического инспектора: всё это живёт в других разделах.

## 2. Решение по структуре

**Сохраняем master-detail вместо нового окна**: слева каталог; справа выбранная партия. Большая правая карточка становится насыщеннее по смыслу и компактнее по вертикали. В списке остаётся только информация, позволяющая быстро отличить партии друг от друга. При клике по записи **НЕ запускается Stockfish**, не открывается отдельное окно и не сбрасывается поиск.

**Пагинация** — обе стрелки и номер страницы в одном левом блоке непосредственно под списком, не на противоположных сторонах всего окна. Верхнее «← Назад» — **другая функция**: возвращает на предыдущий маршрут, а не листает партии. Стрелки внизу должны иметь доступные подписи «Предыдущая страница партий» и «Следующая страница партий».

## 3. Левая сторона — компактный каталог

**Верх:** одна строка поиска (соперник, дебют, дата; существующий поиск сохраняется) + кнопка «Фильтры (количество активных)». Даты/период, источник, контроль, цвет, результат, наличие анализа и остальные существующие фильтры сохраняются; открываются по запросу, без отдельного постоянно занятого столбца.

**Активные партии:** закреплённая сверху самостоятельная группа «В ИГРЕ», для каждой — соперник, цвет, статус только из достоверных данных, действие «Продолжить». Никаких оценок, точности, PV или намёков движка. Фильтрация завершённого архива не должна бесследно прятать факт активных игр.

**Одна строка завершённой партии** (не превращать в многострочную таблицу):
- результат от перспективы выбранного аккаунта + достоверное имя соперника / «Неизвестный соперник», AI и уровень — если достоверны;
- **мой цвет**: «♙ Белыми» либо «♟ Чёрными» текстом и значком; если неизвестен — «Цвет неизвестен», не гадать;
- **моя точность**: одно число, источник рядом («Lichess» либо «Stockfish») и статус; если реальных измерений нет — «Не оценено», частичные данные — честно с охватом;
- дата, контроль и подтверждённый ECO/дебют, только если известны;
- счётчики неточностей/ошибок/зевков **в списке не выводить**: место отдать читабельности и точности.

**Ограничение плотности:** ориентир 2–3 строки на элемент при доступной ширине; не сжимать название соперника до «Со…». Переносить/обрезать с tooltip и доступным полным текстом; цена компактности не должна быть потерей смысла.

**Выбор записи:** выделяет одну запись, сразу загружает правую панель с состоянием загрузки, не перескакивает к другому аккаунту; сохраняет selected game ID, фильтры, страницу и вертикальную позицию. Двойной клик — рассмотреть позднее, **не делать новый скрытый альтернативный маршрут** без пользовательского решения.

## 4. Правая сторона — подробности выбранной партии

Приоритет сверху вниз:

1. **Заголовок:** «Победа / Поражение / Ничья · [соперник]», мой цвет, дата и начало/конец там, где подтверждены, контроль, дебют / ECO. Убрать дубли результатов и пустые многострочные пояснения. Подпись «человеческий соперник / Lichess AI» только из достоверного источника.
2. **Основные показатели:** «Моя точность» и «Точность соперника» как две подписанные величины (нельзя оставлять «84% / 92%» без указания, чьи это числа). Рядом источник и полнота. Для ошибок/зевков компактная пара **я / соперник** с однозначными заголовками. Не выдавать отсутствие данных за ноль.
3. **Точность по фазам:** три компактных ячейки «Дебют / Миттельшпиль / Эндшпиль» с собственной достоверной точностью, если расчёт для фаз и классификация реально существуют. Если подтверждённых вычислений нет — «Недостаточно данных», а не придуманная цифра. При возможности по клику переходить в тот же разбор с фазой, а не открывать новый экран.
4. **График преимущества:** обязателен для анализа при достоверных оценках; без оценок — спокойное пустое состояние. См. §5. Не раздувать диаграмму до полного review.
5. **Нижняя закреплённая панель действий:** первичная «Открыть разбор»; вторичная «Анализ Stockfish» (запуск явный, с проверкой Fair Play, статусом и приоритетом ручного запроса); «Экспорт PGN». Подробности «Ещё → Заметки» и опционально корректная ссылка Lichess, если game ID достоверен. Сохранённые заметки и редактор не удалять.

**Распределение высоты:** компактная шапка → числа и фазы → график → фиксированные основные действия. Локальная прокрутка правых деталей допустима, если контент длиннее, но ни одна основная кнопка не должна оказаться вне viewport на 1280×720. В панели без выбранной партии — текст «Выберите партию слева» и никаких активных действий с чужой игрой.

## 5. График: семантика и безопасность

**Решение:** упростить компактный график в карточке, не уничтожать насыщенный аналитический график самого Review.

- X: ходы/полуходы последовательно и честно; Y: оценка **с точки зрения белых**, положительная выше нуля, отрицательная ниже.
- **Светлая заливка только между нулём и положительной кривой = преимущество белых. Тёмная заливка только между нулём и отрицательной кривой = преимущество чёрных.** Это НЕ зависит от того, каким цветом играл владелец. На тёмной теме тёмная область должна оставаться контрастной; ось нуля всегда видна.
- В компактном представлении убрать символы **на каждом полуходе**: ромбы, квадраты, треугольники, зелёные/красные точки; оставить плавно читаемую ломаную/линию и площади. Ошибки и события — в полном Review, где могут быть доказательными маркерами.
- Не превращать мат в фиктивные ±999 cp, не соединять разрозненные участки как будто у них одинаковый источник и полное покрытие. Указывать «Stockfish / Lichess» и «оценено X/Y»; отсутствие оценок = отсутствие линии.
- Hover/keyboard focus — позиция, номер хода, оценка или mate и источник только если они действительно известны. Шахматная помощь скрыта во время active human Lichess match и при неопределённом safety.

## 6. Служебные действия и устранение дублирования

| Сейчас | Куда в целевой структуре | Обоснование |
| --- | --- | --- |
| «Назад» (страница архива) слева, «Вперёд» справа | **Вместе под левым списком**, с номером страницы | Одно функциональное целое; не путать с глобальным «Назад» |
| «Открыть разбор» | **Главное действие** выбранной партии справа | Целевой сценарий |
| «Анализ Stockfish» | **Отдельное действие** справа, не объединять с просмотром | Запускает вычисления; не то же, что открыть уже сохранённый разбор |
| «Экспорт PGN» | Рядом с основными действиями, вторичный стиль | Доступность файла важна; не скрывать |
| «Заметка» | «Ещё → Заметки» в правой карточке | Сохраняем данные и возможность редактировать; позже можно дать поиск |
| «Синхронизировать» | **Небольшое «Обновить архив» около поиска/короткого статуса архива** | Основной процесс автоматический; ручное обновление должно быть доступным, без обхода API quotas |
| «Фоновые операции» | **Один глобальный переход «Фон» в общей шапке** | Не дублировать на нижней панели |
| «Настройки загрузки» | **Настройки → Lichess / загрузка** | Служебный контроль, не основное действие архивного просмотра |

**Важно:** ручная синхронизация архива, загрузка готовой серверной аналитики Lichess и локальный расчёт Stockfish — три разных workflow. Кнопка «Обновить архив» не должна притворяться запуском/ускорением Stockfish или заказом серверного анализа. При 429/лимите показать конкретное состояние и время проверки, не обещать мгновенного результата.

## 7. Адаптивная компоновка

Величины ниже — **проектные ориентиры, не готовые pixel-perfect требования**:
- **Широкий desktop:** правая и левая колонки примерно равны, с небольшой поправкой на список. Лист 50–54% полезной ширины, детали 46–50%; сохранять понятные строки и график.
- **Окно 1280×720 с обычным sidebar:** обе колонки допустимы, если у каждой остаётся рабочая ширина порядка 420–460 px и все основные действия реально помещаются. Сократить вторичные подписи, уменьшить воздух в правой карточке, не число основных действий.
- **Узкое окно / 1120×640 / увеличенный DPI:** если рабочая ширина нарушает минимумы, переключаться на master→detail: сначала каталог, после выбора — детали с явным «К списку», сохранением позиции. Не допускать горизонтальной прокрутки всей страницы, скрытого правого действия или накладывающихся строк.
- **Sidebar открыт/закрыт** — фактор ширины; переключение не сбрасывает выбор. Проверять реальную Qt геометрию при 100/125/150%, а не только внешний вид PNG.

## 8. Состояния и реальные пути

**Обычный сценарий:** открыть «Мои партии» → выбрать результат/поиск → выбрать карточку → справа увидеть результат/цвет/точность/фазы/график → «Открыть разбор» → возврат без потери позиции списка.

**Партия без анализа:** все данные PGN и результата остаются видимыми; оценки/точность/график имеют честное «Не оценено». «Анализ Stockfish» после явного запуска показывает «проверка безопасности → очередь / вычисление → сохранено / ошибка», с видимым обновлением именно этой карточки. Результат появляется по подтверждённой записи, не по завершению одного UI spinner.

**Нет подключения / 429 / synс идёт:** старый архив можно просматривать, если источник локально достоверен; актуальность данных и ограничения показываются честно. Ошибки одной партии не очищают выбор другой.

**Активная человеческая партия в Lichess:** никакая сохранённая или потенциальная engine-подсказка не раскрывается до безопасного preflight; доступные функции просмотра/импорта не обходят Fair Play. Произвольное закрытие окна игры не означает безопасность.

**Фоновое обновление:** новая PGN/revision/analysis для того же game ID обновляет видимую карточку с account+revision guard; не перезаписывает более новые данные, не сбрасывает scroll и не показывает метрики чужого аккаунта.

## 9. Будущее без преждевременной реализации

Зарезервированы, но **не рисуются как активные кнопки** пока не готовы: «Тренировать мои ошибки» (из проверенных ошибок → Обучение), «Посмотреть диагностику» (из фаз/критических моментов → Анализ/Прогресс), контекстная подготовка к сопернику по публичному архиву. ИИ-тренер — поздний слой внутри разбора и обучения, не отдельный обязательный блок в каталоге.

Не добавлять в этот UX-цикл глубокую диагностику слабостей, репертуар дебютов, собственную библиотеку тренировок и запуск серверного Lichess cloud analysis.

## 10. Критерии дизайнерской приёмки перед будущим исполнительным ТЗ

1. Пользователь видит у завершённой партии **результат, соперника, свой цвет, собственную точность с источником или «Не оценено»** без раскрытия подробностей.
2. Левый pager целиком находится под левым списком. Глобальный «Назад» визуально и функционально отделён.
3. Выбор строки не запускает движок. Правые действия доступны только для действительно выбранной игры.
4. Правая панель разделяет **мою** точность и точность соперника; нет 0%/0 зевков при отсутствии анализа или смешения источников.
5. Фазы показывают реальный вычисленный результат либо «Нет данных».
6. Мини-график без маркеров каждого хода, с белой/тёмной заливкой вокруг нуля и достоверным покрытием; большой Review не теряет детализацию.
7. Автосинхронизация остаётся, ручное «Обновить архив» не отправляет повторные POST и не обходит 429/quota; дубли «Фон» и «Настройки загрузки» убраны из нижнего ряда.
8. На узком окне и DPI нет наложения текста и потери доступных основных действий, выбор/фильтры/scroll восстанавливаются.
9. Сохранённые заметки/экспорт PGN и остальные данные никуда не исчезают.
10. Защитные проверки Fair Play и account isolation имеют приоритет над красивой карточкой.
