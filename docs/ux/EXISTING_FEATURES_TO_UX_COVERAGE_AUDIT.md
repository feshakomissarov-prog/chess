### Реальные расхождения нынешней реализации с утверждённым UX

- **После online finish** код сейчас \`window.py::_show_result\` переключает \`screen_stack\` на отдельный \`ResultPage\`. **Требование владельца — удалить автоматический переход**, остаться в игровом workspace; справа только два добавочных primary actions **«Разобрать» / «Вызвать снова»**. Не рисовать summary card/alert/banner и не маскировать полностью доску. Основа source \`ResultPage\` может стать compatibility adapter, но **UX должен перестать на неё уходить**.
- **Главная сейчас \`HomePage(QScrollArea)\`** и содержит длинное раскрывающееся «Другие разделы и синхронизация». Будущий утверждённый dashboard без общей прокрутки и шесть навигационных пунктов; технические pilot actions переместить, не потерять.
- **Статистика сейчас большой \`StatisticsDialog(QDialog)\`**, не постоянная страница Прогресса; **пазлы сейчас \`PuzzleHistoryPage\` в диалоге**, не Обучение. Переносить без потери фильтров/повторений/выборки/рейтинг-тренда и без дублирования.
- **Локальная \`premove_training\`** и отдельный тестовый ход соперника легко теряются, если оставить в «Играть» только AI/link/username/free без «Дополнительные режимы».
- **В новой карточке партии уже согласован мини-график**, а существующие **заметки** и обновление конкретной партии из Lichess надо явно предусмотреть в деталях; не дублировать полный review graph с miniature, обязательно safety mask.
- **Существующий \`AdvantageBar\` УЖЕ РЕАЛИЗОВАН**, хотя по утверждённому UX-A2 его нужно сохранять как вертикальный индикатор оценки. График CP/Δ тоже существует. Это адаптация/preservation, не новая функция с нуля.
- **История и статистика пазлов** требуют входа из «Обучение → Задачи». По решению владельца **детальная переработка Учебного экрана откладывается**: пока может остаться тонкая совместимая страница/переход к нынешнему working puzzle UI.
- **Native rematch Lichess** не подтверждён существующими кодовыми методами. Имеются \`challenge_username\` и open challenge; поэтому «Вызвать снова» реализовать как **новый challenge тому же сопернику по явному клику** с допустимыми настройками и user consent. Если позже будет документированный серверный механизм предложения рематча, добавить его отдельно; не создавать бесконечную ложную анимацию «ждём приглашение» без event API.

## 2. Что НЕ считать уже реализованным

- **Дальняя подготовка к сопернику** на публичных последних 500 партиях — сохранена [отдельно](../research/OPPONENT_PREPARATION_LONG_TERM_FEATURE.md); **не code feature PR #44**.
- Полноценный интерактивный GPT-шахматный тренер, полноценные темы 263 компетенций, персональные учебные планы, репертуар и новый Opening Explorer — пока **стратегия продукта**, не работающая кнопка.
- Регулярная загрузка новых нерешённых задач Lichess — **не подтверждена** существующим \`puzzles.py\`; подтверждена синхронизация **истории прошлых попыток**. Не обещать новую задачу из Lichess как гарантированную функцию без API/источника.
- **Rematch event/listener** — не подтверждён кодом; доступен обычный challenge нового матча, если имя соперника известно.
- Не требовать удалять pilot diagnostics и тестовые режимы только ради минималистичного UX; их расположение — Advanced/сервис.

## 3. Предварительные продуктовые решения для пользователя

**Нужно согласовать отдельно ТОЛЬКО вопросы, меняющие пользовательское поведение:**
1. Отнести **«Тренировку предходов»** и тестовый ход соперника к *Играть → Свободная доска → Дополнительные режимы*, не к основной форме «Играть».
2. Пробные загрузки **5–10 партий/попыток**, технические checkpoint, отчёты и диагностику убрать с главной и держать в **«Настройки → Система / Диагностика → Дополнительно»** либо в контекстном «···» архива/истории задач. Это **перемещение**, не удаление.
3. **Заметки к партии** поместить в «Мои партии → Подробности → Заметки», сохранить и в полноэкранном разборе; **«Обновить одну партию из Lichess»** — в карточку меню «···», чтобы не загромождать.
4. **«Критические моменты / событие»** сделать вкладкой «Прогресс → Критические моменты» и deep links в Review, а **«Рейтинг задач / результаты повторений»** оставить в «Обучение → Задачи» с агрегатами также в Прогрессе.
