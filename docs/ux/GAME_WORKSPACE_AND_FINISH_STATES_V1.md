## 1. Утверждённая модель

1. **Один основной игровой workspace внутри единственного окна Chess Coach**: большая квадратная доска, явно различимые имена игроков, крупные часы **при наличии контроля**, единая панель ходов и контекстные действия в правой части. В игре без часов показать **«Без контроля времени»**, не 00:00. Слева меню автоматически может быть свёрнуто, но сохраняет глобальный «Вернуться к партии».
2. **После завершения игры НИЧЕГО НЕ ПЕРЕКЛЮЧАЕМ**: не переходить на ResultPage / в архив / в Анализ, не открывать popup, QDialog, баннер, карточку результата или прозрачный overlay поверх доски. Остаётся **та же доска с финальной позицией**, те же часы (заморожены) и список ходов; исторические ходы можно листать без модальных окон.
3. **Справа вместо активных игровых кнопок появляются только два новых явных основных действия:** **«Разобрать»** и **«Вызвать снова»**. Первое переводит по желанию игрока в тот же полноценный безопасный ReviewWorkspace (после preflight), второе создаёт **новый вызов только по явному клику** с доступным контекстом предыдущего соперника. Оба действия могут быть доступны сколько нужно, пока пользователь остаётся на завершённой доске. **Никакой отдельной сводки результатов** или обязательного popup «Победа/Поражение»; если статус нужно сообщить, достаточно компактной подписи в **существующей** status line («Партия завершена · 1–0»), без расширения layout.
4. **Можно ждать инициативы соперника** на оставшейся странице. При реально документированном событии нового вызова/рематча от этого игрока приложение может добавить **ненавязчивое** inline-предложение «Принять / Отклонить», **не автоматически принимать**. Если официальный сервер не предоставляет такого события, нельзя имитировать ожидание бесконечным spinner/timer/ложной кнопкой: «Вызвать снова» отправляет обычный доступный challenge тому же Lichess username при его наличии.
5. **Безопасность:** новый engine/score bar/graph **не запускаются и не открываются по факту завершения**. Действие «Разобрать» требует свежего полноценного Fair Play preflight; оно заблокировано, если параллельно идёт онлайн-партия с человеком или статус неопределён. Во время активной человеческой игры в игровом UI отсутствуют оценка, PV, ошибки, график и подсказки. Произвольное открытие внешнего PGN также не обходит общее правило.
6. **Игровые спецкоманды на виду — решение владельца 04.11:** в постоянно видимом правом блоке «Управление», рядом со списком ходов, находятся «Возврат хода» (запрос/принять/отклонить), «Предложить ничью» / входящее «Принять» / «Отклонить», «Сдаться» (с подтверждением) и прочие поддерживаемые по правилам состояния команды (например, claim draw). **Не убирать их в «···» и не заставлять искать кнопку**, даже если она редко используется. Состояние каждой команды определяется активной сессией и разрешениями Lichess/режима; не поддерживается — недоступна с понятной причиной/не показывается. Обычные premove и отмена сохраняются как сейчас; **тренировка предходов как отдельная пользовательская функция не нужна**. Flip, звук, отмена ожидающего вызова, локальная отмена и выбор активной игры остаются доступны по контексту.
7. **Звуки полностью AS-IS:** start/move/capture, notifications, preview, choice/defaults and settings (см. UX coverage). Нельзя менять catalog/WAV/default sound IDs и события воспроизведения ради нового layout.

## 2. Markdown wireframe — обычная партия С ЧАСАМИ

```text
┌────────────────────── CHESS COACH / ИГРАТЬ ──────────────────────────────┐
│ ☰  Партия с Player42 · Lichess · 3+2      ● Подключено     [Главная]    │
├─────────────────────────────────────┬──────────────────────────────────┤
│ Соперник · чёрные          [03:21]   │ ХОДЫ                             │
│ ┌─────────────────────────────────┐ │  1. e4         c6                │
│ │                                 │ │  2. d4         d5                │
│ │          ШАХМАТНАЯ              │ │  3. Nc3        dxe4              │
│ │             ДОСКА               │ │  ...                             │
│ │                                 │ │                                  │
│ └─────────────────────────────────┘ │ Ваш ход · 3+2                     │
│ Вы · белые                [02:49]   │                                  │
│                                     │ УПРАВЛЕНИЕ                       │
│                                     │ [Возврат хода]                   │
│                                     │ [Предложить ничью] [Сдаться]     │
│                                     │ [Принять/Отклонить]*             │
└─────────────────────────────────────┴──────────────────────────────────┘
Поля/ходы/цифры в макете условны; фактические chess positions только от модели.
```

\* Ответные действия отображаются при подтверждённом входящем предложении; прочие специальные команды находятся в том же видимом блоке, когда доступны, без обязательного «Ещё».

Сверху **соперник и его часы**, снизу **игрок и его часы** — при перевороте доски порядок связан с визуальной ориентацией на доске, не жёстко с цветом. Боковая панель занимает остаток ширины, её список ходов имеет **свой скролл**, весь экран — нет. При небольшой ширине сначала сворачивать sidebar/сокращать второстепенную метаинформацию, не часы.


Варианты: при **Lichess AI** второй глагол можно показать как «Играть ещё с AI» (тот же логический action и настройки, но новый create_ai_game), при свободной локальной доске — «Новая локальная партия», при известном human nickname — **«Вызвать снова»** и подтверждённый новый challenge. Если соперник не определён либо API запрещает вызов, action disabled с объяснением, не пустая кнопка.

### После завершения: подробные переходы и edge cases

- `playing→finishing`: дождаться авторитетного `gameFinish/gameState` (или локального исхода в изолированном режиме), не принимать собственное предположение в качестве серверного окончания. Freeze time only on final authoritative event, локальный remaining может быть «—» если нет подтверждения.
- `finished`: та же route и same board widget; кнопки online move/draw/resign/takeback disabled/hidden; ходовая навигация доступна; **ровно два новых главных действия**. Внешние сохранённые команды «PGN», «Вид доски» или «Перейти в мои партии» допустимы в компактном «···» или глобальном меню, **не** как ещё 4 главные кнопки рядом с разбором.
- `incoming rematch/new challenge`: показывать inline маленькие кнопки accept/decline **только при реальном подтверждённом событии от сервера** и user consent. Пока серверный event не подтверждён — ничего не показывать и не крутить «Ожидаем…». Старые/outdated invite после switch account игнорировать.
- `outgoing again`: по нажатию «Вызвать снова» разрешённый documented challenge, защита от двойного клика, status/Cancel в контекстной области; новый `game_id` означает новый матч, обновляются часы/start sound; **не перезапускать старый game_id**.
- `review`: по «Разобрать» перейти в утверждённое Анализ → Разбор; safety gate прежде данных графика, без engine автозапуска. Должен работать «Вернуться к игре» пока session существует.
- `normal navigation`: «На главную», «Мои партии», «Играть» не удаляют сохранённую завершённую партию; после возврата можно открыть историю с корректным game_id.
- `AI/local`: не делать вымышленный Lichess rematch; «Вызвать снова» имеет контекстный label/action. User с параллельной активной human игрой не получает право на engine review.
- `reconnect`: сохранённый экран окончания не переходит сам в другой view по stale game state, generation/account guarded. Если official server говорит game still live, строго перейти к live state только после authoritative reconciliation.

## 5. Шахматные часы, ходы и UI состояния

- До серверных часов: «Ожидание часов Lichess» без обратного отсчёта. После authoritative snapshot локальная монотонная интерполяция с правильным `+2` и только один инкремент по подтверждению.
- Активные часы большими цифрами и заметным контрастом, обе стороны всегда одновременно видны. В режиме reconnect — «Уточняем часы», не уверенная неправильная цифра.
- Clock absent → «Без контроля времени», не скрывать соперника и не помещать «00:00». При завершении/таймауте остановить часы.
- Список ходов — локальный scroll, текущий полуход/выбор (допустимые действия), premove и cancel без скрытых engine подсказок. Передать право отрисовки Qt без повторной сетевой подписки при смене вкладок.
- Главное меню остаётся доступным/свёрнутым, но уход со страницы сам по себе **не сдаёт матч**. Фокус доски и keyboard controls возвращаются, видна текущая активная партия или список нескольких, если их больше одной.
- Масштаб целевого ноутбука: 1280×720, 1366×768, 1920×1080, font DPI; не скрыть buttons из-за 2 часов/масштаба. Не делать floating windows.

## 6. Реализованные функции, которые нужно сохранить

Подробная source-backed карта: [EXISTING_FEATURES_TO_UX_COVERAGE_AUDIT.md](EXISTING_FEATURES_TO_UX_COVERAGE_AUDIT.md). **Пока партия активна**, справа в одном всегда видимом блоке находятся уместные takeback/draw/resign/accept/decline, а premove и отмена работают как сейчас. Отдельный режим тренировки предходов не включать в новый UX. **Когда партия завершена**, запрещённые игровые команды исчезают/отключаются и на том же месте появляются «Разобрать»/«Вызвать снова» — без отдельного результата. Остальные вспомогательные функции (flip/звук/PGN) сохраняются вторично; пробный импорт не является элементом игрового UX.

## 7. Критерии будущей реализации

- Проверка реального кодового пути `_show_result`: **не должен менять stack page**; видимы те же board instance, clocks, right history и только новые CTA. Не создавать лишний `ResultPage`. В активной игре side controls для takeback, предложения/ответа на ничью, сдачи находятся на виду; fake tests доступности/disabled/confirm для human, AI, no-clock и reconnect. Не прятать в «···».
- Автотесты: AI/human and timed/no-clock, finish by mate/resign/draw/timeout, different source generations, no after-game Stockfish, late events ignored, challenge again single-click, real account reconnect fake, saved state and navigation return. Fake Lichess/engine/SQLite only.
- UI pixel/geometry at standard Windows DPI; physical user pilot on real computer, sound audibility and rematch only if API supports it. No CI real OAuth/PAT/Stockfish.
- **Реализация:** этот контракт включён в единое [ARCH-UX-01](../specs/ARCH_UX_01_UNIFIED_EXECUTION_SPEC.md); запуск Codex только после передачи владельцем, без самостоятельного merge.
