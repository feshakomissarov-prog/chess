# Chess Coach — Product Requirements Document (PRD)

**Версия:** 0.5 (утверждённая пользовательская оболочка ARCH-UX-01, 2026-11-04; исторические M0–M4 требования сохранены ниже)\
**Статус:** основа для итеративной реализации; детали каждого модуля уточняются непосредственно перед его разработкой\
**Платформа:** Windows\
**Связанный документ:** [PCD](PCD.md) · **текущее исполняемое ТЗ:** [ARCH-UX-01 v1.1](specs/ARCH_UX_01_UNIFIED_EXECUTION_SPEC.md)

**Стратегическая цель (выше MVP):** [полноценный тренер по всем шахматным направлениям](PRODUCT_VISION.md) — диагностика пробела, доказуемое объяснение, проверка понимания, индивидуальная тренировка и закрепление. MVP ниже является лишь фундаментом, а не ограничением продукта голосом, статистикой или отдельной функцией.

## 1. Назначение и границы

Настольное Windows-приложение с **шестью утверждёнными рабочими разделами**: **Главная**, **Играть**, **Мои партии**, **Анализ**, **Обучение** (в том числе задачи), **Прогресс**; **Настройки отдельно внизу** левой навигации. Старые четыре раздела — историческая формулировка до согласования UX 04.11.2026.

Первая техническая линия M0–M4.6 уже внедрила игровой клиент Lichess, локальную библиотеку/аналитику и историю задач. **Запись/расшифровка рассуждений и обучающий ИИ-диалог ещё не реализованы и не входят в ARCH-UX-01**; полноценно адаптивную программу тренировок проектируем отдельно.

Данные партии можно получить (а) во время игры через Chess Coach, (б) синхронизацией из Lichess, (в) импортом PGN. Отсутствие аудио у импортированной партии — нормальная ситуация, а не ошибка.

## 2. UI/UX — общие требования

**UI-01.** Приложение имеет **одно главное окно Windows** и шесть внутренних рабочих маршрутов «Главная / Играть / Мои партии / Анализ / Обучение / Прогресс», настройки отдельно внизу. Всегда видны статус Lichess, существующая активная партия/команда возврата и доступ к фоновым операциям. Нет отдельных обычных OS-окон для каталога/статистики/просмотра.

**UI-02.** Главный экран игры включает **одну постоянную доску**, имена игроков, при наличии часы, список ходов, статус сети и **видимый справа блок** поддерживаемых команд (takeback, предложение/ответ на ничью, сдача). Статус микрофона появится только в будущем голосовом модуле. После подтверждённого finish остаётся та же доска с ходами, справа «Разобрать» / «Вызвать снова», **без отдельного ResultPage**. При изменении размера окна сохраняется удобочитаемость и доступность команд.

**UI-03.** Шахматная доска в стиле предоставленного автором референса: тёплые бежевые/коричневые поля, классические чёрные и белые фигуры, подписи координат. Точные цвета и набор изображений согласуем на работающем экране. Не копировать неподходящие по лицензии спрайты Lichess/Chess.com.

**UI-04.** Фигура перемещается мышью (выбор клетки и целевой клетки; перетаскивание желательно, но можно добавить следующим коммитом). Видно последний ход и выбранную клетку. Включаемая подсветка доступных ходов допустима как отображение шахматных правил без оценки качества хода.

**UI-05.** Вручную рисуются стрелки и выделяются клетки **правой кнопкой мыши** (правый drag = стрелка, правый клик = выделение). Владелец попросил **не менять** этот способ до отдельной проверки; Shift-комбинации сейчас не требуются. Автоматические подсказочные стрелки в онлайн-партии недопустимы.

**UI-06.** Пользователь может перевернуть доску; координаты корректно соответствуют ориентации; превращение пешки выбирается явно.

**UI-07.** Во время онлайн-партии с человеком отсутствуют: шкала и численная оценка, график (в том числе **мини-графики архива/Home**), PV/лучший ход Stockfish, категории ошибок, ИИ-подсказки и производная от движка помощь. Эти вычисления **не запускаются**, а кешированные результаты **синхронно маскируются** на всех маршрутах при fail-closed состоянии (human live, неизвестная полная snapshot, reconnect/429/auth revoke); после завершения разбор разрешается только после свежего preflight.

## 3. Lichess и проведение игр

**GAME-01.** Вход через официальный OAuth; пароль Lichess не запрашивается. При повторном запуске приложение использует сохранённую авторизацию с возможностью выхода.

**GAME-02.** Пользователь выбирает игру с другом (ссылка или по имени), игру против компьютера и поддерживаемый контроль времени/цвет; рейтинговость доступна только для поддерживаемых API сценариев.

**GAME-03.** При создании открытого приглашения ссылка копируется для отправки вне приложения. Друг открывает Lichess в обычном браузере; пользователь играет через Chess Coach. **Требует проверки API:** для открытых приглашений процесс присоединения создателя и режим без обычного таймера нельзя считать заранее подтверждённым.

**GAME-04.** Для поддерживаемых игр клиент получает обновления позиции и ходов из Lichess, отправляет собственные легальные ходы и показывает состояние завершения.

**GAME-05.** Клиент различает мат, пат, сдачу, истечение времени, ничью, прерывание, отключение и другие статусы API. При временной потере связи показывает состояние и пытается восстановить позицию; не придумывает неподтверждённый результат.

**GAME-06.** Ходы, метаданные и результат сохраняются локально по мере получения. На завершении партии делается проверка и фиксация финального состояния.

**GAME-07.** Рейтинговые и нерейтинговые партии из Lichess хранятся и анализируются одинаково; нельзя считать рейтинг обязательным для учебной статистики. Дополнительные PGN, в том числе выгрузки Chess.com, поддерживаются импортом.

**GAME-08.** В живой партии различать: отмену неисполненного premove (локально), возврат подтверждённого хода против Lichess AI (takeback на сервере) и предложение возврата человеку (зависит от согласия второго игрока). Сервер — единственный источник истинного состояния. Пользователь видит кнопку «Вернуть ход» с AI и «Предложить вернуть ход» с человеком. Нельзя проводить локальный откат уже подтверждённого Lichess хода без сервера.

**GAME-09.** Предход выполняется после хода соперника, **если остаётся легальным**, даже если ответ соперника был неожиданным. Интерфейс предоставляет явную отмену очереди и опциональное отключение premove; это не разновидность условного хода.

## 4. Микрофон и голосовые фрагменты

**AUDIO-01.** Записывать только выбранный пользователем микрофон, не системный звук.

**AUDIO-02.** Автоматическая сегментация начинается после первого хода белых. Каждое следующее изменение позиции завершает текущий фрагмент и начинает новый, если запись активна. Пауза, ручное отключение и отсутствие микрофона поддерживаются. Игра не зависит от работы записи.

**AUDIO-03.** Каждый фрагмент хранит идентификатор партии, номер полухода, FEN позиции на момент начала фрагмента, начало/конец записи и путь к временному файлу. Запись в ходе ожидания соперника тоже может содержать рассуждения об ожидаемом ответе.

**AUDIO-04.** Сегменты сначала надёжно сохраняются локально. После завершения партии отдельная очередь задач выполняет распознавание русского языка; хранит текст и статус для каждого сегмента. Новую партию разрешено начинать немедленно.

**AUDIO-05.** Успешно расшифрованный, записанный в БД и проверенный на целостность фрагмент можно автоматически удалить. Ошибочные фрагменты не удалять до успешного повтора/решения пользователя. Нулевые/беззвучные сегменты можно не хранить.

**AUDIO-06.** Сбой распознавания, нехватка памяти, закрытие приложения или потеря связи не должны уничтожать уже сохранённые ходы и завершённые аудиосегменты.

## 5. Локальная библиотека

**LIB-01.** SQLite содержит источник, ID партии (если есть), дату, соперника, цвет, результат, контроль времени, список ходов/PGN, доступные данные часов, комментарии, статусы обработки и разбора.

**LIB-02.** Поддержать уникальность (источник + исходный ID, либо иной надёжный ключ), чтобы повторный импорт не дублировал партии.

**LIB-03.** Фильтрация и поиск как минимум по дате, сопернику, результату, источнику, статусу и рейтинговости. Старые партии не удалять автоматически.

**LIB-04.** Статусы: новая / обрабатывается / готова к разбору / разобрана / ошибка. Учитывать отдельно техническое завершение движкового расчёта и завершение пользователем учебного разбора.

**LIB-05.** Импорт PGN доступен без авторизации Lichess. Для импортированных партий голосовые комментарии могут отсутствовать.

## 6. Базовый шахматный анализ — только после окончания игры

**ANA-01.** Stockfish запускается для завершённых партий и отдельных офлайн-позиций, с сохраняемыми параметрами расчёта (версия, лимит времени/глубина).

**ANA-02.** Показывать список ходов, варианты, график оценок и важные изменения; классификацию неточностей, ошибок и зевков осуществлять по заранее документированной методике.

**ANA-03.** Если отображаются точность или средняя потеря в сантипешках, обязательно указывать метод расчёта и не приравнивать их к рейтингу или оценке общей шахматной силы.

**ANA-04.** Пользователь может выбрать позицию и сохранить свой вопрос. Автоматические точки интереса и предложения тренера появляются только после окончания онлайн-партии.

**ANA-05.** Учебный разбор допускает режим «сначала мой ответ, потом подсказка движка» и привязку первичных голосовых расшифровок к ходам.

## 7. ИИ-тренер — в последующем модуле

**AI-01.** Языковая модель получает структурированные данные: FEN, список ходов, проверенные результаты Stockfish и относящиеся к позиции записи/текст. Скриншот не является обязательным входом.

**AI-02.** ИИ задаёт вопросы, помогает сравнивать варианты и формулирует осторожные гипотезы, но не выдаёт отсутствующую в комментарии мысль за факт.

**AI-03.** Первоначальный план — опциональный OpenAI API-ключ пользователя; подписка ChatGPT не обеспечивает автоматическую оплату API. Ключ не помещать в git и логи.

**AI-04.** Работа ИИ необязательна для игры и локального анализа Stockfish.

## 8. Нефункциональные требования

**NFR-01.** Windows; разрабатываем на Python + PySide6 + python-chess; стек остальных компонентов на стадии выбора.

**NFR-02.** Интерфейс должен оставаться отзывчивым; сетевые запросы, Stockfish и транскрипция не блокируют главный UI-поток.

**NFR-03.** Локальное хранение данных и устойчивость к сбоям; секреты — в защищённом хранилище ОС или иной безопасной конфигурации вне репозитория.

**NFR-04.** Тестируемая логика отдельно от UI; интеграция с Lichess через выделенный слой, чтобы тесты не требовали реальных сетевых запросов.

**NFR-05.** Перед переносом кода или ассетов сторонних проектов проверяется лицензия. Прямое копирование шахматных фигур по картинке-референсу без прав недопустимо.

**NFR-06.** Исходный проект запускается в Windows из подготовленного окружения; переносимый .exe желателен на этапе сборки, но не обязателен для первого UI-прототипа. Для ежедневного использования требуется безопасный Desktop .lnk, запускающий `.venv\\Scripts\\pythonw.exe -m chess_coach` без консоли и прав администратора.

**NFR-07.** Автоматические GUI/Qt-тесты выполняются offscreen и не открывают видимых окон; тесты изолированы, один реальный GUI smoke делается отдельно. Сетевые операции и дорогостоящая генерация PGN/SQLite не должны надолго блокировать Qt. Регрессии измеряют отзывчивость click-click, drag, premove и обновления большой истории.

## 9. Первый инкремент для Codex: M0 — игровой интерфейс и доска

**Каноническое детальное ТЗ:** [M0_BOARD_UI.md](specs/M0_BOARD_UI.md); в случае расхождения кратких требований этого PRD с конкретными сценариями M0 применять более детальную согласованную спецификацию M0.

M0 использует выбранный владельцем `leszekhanusz/chess-widgets` как основу доски в Windows-окне PySide6, в стиле визуального референса автора, **оба способа перемещения (клик-клик и drag-and-drop)**, **предходы (premove) с тестовым источником хода соперника**, ручные стрелки и выделения, историю с навигацией, меню настроек, переворот доски, выбор превращения пешки и ограничения online fair play. Звуки необязательны.

Подключение к реальному Lichess и иные сетевые функции не входят в M0. До реализации изучить [обзор готовых компонентов и выбранную библиотеку](BOARD_COMPONENT_REVIEW.md) и правила [AGENTS.md](../AGENTS.md). В M0 требуется только небольшой интерфейс между контроллером и отображением, чтобы позже подключить сетевой источник без переписывания доски.

**Приёмка:** отдельная матрица AC-01..AC-20 в [спецификации M0](specs/M0_BOARD_UI.md), автоматические проверки и ручная приёмка владельцем на Windows.

## 10. Следующие инкременты

- **M1 — технический Lichess spike:** OAuth, реальные события, создание приглашения, присоединение к партии из клиента, базовая обработка ошибок; отдельно проверяем режим без часов.
- **M2 — рабочий онлайн-клиент:** синхронизация доски с Lichess, отправка ходов, часы и завершение игры, локальная запись PGN/данных.
- **M3 — аудио и БД:** сегменты по позициям, очередь распознавания и правила очистки.
- **M4 — библиотека + Stockfish:** импорт, статусы, аналитика завершённых игр.
- **M5 — интерактивный разбор:** выбранные позиции и первые механики обсуждения.
- **Далее:** качественный ИИ-тренер, персональные упражнения и показатели прогресса.

Обоснование этапов и точки проверки см. в [ROADMAP](ROADMAP.md).


## 11. Уточнение приоритетов — архив, анализ и мысли (31.10.2026)

Владелец изменил порядок реализации после M0–M2: **сначала полная локальная база и импорт, затем анализ, потом голос и планы на доске**. Ранее M3 назывался голосом; с этой даты **M3 = архив+импорт, M4 = postgame Stockfish/точность, M5 = голос+рисунки, M6 = будущий персональный тренер**. Детальные acceptance criteria и миграции — **[отдельное ТЗ](specs/M3_M4_ARCHIVE_ANALYSIS_VOICE_THOUGHTS.md)**; это дополнение не отменяет общие требования этого PRD.

- **LIB-06:** сохранить существующую SQLite `games` и личные PGN без потери, добавить schema migration/versioning и локальную библиотеку всех завершённых партий. Источники данных/расчётов различимы.
- **LIB-07:** Lichess `GET /api/games/user/{username}`: первоначальная потоковая выгрузка с checkpoint, затем только новые/изменившиеся (с небольшим overlap, idempotent upsert). Не загружать весь архив при каждом старте. Отдельно активные игры через `/api/account/playing`. Не делать массовый импорт без действия пользователя.
- **ANA-06:** график Stockfish по полуходам **только после партии**, сохранение рассчитанных результатов; Lichess `accuracy` показывать только когда сервер прислал данные, иначе собственную оценку маркировать отдельно и описывать методику. Никакой фоновой шахматной помощи при игре с человеком.
- **AUDIO-06:** каждый новый подтверждённый ход меняет позиционную привязку аудио, **с первого хода белых**; запись только микрофона пользователя, локальные файлы и восстановление после сбоев.
- **THOUGHT-01:** right-click/right-drag — ручные пометки; **после каждого подтверждённого хода** визуально исчезают стрелки/круги. В будущих данных хранить события add/remove/clear, позицию `game_id/ply/FEN/line_revision`, порядок и время.
- **THOUGHT-02:** несколько планов A/B/… связываются с аудио/транскриптом через общую временную линию; старые мыслительные ветки не уничтожаются при takeback. Воспроизведение не смешивает варианты в один кадр.
- **THOUGHT-03:** будущий ИИ получает **локально собранный структурированный пакет**, а не скриншот с неоднозначными стрелками. Автоматической отправки аудио/текста в облако пока нет.
- **NFR-08:** технический долг [#5](https://github.com/feshakomissarov-prog/chess/issues/5) — Windows/Python 3.12, безопасное offline QA, OAuth, Dr.Web/ярлык и E2E. UX-ошибка пометок — [#7](https://github.com/feshakomissarov-prog/chess/issues/7); общий эпик — [#6](https://github.com/feshakomissarov-prog/chess/issues/6).

**Не объединять в один PR:** раздельная приёмка P0 (баги), P1 (база), P2 (синхронизация), P3 (анализ), P4 (мысли/голос), P5 (локальный экспорт). Визуальный редизайн — отдельная задача.

**Обязательная архитектура и приёмка:** [M3_M4_DATA_ARCHIVE_ANALYTICS_PUZZLES.md](specs/M3_M4_DATA_ARCHIVE_ANALYTICS_PUZZLES.md). Уточняет раздел 11 и заменяет прежний порядок этапов P3/P4: **голос отложен до M5**, а в **M4** входят анализ, общая статистика и история личных задач.

- **DATA-01:** одни `games.sqlite3` и таблица `games` без потери существующих записей, миграции с атомарными транзакциями, backup и откатом.
- **DATA-02:** отдельные `game_moves`, `game_positions`, `game_notes`, связи по `game_id + line_revision + ply`. Стабильная привязка будущих мыслей и редактор заметки к позиции.
- **SYNC-01:** потоковый первый импорт завершённых игр Lichess с backfill/checkpoint, затем incremental только новых и изменившихся; дубликаты исключены.
- **ANALYSIS-01:** локальный Stockfish (UCI) после завершённой партии, версионирование и кэш оценок, график `ply=0..N`, white POV и mate отдельно, честная информация об отсутствии официальной accuracy.
- **STATS-01:** аналитическая витрина: ошибки, неточности, blunders, колебания оценки, частота на 100 реально оценённых ходов, по дебюту/миттельшпилю/эндшпилю/контролю/периоду с coverage и методологией.
- **PUZZLE-01:** отдельная история **собственных** задач Lichess `/api/puzzle/activity` (scope `puzzle:read`), попытки многократного решения, `/api/puzzle/dashboard/{days}`, локальная статистика; не скачивать весь публичный банк.
- **NFR-09:** запрет запуска Stockfish и показа шахматных подсказок во время активной игры с человеком, отдельная безопасная проверка OAuth scopes, без автоматического массового импорта.

**Доставка:** одно большое ТЗ, последовательные небольшие блоки и отдельные reviewable PR; merge только по решению владельца.

## 13. Решение владельца о модели тренера и порядке будущей разработки (02.11.2026)

**Более актуальное стратегическое решение, чем устаревшие схемы из §10–12:** Chess Coach рассматривается как будущий персональный агент-тренер: объяснение сложных закрытых позиций, пешечных структур, позиционной разницы в размещении фигур, наказания за потерю темпа и других шахматных причин с примерами и проверкой понимания. Он не сводится к обнаружению ошибок в партиях.

**Методология согласована:** [модель A × (B1+B2) → C → D → E](research/CHESS_COACH_APPROVED_COMPETENCY_MODEL.md), отдельные [9 направлений для последующего исследования](research/CHESS_COACH_NINE_FOLLOWUP_DIRECTIONS.md). Навыки, которые трудно объективно диагностировать по PGN, не следует автоматически вычёркивать; использовать интерактивные тесты, добровольные объяснения и `unknown` при недостатке свидетельств. Карту знаний/обучения прорабатывать до отдельного обучения/персонального планирования.

**Последовательность пожеланий (ещё не утверждённое новое ТЗ):** после приёмки M4.6 рассмотреть большой блок с фоновым продолжением недосчитанных анализов от новых партий и локальной Training Arena со Stockfish, контролем силы, игрой из позиции и обратной связью. Уже имеющийся bounded batch runner надо расширять осмысленно, а не реализовывать с нуля. Персональные расписания — лишь после методологически убедительной диагностики. ИИ-тренер с объяснениями — содержательный поздний модуль, **голос/записи мыслей после ИИ-тренера**, а не прежний обязательный M5 перед ним. Упоминания прежнего порядка в §4/§10–12 хранятся как история решений, не как актуальный порядок.

**Способ управления:** одно крупное согласованное техническое задание для Codex с подэтапами, checkpoint и независимым ревью; не дробить без причины на множество отдельных milestone/PR. Дальнейшие номера и roadmap **не утверждены**; ROADMAP пока не изменять. Приёмка PR после CI, независимого код-ревью и ручного Windows-пилота владельца. Fair Play: ни engine/AI hints, ни раскрытие PV во время онлайн-игры с человеком. Будущая возможность бесплатно поделиться локальным продуктом допускается, коммерциализация не предполагается автоматически.

## 14. ARCH-UX-01 v1.1 — обязательные требования к следующей реализации (04.11.2026)

**Приоритет:** [единое исполняемое ТЗ](specs/ARCH_UX_01_UNIFIED_EXECUTION_SPEC.md) и [предстартовый аудит](reviews/ARCH_UX_01_PRE_FLIGHT_AUDIT.md) выше исторических ранних MVP/голосовых milestone в этом файле. Исходная готовая архитектура — [draft PR #44](https://github.com/feshakomissarov-prog/chess/pull/44), документация требований — [draft PR #45](https://github.com/feshakomissarov-prog/chess/pull/45).

- **UI-08 — Главная:** четыре смысловые области (включая sidebar), без общего scroll, 2–3 подтверждённых KPI и честный небольшой тренд, одно действительно доступное действие из существующих повторяемых задач/упражнений, три последние **завершённые** партии. Не подменять историю решённых задач новыми.
- **UI-09 — Играть:** одна встроенная форма AI/друг по ссылке/ник/свободная доска, актуальные параметры, без дополнительной «Тренировки предходов». Обычный premove и его отмена остаются.

- **UI-11 — Мои партии:** компактный верх sync, закреплённые активные, виртуализированный список завершённых с локальным scroll, фильтры справа, подробности с целым сохранённым мини-графиком, provenance+coverage+Fair Play. Заметки вторично; единичный Lichess refresh — recovery, пилотный import UI отсутствует.

Сценарии на 1280×720, 1366×768, 1920×1080 и DPI проверяются без требования выдуманного FPS/p95 SLA.
