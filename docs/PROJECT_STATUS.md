## 1. Что такое Chess Coach

Локально ориентированное Windows-приложение на Python/PySide6 для игры в шахматы и будущего разбора **собственных мыслей во время партии**. Долгосрочная цель: Lichess → голосовые записи по изменениям позиции (включая первый ход белых) → локальный архив → postgame Stockfish → персональный диалог и упражнения с ИИ. Никаких движковых/ИИ-подсказок во время сетевой игры против человека.

**Уже кодируется:** доска `leszekhanusz/chess-widgets==0.5.0`, адаптер `BoardView`, локальный `GameController`, OAuth PKCE Lichess и Windows Credential Manager, Board API, потоки NDJSON, игра по ссылке/по имени/против Lichess AI, часы, стрелки правой кнопкой, premove, takeback, локальный SQLite и PGN, Home/Game/Result/Review. Всё это **пока в PR, а не обязательно в main**.

**Ещё НЕ реализовано / не принимаем за готовое:** аудиофиксация, Whisper/расшифровка, Stockfish postgame, ИИ-тренер, полноценная библиотека/аналитика, Chess.com, финальный визуальный дизайн, Windows EXE-инсталлятор. Ярлык Desktop — новая отдельная задача.

## 4. Текущие пожелания владельца / новая задача

1. **Вернуть ход после ошибки в AI-партии.** Владелец потерял ферзя, потому что обычный premove сыграл, хотя компьютер сделал неожиданный (но не делающий premove нелегальным) ход. Это ожидаемое правило premove; пользователь просит удобный takeback. Lichess AI возвращает ход через сервер; в человеческой игре предложение должно быть принято соперником. Не подменять сервер локальной историей.
2. **Автотесты не должны мигать окнами.** Исполнять Qt-тесты **offscreen**, сохраняя изоляцию между тестами; один обычный GUI smoke как отдельная проверка. Использовать постоянный PowerShell; выяснить происхождение всплывающих `cmd.exe`, если повторится. Не превращать 78 независимых тестов в один stateful widget.
3. **Подлагивания управления мышью.** Проверить полную цепочку click-click, drag, pending server move, queued premove и обновления экрана, включая `BoardView.set_position` с unconditional `set_board`, `MainWindow._refresh_online` с пересборкой SAN и синхронную SQLite/PGN запись в GUI thread. Причины торможений требуют измерения, а не гадания.
4. **Ярлык на рабочем столе Windows.** По двойному щелчку открывать Chess Coach напрямую через `.venv\Scripts\pythonw.exe -m chess_coach`, без консоли, админ-прав, EXE-инсталлятора или изменения автозапуска. Создание ярлыка — явный, безопасный шаг владельца/штатного скрипта.
5. **Внешний вид:** текущий дизайн пока допустим как прототип; **полный редизайн отложен**. Не менять управление ручными стрелками правой кнопкой (владелец просил оставить).
6. **Безопасность:** были короткие чёрные консольные окна и блокировка в **Dr.Web** 2026-10-31 20:06 «Поведенческий анализ: доступ к защищаемому объекту заблокирован». Причина и файл **не установлены**. Codex ранее проверял журнал Defender, что не является проверкой журнала Dr.Web. **Не отключать антивирус и не делать исключения.**

## 5. Архитектура, которую нельзя ломать

- Online authoritative state: только серверная `LichessGameSession.board` и подтверждённые stream events, не визуальный BoardWidget.
- Pending собственный ход допускает оптимистичный render-only overlay; PGN/SQLite не меняются до серверного подтверждения.
- Premove — intent, после хода соперника проверить шахматную легальность и отправить один раз. Premove **не требует** угаданного ответа противника, если ход остался легален.
- Takeback против AI/человека — исключительно Board API `/api/board/game/{gameId}/takeback/yes|no` с подтверждённым `gameState`, способным сокращать ходовую линию.
- При финале `gameFinish` до `gameState` статус терминальный, но `final_sync_pending` восстанавливает последний ход и PGN. Нельзя терять финальные ходы или повторять запросы при 429.
- OAuth PKCE и keyring/Windows Credential Manager: не писать токены/пароли в git/log/chat. SQLite в Windows AppData.
- Правообладатели: код chess-widgets MIT, SVG pieces отдельно, python-chess GPL-3.0-or-later; итоговую лицензию не объявлять без проверки.

## 8. Выполнение стабилизации PR #3 — 2026-10-31

Работа выполнена в ветке `codex/m1-lichess-client`; PR #3 остаётся draft и направлен в `codex/m0-chess-widgets`. Изменения ожидают публикации и повторного ревью.

- Добавлены отдельные действия локальной отмены последнего хода и официального takeback Lichess AI; настройка premove выключает очередь и поддерживает выбор Q/R/B/N при превращении.
- Ускорены обновления доски и списка ходов; снимки партий/PGN сохраняются последовательной фоновой очередью SQLite, ошибки записи отображаются и допускают повтор.
- Qt тесты принудительно используют offscreen и временный каталог данных на каждый тест.
- Добавлен безопасный скрипт создания Desktop ярлыка и stack-only crash log для запуска через `pythonw.exe`. Ярлык фактически создан: `Chess Coach.lnk` у владельца указывает на локальный `.venv\Scripts\pythonw.exe`.
- Проверено локально на Windows с Python 3.11.5: **95 тестов прошли**; `compileall` прошёл; `git diff --check` прошёл, Git сообщил только предупреждения о нормализации LF/CRLF.
- Python 3.12+ недоступен в данной среде и не проверялся.
- PowerShell отказался запускать скрипт ярлыка из-за действующей execution policy. Политика не менялась, обход не применялся; ярлык был создан стандартным COM через уже запущенный PowerShell после проверки цели и конфликта.
- Однократный запуск окна через ярлык был начат с временной переменной PowerShell, но запуск через Проводник её не унаследовал. Приложение восстановило сохранённую OAuth-сессию, показало ожидающий ход, после чего доска обновилась серверными событиями. Я вручную ходы не вводил; нельзя исключить отправку ранее ожидавшего хода при восстановлении. Окно штатно закрыто. Владельцу следует проверить результат партии в браузере. Это не приёмочный E2E-тест и дальнейшие сетевые действия не выполнялись.
- Реальная Lichess AI партия/takeback **не проверялись**. Не получена проверяемая последовательность авторизованной тестовой партии, завершения и локального PGN.

**Ручная приёмка:** владельцу проверить запуск двойным щелчком по ярлыку в обычной сессии, drag/click, предход, локальное сохранение, а затем отдельно по разрешению провести AI takeback и проверить PGN. Перед первым запуском убедиться, что тестовая/реальная сохранённая онлайн-сессия не должна автоматически возобновляться.
