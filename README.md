# Chess Coach

**Персональный шахматный тренер: от непонятной позиции — к пониманию и навыку.**

Chess Coach — разрабатываемое настольное приложение для Windows. Цель проекта — **помогать человеку разобраться в любом шахматном вопросе**, а не только находить неудачные ходы: тактика, дебюты и ловушки, стратегические планы и структуры, типы позиций, эндшпили, расчёт вариантов, ошибки оценки и принятия решений.

Тренер должен уметь **найти конкретный пробел → объяснить причину на доске → проверить, понял ли игрок → предложить упражнения → убедиться, что навык закрепился**. Это долгосрочная продуктовая цель; разработка идёт по проверяемым этапам.

[**Продуктовая цель и образовательные принципы**](docs/PRODUCT_VISION.md) · [**Дорожная карта**](docs/ROADMAP.md) · [**Текущее состояние / handoff**](docs/PROJECT_STATUS.md)

## Какого тренера мы строим

| Направление | Какую преграду непонимания нужно уметь снимать |
| --- | --- |
| **Тактика и расчёт** | Почему здесь работает вилка, связка, отвлечение или жертва; как найти кандидатные ходы, защититься и проверить варианты |
| **Дебюты и ловушки** | Не только помнить линию, но понимать идеи, типовые ошибки, транспозиции и планы обеих сторон |
| **Миттельшпиль** | Пешечные структуры, слабые поля, активность фигур, динамика, переходы и выбор долгосрочного плана |
| **Эндшпиль** | Выигрыш/удержание ничьей, точная техника и практические решения |
| **Разбор собственных партий** | Не только «ход плохой», но *почему* он казался разумным, какую угрозу игрок не заметил и как проверить понимание |
| **Персональные занятия** | Подбор упражнений по подтверждённым пробелам, повторение и проверка прогресса |
| **Объяснение и диалог** | Вопросы ученика, наводящие подсказки, альтернативные объяснения и демонстрация идей на доске |

**Важное разграничение:** это *целевая функциональность*, а не список уже готовых возможностей программы. Тренер, способный надёжно объяснять всё перечисленное, ещё **не создан**. Мы начинаем с проверяемого хранилища партий, корректного шахматного анализа и понятного интерфейса.

### Текущий технический этап

M0–M4 интегрированы в main ([PR #26](https://github.com/feshakomissarov-prog/chess/pull/26)). **Следующее большое задание для десктопного Codex — [M4.5 v2.0](docs/specs/M4_5_BATCH_ANALYSIS_PERSONAL_DIAGNOSTICS.md)**, этапы 0–I, [журнал исполнения](docs/handoffs/M4_5_EXECUTION_LOG.md), [эпик #28](https://github.com/feshakomissarov-prog/chess/issues/28). Codex работает в отдельной feature-ветке, ведёт checkpoints в GitHub и не сливает main самостоятельно.

Ключевые продуктовые решения: полный архив рассчитывается с приоритетом свежих партий, локальный Stockfish ограничен быстрым бюджетом, углублённый анализ выборочен, классификация расширяема, историческая и текущая статистика раздельны; общие показатели включают **среднюю точность партии с источником и N, ошибки/партию и на 100 оценённых собственных ходов, покрытие, дебюты и фазы**. Это план, не готовая новая функциональность. Ручной долг в [Issue #5](https://github.com/feshakomissarov-prog/chess/issues/5).

## Как устроена работа тренера

1. **Наблюдение.** Партии, PGN, собственные заметки, ответы на вопросы и тренировочные задания.
2. **Шахматные факты.** Легальность ходов, варианты, локальный Stockfish после завершения человеческой партии, при необходимости точные эндшпильные данные.
3. **Диагноз.** Проверяемые гипотезы: что игрок не понял, недооценил или не заметил. Одна потеря сантипешек сама по себе ещё не является объяснением.
4. **Обучение.** Доска, примеры, контрпримеры, вопросы и объяснения с учётом опыта человека.
5. **Закрепление.** Персональные упражнения, повторение сходных ситуаций, отслеживание реального улучшения.

**Fair play:** подсказки Stockfish и ИИ во время онлайн-игры против человека запрещены. Обработка личных партий и аудио должна быть явной, с приоритетом локального хранения.

## Технологии

- **Платформа:** Windows, Python 3.12+, PySide6/Qt.
- **Шахматная логика:** `python-chess`, интерактивная доска на основе [chess-widgets](https://github.com/leszekhanusz/chess-widgets).
- **Данные:** локальная SQLite, PGN, нормализованная история ходов; Lichess API/OAuth по разрешению пользователя.
- **Анализ:** внешний UCI Stockfish (движок выбирается пользователем, приложение не должно скачивать бинарники автоматически).
- **В перспективе:** текст/голос, история стрелок и рассуждений, проверяемые объяснения языковой моделью, персональная система тренировок.

Архитектура и детали приёмки — в [PRD](docs/PRD.md), [PCD](docs/PCD.md), [ROADMAP](docs/ROADMAP.md).

## Запуск на Windows

**Текущий исходный код `main` (M0–M4):** используйте существующее окружение проекта. Если локально есть несохранённые изменения, **не переключайте ветку принудительно**.

```powershell
cd G:\project\chess
git status --short
git switch main
git pull --ff-only
.\.venv\Scripts\python.exe -m chess_coach
```

Команды с `git switch` выполняйте только при чистом рабочем дереве. Обычный запуск может использовать сохранённую авторизацию Lichess.

**Для работы над M4.5:** Codex создаёт собственную ветку от актуального main по [ТЗ v2](docs/specs/M4_5_BATCH_ANALYSIS_PERSONAL_DIAGNOSTICS.md). Старые ветки интеграции PR #26 уже слиты и не должны использоваться как исходная база.


## Карта шахматных знаний и методика обучения

Чтобы Chess Coach со временем мог **объяснять что угодно, от матовых приёмов до сложных стратегических планов**, мы составили не просто перечень тем, а карту **«шахматная область × конкретный навык × уровень усвоения»**.

- **[22 области шахмат и 12 сквозных навыков](docs/research/CHESS_SKILL_TAXONOMY.md)** — чему именно нужно обучать; как отличить незнание темы от ошибки расчёта, внимания или исполнения.
- **[Как тренер работает с учеником](docs/research/CHESS_COACHING_PRACTICE.md)** — постановка вопроса, проверка понимания, объяснение с контрпримерами, самостоятельные упражнения, отложенный контроль.
- **[Что Chess Coach покрывает и чего пока нет](docs/research/CHESS_COACH_COVERAGE_GAPS.md)** — честное сопоставление с MAIN/draft M3–M4 и будущие ограниченные EDU-модули, включая направления следующего поиска на GitHub.

Это **исследовательский backlog, не команда менять текущую работу Codex**. Актуальный порядок: M3/M4 → **M4.5 (паспорт и аналитика)** → M5 (голос) → M6 (ИИ-тренер). Новые тренажёры добавятся после того, как аналитика накопит проверенные данные.

## Исследуем открытые шахматные проекты

Разбираем, **как другие авторы успешно реализуют шахматные тренировки**, хранение позиций, распознавание мотивов, объяснения планов, работу с PGN, Stockfish и интервальными повторениями. Это библиотека идей для охвата **всех направлений шахмат**, а не поиск одной «уникальной функции».

## Открытость и участие

Проект разрабатывается для личного обучения и изучения технических решений, **не предполагает обязательной оплаты**. Это не запрещает другим знакомиться с идеями; однако **публичность GitHub не означает права свободно копировать и распространять весь код**.

На момент обновления в корне Chess Coach **нет выбранного файла `LICENSE`**. Перед публичным распространением/приёмом существенных внешних компонентов нужно решить вопрос совместимой лицензии и уведомлений о зависимостях (включая `python-chess`, PySide6, Stockfish и наборы шахматных фигур). Не использовать сторонние файлы без проверки прав.

Идеи и предложения по тому, как лучше объяснять шахматы, можно обсуждать через [GitHub Issues](https://github.com/feshakomissarov-prog/chess/issues). Порядок работы Codex и требования к ревью — в [AGENTS.md](AGENTS.md). **Слияние PR — только по явному разрешению владельца.**
